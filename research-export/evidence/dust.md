## 1. Product Overview

Dust.tt is "a platform that enables teams to create customizable and secure AI agents powered by leading large language models... agents integrate with company data sources to enhance productivity and improve work processes across various domains." [Source: ud-getting-started/intro-to-dust.md, accessed 2026-11-15] The product positions itself as an **Agent Management Platform** — "a central hub where companies build and manage AI agents for their teams... one place to create custom AI agents that can access your company's information and tools. Anyone in the company can build these agents without knowing how to code, and employees can use them wherever they work—in third-party tools, on the web, or through custom-built user interfaces." [Source: wb-02b7df0319bd.txt (Why you need an Agent Management Platform, 2026-02-25), accessed 2026-11-15] Launched in 2023, used by 2,000+ companies by 2026 with 80,000 agents and 12M conversations in 2025 alone. [Source: wb-aceb8610b6bf.txt, accessed 2026-11-15] Built on Mintlify docs (footer attribution). [Source: fresh-docs-home.txt, accessed 2026-11-15]

## 2. Product Philosophy ("AI as colleague")

Stanislas Polu's "thought experiment: think about coding. Would Cursor, Claude Code, or Manus be of any use if they were based on configurable workflows?" — Dust's bet is that **AI agents are not workflows** and the visual boxes-and-arrows paradigm limits what they can accomplish. [Source: wb-5f7508f73ffb.txt (AI Agents don't need to be Boxes and Lines, 2026-01-16), accessed 2026-11-15] The mental model is **"agent as colleague"**: "The best way to build an agent is the same way you'd onboard a new hire: tell them what you need, give them the tools, and let them figure it out. Agents deserve agency. Give it to them." [Source: wb-5f7508f73ffb.txt, accessed 2026-11-15] This justifies (a) instructions as natural language (no node graph), (b) triggers in natural language (no cron syntax), and (c) skills as reusable instruction packages rather than sub-workflows. The four-stage maturity ladder is: Secure LLMs → Knowledge Assistants → Personal Agents → Autonomous Agents. [Source: wb-02b7df0319bd.txt, accessed 2026-11-15]

## 3. Core Mental Model (AI colleague)

The mental model is the **@handle**. Each agent is invoked by name (`@sales`, `@dust`, `@deep-dive`) and behaves per a written **instruction set** + curated **tools** + curated **knowledge** (data sources / folders). [Source: ud-agents/create-your-first-agent.md, accessed 2026-11-15] Skills are "reusable packages of instructions, knowledge and tools that you can share across multiple agents. Think of them as specialized toolboxes that contain the knowledge and capabilities needed for specific tasks or domains." [Source: ud-agents/skills/skills-overview.md, accessed 2026-11-15] The system ships default global agents: **@dust** (general-purpose assistant), **@deep-dive** (long-running research), **@gpt/@claude/@gemini** (model passthroughs), **@sidekick** (agent-builder assistant inside the Agent Builder), and private sub-agents **@dust-planning** and **@dust-task** used by @deep-dive. [Sources: ud-agents/deep-dive-agent.md, ud-agents/agent-builder-sidekick.md, ud-getting-started/intro-to-dust.md, accessed 2026-11-15] "Conversations are now scoped to one agent at a time. The active agent is shown in the input bar." [Source: ud-agents/steering-conversations.md, accessed 2026-11-15]

## 4. User Journey

First-run (from intro-to-dust): "type your message and mention the agent with `@`. Start asking questions to @dust. This agent is set up by default and will use all of the internal documentation integrated to Dust to generate the answer." [Source: ud-getting-started/intro-to-dust.md, accessed 2026-11-15] Build flow (create-your-first-agent): (1) Click **Create** from home page → choose template or scratch → Sidekick opens; (2) Give instructions (Sidekick drafts + you accept/reject diffs); (3) Add Tools & Knowledge (pick a Space, e.g. Notion folder `Sales Corner`); (4) Test in preview area; (5) Give name + description + tags; (6) Set access (publish to workspace or keep private); (7) Use via `@YOUR_AGENT_NAME` in web app, Slack (`@dust +YOUR_AGENT_NAME`), or Zapier. [Source: ud-agents/create-your-first-agent.md, accessed 2026-11-15] Improvement flow: open agent → Sidekick "automatically reviews user feedback (thumbs-up/thumbs-down ratings) and performance metrics for that agent" → proposes inline diffs (green adds / red removes) → accept/reject per change. [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15]

## 5. Navigation (Dust dashboard)

[Source: ud-admins/agents-management.md, accessed 2026-11-15] Admins can "Become an editor" of any agent/skill from a view-only open. [Source: ud-admins/agents-management.md, accessed 2026-11-15]

## 6. Workspace (Dust agent panels)

The Agent Builder is a multi-panel layout: left = instructions editor (with inline `/` slash menu to attach tools, skills, knowledge as chips); centre = live preview area for testing; right = Sidekick conversation panel (with accept/reject diff cards). [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15] Below the editor are tabs: **Capabilities** (Discover Knowledge, Discover Tools, Go Deep, etc.), **Tools** (per-tool toggle), **Knowledge** (data sources with label filters), **Triggers** (schedules + webhooks), **Advanced** (structured output, model selection, search settings), **Settings** (name, description, tags, editors, access). [Sources: ud-agents/skills/skills-overview.md, ud-agents/triggers.md, ud-agents/structured-output-format.md, ud-agents/knowledge/search-data-sources.md, accessed 2026-11-15] The agent details drawer (click agent avatar) shows: usage, Memory tab (inspect/delete memories), skill usage summary. [Sources: ud-agents/tools/agent-memory.md, ud-agents/skills/skills-overview.md, accessed 2026-11-15]

## 7. Conversation (Dust chat with @-mentions)

Conversations are scoped to one agent at a time (active agent shown in input bar; no @mention needed inside the conversation itself). [Source: ud-agents/steering-conversations.md, accessed 2026-11-15] Users can mention *teammates* with `@name` (human collaborators) — the mentioned user is added as participant, notified, and shows in Inbox. "For the first time, AI agents can @ mention specific team members when they need input, approval, or expertise." [Source: wb-blog-mentions-collaborate-better-together.next.txt, accessed 2026-11-15] Multi-agent invocation is still possible: "Dust allows you to call multiple agents in one discussion and have them work together to achieve a given task." [Source: ud-getting-started/intro-to-dust.md, accessed 2026-11-15] Each agent message has a **"Completed in N sec"** affordance that opens the details panel showing the skills loaded and tool calls made. [Source: ud-agents/skills/skills-overview.md, accessed 2026-11-15]

## 8. Agent Experience (Dust multi-agent per-agent observability)

Two complementary observability surfaces:

**(a) Conversation-level "steering"**: every step (thinking blocks, tool calls, searches, file operations) appears live as it happens. "Every step now appears live in the conversation... instead of hiding behind a single activity indicator." [Source: ud-agents/steering-conversations.md, accessed 2026-11-15] Users can send messages mid-run; the agent finishes its current round of parallel actions then picks up the queued message with full context. [Source: ud-agents/steering-conversations.md, accessed 2026-11-15] Stop button keeps all completed work — "everything it's already done is kept. You only stop what comes next." [Source: ud-agents/steering-conversations.md, accessed 2026-11-15]

**(b) Workspace-level "Agent Builder Observability"**: announced in Product Update 19 (Dec 2025) — "Builder Observability lets you see exactly where they're crushing it (and where they're not)... which tools your agents use, when they use them, and how behavior shifts between versions. It allows you to see real usage patterns, identify bottlenecks, and iterate based on real behavior." [Source: wb-blog-product-update-19.next.txt, accessed 2026-11-15] Per-agent observability is materialised in **Workspace Analytics** (Admin > Analytics): "Agents by credits: the top 100 agents by credits consumed, with their model, description, top users, and top skills... Skill usage: executions and unique users per skill over time... Tool usage: executions and unique users per tool over time." [Source: ud-admins/workspace-analytics.md, accessed 2026-11-15] This is genuinely differentiated — most agent platforms surface traces; Dust surfaces *aggregate agent behaviour* (which skills fired, which users, which tools, model drift over versions). [Source: ud-admins/workspace-analytics.md, accessed 2026-11-15]

## 9. Memory (Dust context)

Dust has both **short-term** (within-conversation: full message history, with Context Compaction at 33/70/80% thresholds) and **long-term** (Agent Memory tool, user-scoped). [Sources: ud-agents/context-compaction.md, ud-agents/tools/agent-memory.md, accessed 2026-11-15] Agent Memory is **opt-in as a tool**, not default — by design, because "memory isn't universally beneficial" (a code review agent without memory applies consistent standards; with memory it could become biased toward individual patterns). [Source: wb-f6c134a497d0.txt (Agent Memory blog), accessed 2026-11-15] Memory is "encrypted at rest, isolated per user, and never used for model training. The system maintains full audit trails." [Source: wb-f6c134a497d0.txt, accessed 2026-11-15] Context Compaction: circular indicator in input bar shows usage %; "Compact now" button at 33%; warning at 70%; compaction *required* at 80%; takes 10s–1min. Original messages retained but replaced by a summary for future model calls. [Source: ud-agents/context-compaction.md, accessed 2026-11-15] **Branch a conversation**: spin off new conversation from any point — generates summary, deep-copies files and tool outputs, child is fully independent. Takes 10–20 seconds. [Source: ud-agents/branch-a-conversation.md, accessed 2026-11-15]

## 10. Knowledge (Dust @-mentions as citations)

Knowledge is provided by **Data Sources** (Connections to Notion, Confluence, Google Drive, Slack, GitHub, Snowflake, BigQuery, Zendesk, Intercom, Gong, Microsoft, Atlassian, Snowflake...). [Source: fresh-llms.txt connections list, accessed 2026-11-15] The agent uses semantic search + advanced "filesystem-like" search. **Discover Knowledge** skill: "Finds relevant content across connected company data, even when the source uses different wording... Explores source hierarchies and locates folders, documents, pages, schemas, and tables by name." [Source: ud-agents/discover-knowledge.md, accessed 2026-11-15] Labels allow filtering: must-have / must-not-have labels refine what content is available. [Source: ud-agents/knowledge/search-data-sources.md, accessed 2026-11-15] **Citations**: every agent answer includes "citations to sources (your internal documents, web pages, or data queries) so you can verify the information." [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15] Knowledge is permissioned: agents only see data in Spaces the user has access to; "Discover Knowledge follows the user's permissions and the spaces available to the agent." [Source: ud-agents/discover-knowledge.md, accessed 2026-11-15]

## 11. Search (Dust filesystem search)

This is a flagship feature born from a real pattern: "In April 2025, something kept showing up in our logs. Our AI agents were inventing their own syntax for searching content — `file:front/src/some-file-name.tsx`, `path:/notion/engineering/weekly-updates` — they were trying to reference resources by inventing file paths, even though no filesystem existed." [Source: wb-blog-building-deep-dive-infrastructure-for-ai-agents-that-actually-go-deep.next.txt, accessed 2026-11-15] Dust built "synthetic filesystems that map disparate data sources (Slack channels, Notion databases, GitHub repos, Google Sheets) into navigable Unix-like structures. Five simple commands... Just like Unix, but operating across your entire company knowledge base." [Source: same, accessed 2026-11-15] The "Advanced search mode" in the Agent Builder enables "filesystem-level access to your data sources in addition to semantic search... list folders, browse directory structures, and read specific files by their exact path." [Source: ud-agents/knowledge/search-data-sources.md, accessed 2026-11-15] Tradeoff: "Generally requires more tool calls, hence more induced latency, to locate and retrieve information." [Source: ud-agents/knowledge/search-data-sources.md, accessed 2026-11-15]

## 12. Execution (Dust agent runs)

Agent execution model: user sends message → agent reasoning + tool calls + skills activation; "the agent will decide to enable a skill by analyzing the current situation. Skills that are not relevant will not be loaded, optimizing the context exposed to the agent at a given time." [Source: ud-agents/skills/skills-overview.md, accessed 2026-11-15] **Sub-agent parallelism** (deep-dive): up to 6 concurrent @dust-task sub-agents, each with its own fresh context window. [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15] **Temporal durability**: "The system is built on Temporal workflows for durability, meaning work can survive deployments and infrastructure issues without losing progress." [Source: wb-blog-building-deep-dive-infrastructure-for-ai-agents-that-actually-go-deep.next.txt, accessed 2026-11-15] Latency buckets: simple questions under a minute; deep dive planning 30s–2min; research phase 5–20min; synthesis 1–3min. [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15] **Tool output pruning** ("Big Loop" + "Amnesia" prevention): "selectively prune tool outputs by replacing their content with `<dust_system>This tool output is no longer available</dust_system>`. The tool call itself remains visible, so the model still sees what it did, just not the full results." [Source: wb-blog-building-deep-dive...next.txt, accessed 2026-11-15] **Offloaded tool use**: large tool outputs are stored as files with snippets inline + full filesystem access for retrieval (offset, limit, regex, semantic search). [Source: same, accessed 2026-11-15] **Long-running durable agents** shipped as a feature (Sep 2025 changelog). [Source: wb-docs-urls.json entry `long-running-durable-agents`, accessed 2026-11-15]

## 15. Motion (LangGraph live graph animation — n/a for Dust; Dust's motion is steering)

Dust does not have a graph-canvas animation because it explicitly rejects the boxes-and-lines paradigm. Instead, motion is **live step streaming**: "While the agent works, every step now appears live in the conversation. Thinking blocks, tool calls, searches, file operations: they show up one after another as they happen, instead of hiding behind a single activity indicator." [Source: ud-agents/steering-conversations.md, accessed 2026-11-15] The reasoning is functional ("Trust the process. When you can watch the agent work in real time, you let it run longer instead of stopping it out of uncertainty. That means better outputs."). [Source: ud-agents/steering-conversations.md, accessed 2026-11-15] Image creation is positioned as "absurdly fast" with "Nano Banana renders photorealistic images in seconds" — speed itself as a perceived-motion feature. [Source: wb-blog-product-update-19.next.txt, accessed 2026-11-15]

## 20. Performance Perception (Dust latency)

Steering is the primary latency-perception feature: by streaming steps live and allowing mid-run redirection, long runs feel productive rather than blocking. [Source: ud-agents/steering-conversations.md, accessed 2026-11-15] Deep-dive phases have explicit time expectations: "Planning phase (30 seconds - 2 minutes)... Research phase (5-20 minutes)... Synthesis phase (1-3 minutes)." [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15] Context compaction is exposed as an explicit user action with progress indicator rather than silent context pruning. [Source: ud-agents/context-compaction.md, accessed 2026-11-15] Sub-agent parallelism (up to 6 concurrent @dust-task) collapses total wall-time. [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15] Tool output pruning + offloaded tool use prevent context-window stalls mid-run. [Source: wb-blog-building-deep-dive-infrastructure...next.txt, accessed 2026-11-15] Sidekick suggestions are non-blocking — user can keep editing while Sidekick is processing. [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15]

## 21. Trust (Dust data handling)

Dust positions trust via: (a) **no model training**: "Dust does not train any model or fine-tune any foundation model based on your conversations. Self-improving Skills only uses conversations to improve the instructions and configuration of your own skills." [Source: ud-agents/self-improving-skills.md, accessed 2026-11-15] (b) **Data isolation**: "There is no cross-workspace data sharing. Conversations from your workspace are only used to improve skills within your workspace." [Source: same] (c) **Permissioned agents**: @deep-dive "respects your workspace's access controls. It only accesses data you're authorized to see, operates under your identity when using tools with Personal authentication, and respects space-level and query-level permissions. Sub-agents inherit the same permissions." [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15] (d) **Audit logs**: admin-accessible event log capturing what agents did. [Source: ud-admins/audit-logs/audit-logs.md, accessed 2026-11-15] (e) **Trust Center** linked from footer of every page (legal/dust-tt). [Source: every blog page footer] (f) **ZDR option**: Self-improving skills support a "Streaming mode (ZDR-eligible)" so strict Zero Data Retention workspaces can opt for synchronous processing instead of batch. [Source: ud-agents/self-improving-skills.md, accessed 2026-11-15] Privacy in analytics: "analytics and exports never include the content of messages. Only metadata such as timestamps, user and agent identifiers, conversation IDs, credit consumption, and the source of each message is captured." [Source: ud-admins/workspace-analytics.md, accessed 2026-11-15]

## 22. Explainability (Dust @-mentions as citations)

Two pillars: (a) **@-mentions as citations to humans** — when an agent uses a fact from a data source, it includes a citation link to the underlying document; when it needs human input, it @-mentions a teammate (visible, accountable, audit-trail-forming). [Source: wb-blog-mentions-collaborate-better-together.next.txt, accessed 2026-11-15] (b) **Live step streaming** — every step is visible as it happens, clickable for inspection. [Source: ud-agents/steering-conversations.md, accessed 2026-11-15] (c) **Per-message detail panel** ("Completed in N sec") showing which skills were loaded and which tool calls were made — so the user can verify what context shaped the answer. [Source: ud-agents/skills/skills-overview.md, accessed 2026-11-15] (d) **Per-agent observability** — Agent Builder Observability surfaces "which tools your agents use, when they use them, and how behavior shifts between versions" — so an agent's behaviour is auditable across versions. [Source: wb-blog-product-update-19.next.txt, accessed 2026-11-15] (e) **Self-improving skills** — nightly analysis surfaces evidence-based edit suggestions to skill builders (with reasoning tied to specific feedback signals). [Source: ud-agents/self-improving-skills.md, accessed 2026-11-15] Limitations: sidekick "cannot create or edit triggers" and "evaluates each agent individually: it doesn't orchestrate multi-agent workflows or suggest building new sub-agents." [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15]

## 23. Long Session Experience

Long conversations handled via: (a) **Context Compaction** with three thresholds (33% offer, 70% warn, 80% required); summary marker preserves older messages visibly but model uses summary. [Source: ud-agents/context-compaction.md, accessed 2026-11-15] (b) **Branching** for splitting work streams or handing off — 10–20s to generate summary + copy files. [Source: ud-agents/branch-a-conversation.md, accessed 2026-11-15] (c) **Offloaded tool use** — large tool outputs stored as files with snippet + retrieval API, so 200K-token web pages don't blow the context. [Source: wb-blog-building-deep-dive...next.txt, accessed 2026-11-15] (d) **Deep-dive sub-agents** — each sub-problem gets its own fresh context window, so a 30-minute investigation doesn't exhaust one model's context. [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15] (e) **Long-running durable agents** — Temporal-backed, "work can survive deployments and infrastructure issues without losing progress." [Source: wb-blog-building-deep-dive...next.txt, accessed 2026-11-15] Multi-agent runs are coordinated by the @deep-dive main agent that orchestrates up to 6 concurrent @dust-task sub-agents. [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15]

## 24. Power User Features (Dust triggers + scheduled + per-agent dashboards)

- **Triggers** (Nov 2025): schedules + webhooks + events. Schedules via natural language ("Every Tuesday at 8:30 AM Pacific Time") with LLM-generated cron confirmation visible to user. [Source: ud-agents/triggers.md, accessed 2026-11-15] Webhooks via natural-language filter ("New pull requests on dust-tt/dust that have the 'bug' label") — Dust uses an LLM to generate the filter; for custom webhooks a Lisp-style S-expression filter language is documented. [Source: ud-agents/triggers/webhooks.md, accessed 2026-11-15] Trigger sources: GitHub, Zendesk, Fathom, Linear, Jira (PRs opened, tickets created, calls completed, issues updated). [Source: wb-blog-product-update-19.next.txt, accessed 2026-11-15] "Triggers complete the automation loop... no third-party workflow tools like Zapier, n8n, or Make [needed]." [Source: wb-blog-introducing-triggers...next.txt, accessed 2026-11-15] Currently "triggers are personal, and only the editor can observe the runs." [Source: ud-agents/triggers.md, accessed 2026-11-15]
- **Agent Builder Observability**: per-tool, per-skill, per-version usage analytics; "see exactly where they're crushing it (and where they're not)." [Source: wb-blog-product-update-19.next.txt, accessed 2026-11-15]

## 27. Biggest Weaknesses (with evidence)

1. **Multi-agent confusion at scale.** Wakam deployed 136 agents (50 company + 90 personal); the platform's own writing admits "everyone's using ChatGPT in a different way and generating different content and creating different agents. We need control before we go down a rabbit hole." [Source: wb-02b7df0319bd.txt, accessed 2026-11-15] Without strong discoverability + curation, fleet-wide confusion is a real risk.
2. **No documented keyboard shortcuts or accessibility statement.** [Gap across all docs, accessed 2026-11-15]
3. **Triggers are personal-only.** "For now, triggers are personal, and only the editor can observe the runs. More to come on that topic!" — limits team-shared automation observability. [Source: ud-agents/triggers.md, accessed 2026-11-15]
4. **Sidekick limitations**: "cannot create or edit triggers", "cannot draft or build skills, though it can recommend existing ones", "evaluates each agent individually: it doesn't orchestrate multi-agent workflows or suggest building new sub-agents", "Testing still requires switching to the Preview tab". [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15] Sidekick messages also count against the workspace's message limit. [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15]
5. **Self-improving skills has ZDR caveat**. Batch mode "is not covered by ZDR guarantees from any of the supported providers" — strict enterprises must either disable batch mode (more expensive) or disable the feature entirely. [Source: ud-agents/self-improving-skills.md, accessed 2026-11-15]
6. **Webhook filter expression language is bespoke** (Lisp-style S-expressions) for custom webhooks — a new DSL users must learn for non-LLM-generated filters. [Source: ud-agents/triggers/webhooks.md, accessed 2026-11-15]
7. **No graph view** — by philosophical choice. For users who *do* want to visualise control flow, there is no equivalent of LangGraph's animated graph; only mermaid diagrams on demand from Sidekick. [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15]
8. **Deep-dive cannot access Table Query tool or Restricted Spaces** — limits its universality. [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15]
9. **Long latency for deep-dive (10–30+ minutes)** requires users to trust a long-running process; the live-steaming UX mitigates but doesn't eliminate the wait. [Source: ud-agents/deep-dive-agent.md, accessed 2026-11-15]
10. **Branding ambiguity** between "Dust", "Dust.tt", "Multiplayer AI" (the docs site name), and "Agent Management Platform" (the category positioning) — multi-name confusion in customer-facing surfaces.

## 29. What should MiMo reject?

- **Multi-name brand confusion** (Dust / Dust.tt / Multiplayer AI / Agent Management Platform) — pick one name and own it.
- **Triggers scoped personal-only.** Team-shared automation requires team-shared observability from day one. [Source: ud-agents/triggers.md, accessed 2026-11-15]
- **No documented keyboard shortcuts or accessibility.** This is a baseline expectation; both LangGraph Studio and Dust fail here.
- **Bespoke DSLs for filters.** The Lisp-style S-expression webhook filter language is a learning-tax that the natural-language trigger generator should ideally subsume. [Source: ud-agents/triggers/webhooks.md, accessed 2026-11-15]
- **Self-deprecating philosophical absolutism.** "AI agents aren't workflows" is rhetorically strong but ignores that some workflows *are* genuinely deterministic and boxes-and-lines is right for them; the "When Workflows Are Still the Right Tool" section in their own blog acknowledges this. [Source: wb-5f7508f73ffb.txt, accessed 2026-11-15] The absolutism risks under-serving hybrid use cases.
- **Sidekick message-billing.** Charging per Sidekick interaction against the workspace message limit discourages the exact iterative behaviour the feature is designed to enable. [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15]
- **No graph view by philosophy.** Some users want to *see* their agent's structure; even an auto-generated mermaid rendering (which Sidekick can produce on demand) should be a first-class surface, not an on-demand Sidekick output. [Source: ud-agents/agent-builder-sidekick.md, accessed 2026-11-15]
