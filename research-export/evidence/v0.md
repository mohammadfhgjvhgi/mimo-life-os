## 3. Core Mental Model

- **Identity confusion: design tool OR code tool?** v0 simultaneously markets itself as both. The home page lists both "Edit with design mode — Fine-tune every detail with visual controls and live preview" and "Sync with a repo — Connect to GitHub and push code directly to your repository" as equal-tier capabilities. [Source: https://v0.dev/home, accessed 2026-08-07]
- Feb 2026 update added a "Full editor: A complete VS Code-style editor is built into v0" — explicitly competing with IDEs. [Source: https://v0.dev/docs/faq, accessed 2026-08-07]
- Feb 2026 update also reorganized workspace into "Projects" (connected to actual app, deployments, env vars, git) and "Folders" (purely organizational). [Source: https://v0.dev/docs/faq, accessed 2026-08-07]
- Quickstart confirms the dual mental model in a single workflow: prompt → "Edit the Code" (Code tab) OR "Design Mode" (Option+D) → integrate → ship. [Source: https://v0.dev/docs/quickstart, accessed 2026-08-07]
- "Design Mode" lets you "select any element in the live preview, tweak its styles with a visual panel (and/or natural-language instructions), and then apply those edits back to your source code." [Source: https://v0.dev/docs/design-mode, accessed 2026-08-07]
- Agentic mental model: v0 picks capability based on phrasing ("Search for…" → web search; "Open my app and test the signup flow" → browser use; "Check the latest Vercel deployment logs" → Vercel CLI through terminal; "Connect to my Supabase database" → Marketplace integration; "Run the unit tests and fix any failures" → terminal). [Source: https://v0.dev/docs/agentic-features, accessed 2026-08-07]
- Mental model summary: **v0 = prompt → live preview + code editor + agent; identity oscillates between "design tool" (Design Mode, visual) and "code tool" (full VS Code editor, terminal, GitHub PRs)**. The Feb 2026 release ("Full editor", Projects+Folders) tipped the center of gravity toward code tool.

It can also visit external URLs to capture visual references or inspect a page's layout before recreating it." [Source: https://v0.dev/docs/agentic-features, accessed 2026-08-07]
- **Browser screenshots surfaced to user:** "v0 can now show the browser screenshots the agent captures while testing your preview." [Source: https://v0.dev/changelog, "May 15, 2026", accessed 2026-08-07]
- **Automatic error fixing:** Detects missing files/dependencies, syntax/formatting issues, runtime errors, import/export problems; "can diagnose and fix them automatically as part of the generation loop." [Source: https://v0.dev/docs/agentic-features, accessed 2026-08-07]
- **Fix with v0 button:** "When a deployment has errors or warnings, a Fix with v0 button appears in the deployment popover." Premium/Team/Business/Enterprise get "up to 10 free Fix with v0 uses per day. The button shows a 'Free' badge when free uses are available. - **Terminal commands:** "v0's Bash tool runs commands in the same sandbox where your project files live. Each command runs in a fresh shell starting from the project root." [Source: https://v0.dev/docs/terminal-commands, accessed 2026-08-07]
- **Three permission modes:** Ask (every ask/unmatched command prompts), Auto (default; built-in allow list runs without confirmation; v0 decides whether to confirm unmatched), Full (skips permission evaluation entirely; for "non-sensitive projects with no production credentials"). ## 12. Execution

- **Generation loop:** v0 generates code → runs in Vercel Sandbox dev server → renders live preview → if errors, automatic error fixing kicks in → on completion, user reviews version. [Source: https://v0.dev/docs/sandbox + agentic-features, accessed 2026-08-07]
- **Sandbox = Vercel Sandbox (Firecracker microVM):** "VM-backed chats run your project inside an isolated Vercel Sandbox that hosts your code, dev server, terminal, and agent tools." Replaces older browser-based preview. [Source: https://v0.dev/docs/sandbox, accessed 2026-08-07]
- **Isolation boundaries:** Per chat (each VM-backed chat has its own sandbox; files/env/running processes never cross); per user or team (others can't reach unless shared); from production (sandbox never same machine as deployed app). [Source: https://v0.dev/docs/sandbox, accessed 2026-08-07]
- **Sandbox lifecycle:** Created first time chat needs one; 30-minute pooled lifetime initial timeout; active running sandboxes auto-extend +10 min when ≤5 min remaining; **24-hour absolute cap**; inactive/stopped sandboxes NOT revived by keep-alive (reused or recreated on next visit); new VM-backed chat creates new sandbox; "State doesn't carry over from older chats unless you explicitly fork or import." [Source: https://v0.dev/docs/sandbox, accessed 2026-08-07]
- **Sandbox network policy:** "Sandbox Network Policy controls which outbound hosts the sandbox is allowed to reach. The default is allow-all. Team owners configure this from team settings." [Source: https://v0.dev/docs/sandbox, accessed 2026-08-07]
- **What runs inside:** Node.js with pnpm/npm/yarn/bun; framework-aware dev server (Next.js, Vite, generic Node.js); environment variables from connected Vercel project. [Source: https://v0.dev/docs/sandbox, accessed 2026-08-07]
- **Performance:** "Sandboxes start over 50% faster on new chats and use about 500 MB less storage" (May 12, 2026). "Faster VM preview startup and Vercel deploys, trimming several seconds of setup" (Jul 7, 2026). "Preview sandboxes can run for up to 24 hours." [Source: https://v0.dev/changelog, accessed 2026-08-07]
- **Preview sandboxes limit:** "Signed-out users get a higher preview sandbox limit of 240 per hour, and hitting it prompts sign up or sign in." [Source: https://v0.dev/changelog, "Jul 7, 2026", accessed 2026-08-07]
