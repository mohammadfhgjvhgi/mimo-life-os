1. ما هو MiMo؟
MiMo هو نظام تشغيل معرفي (Knowledge Operating System) للفرد الواحد.

ليس تطبيق محادثة. ليس ملاحظات. ليس أدوات مهام. بل طبقة برمجية واحدة
تتولّى: الفهم، التذكر، التخطيط، التنفيذ، والتعلم — كلها مدفوعة بنموذج
عن حياة المستخدم يُبنى ويُحدَّث باستمرار.

MiMo يجلس بين المستخدم وكل أدواته، فيتحول من "أداة يسألها المستخدم" إلى
"عقل يفهم سياق المستخدم قبل أن يسأل".

2. لماذا يوجد؟
كل أداة ذكاء اصطناعي اليوم تعاني من ثلاث مشكلات جوهرية:

فقدان الذاكرة: كل محادثة تبدأ من الصفر. الأداة لا تتذكر من أنت،
ولا ماذا كنت تعمل أمس، ولا لماذا يهمك هذا الموضوع.
فقدان السياق: الأداة ترى رسالة واحدة معزولة. لا ترى مشاريعك،
مهامك، أهدافك، علاقاتك، أو حتى الوقت من اليوم.
عدم القدرة على الفعل: الأداة تجيب لكنها لا تنفذ. لا تبحث، لا
تكتب، لا تنظم، لا تربط — إلا إذا برمجت ذلك يدوياً.
MiMo موجود ليحل الثلاثة معاً: ذاكرة دائمة + سياق ذاتي + تنفيذ ذاتي.

3. من هو المستخدم؟
المستخدم الأساسي (v1.0): فرد واحد — المالك.

محمد عادل (وفي التوسع: أي فرد محترف).
طالب/مهندس/صانع يعمل على مشاريع متعددة متوازية.
يتعامل مع الكود، الإلكترونيات، الكتابة، التخطيط، والبحث.
يميل إلى الأنظمة (systems thinker) — يريد أن يعمل مع النظام لا ضده.
يكرر نفس المعلومات لكل أداة جديدة ويشعر أن وقته يُهدر.
هدفه: أن يفتح نظاماً واحداً فيجد كل شيء مفهوماً ومستعداً.
المستخدم ليس:

فريق شركة (v1.0 فردي بالكامل).
مستهلكاً عابراً يريد جواباً سريعاً.
مطوراً يريد API فقط.

8. ما هي التجربة الأساسية؟
اللحظة المحورية (The Defining Moment)
المستخدم يفتح MiMo ويكتب:

"ابحث عن آخر مشروع كنت أعمل عليه، افتح ملفاته، لخص ما وصلت إليه،
ثم أنشئ خطة عمل لليوم."

ولا تكون هذه "ميزة". بل تكون النتیجة الطبیعیة للبنية:

Planner يفهم: هذه مهمة متعددة الخطوات.
Memory Engine يستدعي: آخر مشروع، آخر ملف، آخر تقدم.
Context Builder يبني: سياقاً من الذاكرة + الوقت + المهام.
Orchestrator يشغل: وكيل الذاكرة → وكيل القراءة → وكيل التلخيص → وكيل التخطيط.
Reasoner يراجع: هل النتيجة متماسكة؟
Prompt Engine يبني: prompt غني بالسياق للنموذج.
المستخدم يرى: إجابة واحدة متماسكة + خطة + روابط لكل ما فُتح.
ما يشعر به المستخدم
"يفهمني" — لا يحتاج أن يشرح نفسه كل مرة.
"يتذكر" — يعرف ماضيه وحاضره.
"ينفّذ" — لا يكتفي بالكلام.
"يتعلم" — كل تفاعل يجعله أدق.
"خاص بي" — ليس عاماً، بل نسخته وحده.
ما لا يجب أن يشعر به
"علي أن أشرح له من أنا" → فشل الذاكرة.
"علي أن أنسخ وألصق السياق" → فشل الـ Context Builder.
"يجيب بشكل عام" → فشل الـ Prompt Engine.
"يجيب فقط ولا يفعل" → فشل الـ Orchestrator.
9. المبادئ غير القابلة للتفاوض
السياق قبل الـ Prompt. لا يُبنى prompt قبل أن يُبنى Context Object كامل.
لا Component يستدعي AI مباشرة. كل طلب يمر عبر Core.
لا توجد ميزة Hardcoded. كل شيء Tool أو Agent قابل للاستبدال.
الذاكرة حق. كل تفاعل يُسجَّل ويُستدعى عند الحاجة.
العلاقات أهم من العناصر. Knowledge Graph قبل Memory List.
الواجهة تعرض، لا تقرر. القرار للـ Reasoner.
التنفيذ موزّع. Orchestrator يفوّض، لا ينفّذ بنفسه.
