# MiMo Life OS — Product Specification v1.0

> **Codename:** MiMo
> **Public name:** Nova Ultra
> **Document owner:** Chief Software Architect
> **Status:** Canonical — supersedes all prior descriptions

---

## 1. ما هو MiMo؟

MiMo هو **نظام تشغيل معرفي (Knowledge Operating System)** للفرد الواحد.

ليس تطبيق محادثة. ليس ملاحظات. ليس أدوات مهام. بل طبقة برمجية واحدة
تتولّى: **الفهم، التذكر، التخطيط، التنفيذ، والتعلم** — كلها مدفوعة بنموذج
عن حياة المستخدم يُبنى ويُحدَّث باستمرار.

MiMo يجلس بين المستخدم وكل أدواته، فيتحول من "أداة يسألها المستخدم" إلى
"عقل يفهم سياق المستخدم قبل أن يسأل".

---

## 2. لماذا يوجد؟

كل أداة ذكاء اصطناعي اليوم تعاني من ثلاث مشكلات جوهرية:

1. **فقدان الذاكرة:** كل محادثة تبدأ من الصفر. الأداة لا تتذكر من أنت،
   ولا ماذا كنت تعمل أمس، ولا لماذا يهمك هذا الموضوع.
2. **فقدان السياق:** الأداة ترى رسالة واحدة معزولة. لا ترى مشاريعك،
   مهامك، أهدافك، علاقاتك، أو حتى الوقت من اليوم.
3. **عدم القدرة على الفعل:** الأداة تجيب لكنها لا تنفذ. لا تبحث، لا
   تكتب، لا تنظم، لا تربط — إلا إذا برمجت ذلك يدوياً.

MiMo موجود ليحل الثلاثة معاً: **ذاكرة دائمة + سياق ذاتي + تنفيذ ذاتي.**

---

## 3. من هو المستخدم؟

**المستخدم الأساسي (v1.0):** فرد واحد — المالك.

- محمد عادل (وفي التوسع: أي فرد محترف).
- طالب/مهندس/صانع يعمل على مشاريع متعددة متوازية.
- يتعامل مع الكود، الإلكترونيات، الكتابة، التخطيط، والبحث.
- يميل إلى الأنظمة (systems thinker) — يريد أن يعمل مع النظام لا ضده.
- يكرر نفس المعلومات لكل أداة جديدة ويشعر أن وقته يُهدر.
- هدفه: أن يفتح نظاماً واحداً فيجد كل شيء مفهوماً ومستعداً.

**المستخدم ليس:**
- فريق شركة (v1.0 فردي بالكامل).
- مستهلكاً عابراً يريد جواباً سريعاً.
- مطوراً يريد API فقط.

## 4. ما المشكلة التي يحلها؟

| المشكلة | كيف يحلها MiMo |
|---|---|
| "نسيت أين توقفت في المشروع" | ذاكرة طويلة المدى + خط زمني تلقائي |
| "سألت ChatGPT نفس الشيء للألف مرة" | سياق ذاتي يُبنى قبل السؤال |
| "لدي 5 أدوات لا تتكلم مع بعضها" | طبقة واحدة + Tool Registry موحد |
| "الـ AI لا يعرف شيئاً عن حياتي" | Life Context + Knowledge Graph |
| "أردت أن أنجز لا أن أسأل" | Planner + Orchestrator ينفذان |
| "كل أداة تبدأ من الصفر" | Context Builder يبني أفضل سياق |

## 5. ما الفرق بين MiMo و ChatGPT؟

| البُعد | ChatGPT | MiMo |
|---|---|---|
| **الوحدة الأساسية** | المحادثة | المستخدم نفسه |
| **الذاكرة** | لكل محادثة (أو ميزة منفصلة) | مدمجة في النواة |
| **السياق** | ما يكتبه المستخدم الآن | كل ما يعرفه النظام عن المستخدم |
| **التنفيذ** | يجيب فقط | يخطط، يفوض، ينفذ، يراجع |
| **العلاقة** | أداة عامة | عقل شخصي |
| **المعرفة** | عامة (ويب + تدريب) | عامة + خاصة بالمستخدم |
| **الهدف** | إجابة جيدة | حياة منظمة |

**القاعدة الذهبية:** ChatGPT يسأله المستخدم. MiMo يفهم المستخدم.

## 6. ما الفرق بين MiMo و Notion؟

| البُعد | Notion | MiMo |
|---|---|---|
| **النموذج** | مستندات وقواعد بيانات | معرفة + علاقات + عقل |
| **الإدخال** | يدوي | تلقائي + يدوي |
| **الاسترجاع** | بحث نصي | فهم دلالي + سياق |
| **الفعل** | تخزين | تخزين + تنفيذ + توصية |
| **الذكاء** | لا يوجد (عدا AI add-on) | مدمج في النواة |
| **العلاقة بين البيانات** | روابط يدوية | Knowledge Graph تلقائي |

Notion مكان تحفظ فيه أشياء. MiMo عقل يفهم الأشياء التي تحفظها.

## 7. ما الفرق بين MiMo و Obsidian؟

| البُعد | Obsidian | MiMo |
|---|---|---|
| **الفلسفة** | ملاحظات مترابطة يدوياً | معرفة يربطها النظام |
| **الروابط** | `[[wikilinks]]` | علاقات دلالية تلقائية |
| **الذكاء** | إضافات (plugins) | النواة |
| **الفعل** | قراءة وكتابة ملاحظات | فهم + قرار + تنفيذ |
| **السياق** | ما تفتحه أنت | ما يحتاجه النظام |
| **الذاكرة النشطة** | لا | نعم — تُبنى وتُستدعى تلقائياً |

Obsidian أرشيف. MiMo ذاكرة عاملة.

## 8. ما هي التجربة الأساسية؟

### اللحظة المحورية (The Defining Moment)

المستخدم يفتح MiMo ويكتب:

> "ابحث عن آخر مشروع كنت أعمل عليه، افتح ملفاته، لخص ما وصلت إليه،
> ثم أنشئ خطة عمل لليوم."

ولا تكون هذه "ميزة". بل تكون **النتیجة الطبیعیة** للبنية:

1. **Planner** يفهم: هذه مهمة متعددة الخطوات.
2. **Memory Engine** يستدعي: آخر مشروع، آخر ملف، آخر تقدم.
3. **Context Builder** يبني: سياقاً من الذاكرة + الوقت + المهام.
4. **Orchestrator** يشغل: وكيل الذاكرة → وكيل القراءة → وكيل التلخيص → وكيل التخطيط.
5. **Reasoner** يراجع: هل النتيجة متماسكة؟
6. **Prompt Engine** يبني: prompt غني بالسياق للنموذج.
7. المستخدم يرى: إجابة واحدة متماسكة + خطة + روابط لكل ما فُتح.

### ما يشعر به المستخدم

- **"يفهمني"** — لا يحتاج أن يشرح نفسه كل مرة.
- **"يتذكر"** — يعرف ماضيه وحاضره.
- **"ينفّذ"** — لا يكتفي بالكلام.
- **"يتعلم"** — كل تفاعل يجعله أدق.
- **"خاص بي"** — ليس عاماً، بل نسخته وحده.

### ما لا يجب أن يشعر به

- "علي أن أشرح له من أنا" → فشل الذاكرة.
- "علي أن أنسخ وألصق السياق" → فشل الـ Context Builder.
- "يجيب بشكل عام" → فشل الـ Prompt Engine.
- "يجيب فقط ولا يفعل" → فشل الـ Orchestrator.

## 9. المبادئ غير القابلة للتفاوض

1. **السياق قبل الـ Prompt.** لا يُبنى prompt قبل أن يُبنى Context Object كامل.
2. **لا Component يستدعي AI مباشرة.** كل طلب يمر عبر Core.
3. **لا توجد ميزة Hardcoded.** كل شيء Tool أو Agent قابل للاستبدال.
4. **الذاكرة حق.** كل تفاعل يُسجَّل ويُستدعى عند الحاجة.
5. **العلاقات أهم من العناصر.** Knowledge Graph قبل Memory List.
6. **الواجهة تعرض، لا تقرر.** القرار للـ Reasoner.
7. **التنفيذ موزّع.** Orchestrator يفوّض، لا ينفّذ بنفسه.

## 10. حدود v1.0 (ما هو داخل وما هو خارج)

### داخل v1.0
- Core Intelligence Layer (planner, reasoner, orchestrator, context, memory).
- Agent Interface + 3-4 وكلاء أساسيين.
- Tool Registry + 3-4 أدوات أساسية.
- Model Interface (مزود واحد: z-ai-web-dev-sdk).
- Event Bus.
- Prompt Engine.
- الذاكرة في الـ RAM (لا قاعدة بيانات بعد).

### خارج v1.0 (مؤجل)
- Prisma / قاعدة بيانات دائمة.
- Authentication / متعدد المستخدمين.
- Voice / Desktop / Mobile apps.
- Plugin SDK عام.
- Marketplace.
- Local LLM / مزودات متعددة.

### المبدأ
v1.0 يثبت أن البنية **قادرة** على التجربة الأساسية. لا أكثر.
كل ما بعدها إضافات طبيعية فوق أساس صلب.

## 11. معايير النجاح

تنجح v1.0 إذا وفقط إذا:

- ✅ الـ Core منفصل تماماً عن الـ UI (يمكن استبدال الـ UI دون لمس Core).
- ✅ كتابة التجربة الأساسية لا تتطلب كوداً مخصصاً لها.
- ✅ إضافة Agent جديد = تطبيق interface واحد + تسجيل.
- ✅ إضافة Tool جديد = تطبيق interface واحد + تسجيل.
- ✅ استبدال مزود AI = adapter واحد فقط.
- ✅ كل حدث يمر عبر Event Bus ويمكن تتبعه.
- ✅ الـ UI لا يعرف أي شيء عن الـ Model أو الـ Provider.
