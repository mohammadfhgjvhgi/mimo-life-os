## 1. Pattern Definition

**Sidebar UX** is the interaction pattern governing the persistent (or toggleable) navigation surface — typically a left vertical column — that provides top-level access to: new-instance creation (New chat / New project / + button), search, history (conversations / chats / sessions / notebooks / notes / issues), workspace/context switching (Projects, Spaces, Channels, Graphs, Folders, Teams), pinned items (Favorites / Starred / Shortcuts), and settings / profile. The sidebar co-exists with a primary content pane and may collapse (Cmd+B / Cmd+\ / hamburger), hide entirely (Zen Mode, mobile), or be replaced by a command palette (Raycast, Helix `Space ?`). This pattern includes both the *left sidebar proper* and the IDE-derived **Activity Bar** (vertical icon strip switching between view modes: Explorer / Search / Source Control / Run / Extensions / Chat). It excludes the right-side contextual rails (Claude Artifacts panel, NotebookLM Guide, Perplexity Sources) which belong to Workspace UX (Pattern 2). [Source: evidence/chatgpt.md §5, citing https://web.archive.org/web/2025/https://help.openai.com/en/articles/10169521-projects-in-chatgpt; evidence/notion.md §5, citing notion-help-sidebar.html; evidence/linear.md §5, citing linear help docs; evidence/vscode.md §5, citing https://code.visualstudio.com/api/ux-guidelines/activity-bar; evidence/raycast.md §5, citing raycast-ai.html]

## 2. Why It Matters

Sidebar UX is the primary mechanism by which a user *recognizes* where state lives rather than *recalling* it from memory. Nielsen's Heuristic #6 "Recognition Rather than Recall" [Source: academic/recognition-vs-recall.md §1–3, citing Nielsen 1994 nngroup.com/articles/ten-usability-heuristics/] is directly implemented by: persistent chat history (ChatGPT, Claude, Gemini), Favorites/Starred sections (Linear, Arc, Craft, v0), breadcrumb navigation (Linear, Notion, VS Code, Craft), and visible workspace switchers (ChatGPT projects, Claude Projects, Arc Spaces). All convert recall ("what was that chat called?") into recognition ("I see it in my list").

Jakob's Law ("Users spend most of their time on other sites") [Source: academic/jakob-nielsen.md cross-ref Jakob's Law] applies: the left-sidebar-with-conversation-list pattern was established by ChatGPT (Nov 2022) and is now an industry convention — every consumer chat product (Claude, Gemini, GLM, Grok, Le Chat, Meta AI, Perplexity) follows it. Deviation imposes learning cost.

Amershi et al. (2019) G4 "Show contextually relevant information" requires the sidebar to surface workspace context (which project, which space, which folder); Amershi G17 "Provide global controls" requires the sidebar to be the home for global settings/profile [Source: academic/human-ai-interaction.md §4].

Hick's Law (Hick 1952, *Quarterly Journal of Experimental Psychology* 4(1):11–26) — reaction time increases logarithmically with the number of choices — predicts that sidebar breadth (number of top-level items) directly affects navigation decision time [Source: academic/hicks-law.md cross-ref]. Linear's sidebar is "dense but disciplined — fewer top-level items than Notion, more than VS Code's Activity Bar" — explicit Hick's-Law trade-off documented across evidence files.

Shneiderman Golden Rule #7 "Support internal locus of control" requires the sidebar to be collapsible/reorderable/customizable; VS Code Custom Layout (1.84) and Craft's "Customize sidebar" are direct implementations.

## 7. Cognitive Load Implications

CLT predicts the following sidebar-UX effects [Source: academic/cognitive-load-theory.md §5–7, citing Sweller 1988 and Cowan 2001]:

- **Sidebar breadth → extraneous load** — Notion's "five top-level tabs plus per-tab sections" imposes higher decision EL than Linear's "fewer top-level items" or VS Code's 5-icon Activity Bar. Hick's Law (Hick 1952) quantifies: reaction time grows log(N) where N = number of top-level items [Source: academic/hicks-law.md cross-ref]. Linear explicitly optimizes for Hick's-Law; Notion trades off breadth for "everything workspace" positioning.

- **Search palette reduces EL** — Raycast, Linear Cmd+K, v0 Cmd+K, Lovable Cmd+K, Craft Cmd+O, Anytype Cmd+K, Reflect Cmd+K, Roam Cmd+U, Warp CTRL-SHIFT-R, Zed Cmd+Shift+P. Typing a partial query collapses N items to ~4 matching items (Cowan's chunk limit), reducing decision EL. Recognition-over-recall: the user *recognizes* the right item in the filtered list rather than recalling it from memory [Source: academic/recognition-vs-recall.md §6 — "Autocomplete / autosuggest in search, addresses, code completion"].

- **Breadcrumbs reduce split-attention** — Linear (Workspace → Team → Project → Issue), Notion (page hierarchy), VS Code (file location + cursor's symbol location), Craft (Navigate Back/Forward/Into). Physically integrating location info next to the content reduces split-attention between content and a separate nav panel — CLT split-attention effect (Sweller, Chandler & Tierney 1990) [Source: academic/cognitive-load-theory.md §5].

- **Sidebar hover cards reduce EL of "what was that?"** — v0's hover card "previews how a turn ended, such as its closing summary or the question it is waiting on, and the in-progress status reads 'v0 is working'" — eliminates the need to click into each chat to recognize its state. Recognition-over-recall; reduces CLT redundancy effect (no need to scan + click + return).

- **Persistent vs ephemeral sidebar** — MS Copilot Teams ("Copilot conversations close when the side panel closes") forces re-orientation EL on every panel reopen. ChatGPT/Claude/Gemini persistent sidebars avoid this.

- **Modal navigation (Helix) imposes intrinsic load** — Helix's Normal/Goto/Space modes require the user to hold modal state in working memory (~4 chunks per Cowan 2001). For experts this becomes schema in long-term memory (germane load); for novices it is intrinsic load that could be eliminated by a command palette.

## 8. Progressive Disclosure Relationship

Progressive disclosure (Nielsen 2006) interacts with sidebar UX in five documented patterns [Source: academic/progressive-disclosure.md §4–7, citing Nielsen 2006 nngroup.com/articles/progressive-disclosure/ and Springer & Whittaker 2018 arXiv:1811.02164]:

1. **Sidebar collapse / hide** — Linear `⌘\`; Notion `cmd/ctrl + \` or `>>`/`<<` buttons; VS Code Zen Mode (⌘K Z) hides all chrome except editor; Arc Cmd+S sidebar toggle; Lovable Cmd+B; Things3 `⌘ /`; Heptabase left/right sidebar browser analogy. Each progressively discloses the sidebar — "initially simplified surface with drill-down on demand" per Nielsen 2006.

2. **Section collapse** — ChatGPT conversation history grouped (Today/Yesterday/Previous 7 days/Previous 30 days, then by month); Notion top-level tabs + per-tab sections; Linear Active/Backlog/Projects sub-tabs; Arc Pinned/Today/Unpinned tab stacks. Each section is a disclosure layer.

3. **Hover-reveal item actions** — ChatGPT hover "..." menu (Rename/Share/Archive/Delete/Move to project); v0 hover card with closing-summary preview; Linear hover Peek/Quick view; Heptabase AI Action buttons on hover. Each is "initially simplified feedback" with drill-down on demand — empirically validated by Springer & Whittaker 2018 [Source: academic/progressive-disclosure.md §5].

4. **Command palette as progressive-disclosure widget** — Raycast, Linear Cmd+K, v0 Cmd+K, Lovable Cmd+K, Craft Cmd+O, Anytype Cmd+K, Reflect Cmd+K, Roam Cmd+U, Warp CTRL-SHIFT-R, Zed Cmd+Shift+P, LangGraph ⌘K, Helix `Space ?`. Each hides the full command catalog behind a keyboard shortcut — the canonical "triangle-twist" disclosure widget (GTK Disclosure, macOS "Show Details") generalized to keyboard.

5. **Quick Find / fuzzy navigation as progressive disclosure** — Things3 Quick Find ("Type 'tod…' to jump to the Today list. Type 'finan…' to jump to the Finances area. Special lists accessible only through Quick Find: Tomorrow, Deadlines, Repeating, All Projects, Logged Projects"); Craft Quick Open (Cmd+O / Ctrl+P, accepts view names). Each progressively discloses special lists only when the user types a partial query — direct Nielsen 2006 criterion #3 "discoverability."

**Opacity-theatre risk** — arXiv:2605.10930 (2026) requires that progressive disclosure not become opacity theatre [Source: academic/progressive-disclosure.md §7–8, citing arXiv:2605.10930]. Things3's "Special lists accessible only through Quick Find" (Tomorrow, Deadlines, Repeating, All Projects, Logged Projects) borders on this — the user must know to type the partial query.

## 10. Performance Implications

Sidebar topology affects perceived performance in three documented ways:
- **Instant navigation** — v0 "Navigating between chats, settings, design systems, and your library is now instant" (Jun 26 2026 changelog). Pre-fetching or in-memory caching of sidebar destinations eliminates navigation latency perception [Source: evidence/v0.md §5, citing https://v0.dev/changelog Jun 26 2026].
- **Hover-card preview** — v0 sidebar hover card previews chat state without click — eliminates click-then-back navigation cost [Source: evidence/v0.md §5, citing https://v0.dev/changelog Jul 31 2026].
- **Search palette parallel search** — Raycast "typing searches across all installed commands, extensions, applications, file paths, calculations, and clipboard history simultaneously" — parallel search eliminates sequential browsing cost [Source: evidence/raycast.md §5, citing raycast-ai.html and raycast-home.html].
- **Workspace switcher pre-loaded context** — ChatGPT "Projects available to all free and paid subscription types globally" with each project carrying its own instructions and files — switching projects is a context swap, not a fresh-load [Source: evidence/chatgpt.md §5, citing https://web.archive.org/web/2025/https://help.openai.com/en/articles/10169521-projects-in-chatgpt].
- **Drag-to-reorder** — Manus drag-and-drop reordering of pinned projects; Obsidian mobile drag-drop tab reordering — direct-manipulation UX eliminates menu navigation cost [Source: evidence/manus.md §5, citing https://manus.im/docs/features/projects; evidence/obsidian.md §5, citing https://obsidian.md/changelog/2026-07-30-mobile-v1.13.4/].

## 11. Long-Session Impact

Multi-hour sidebar use faces three documented failure modes:
1. **History-list bloat** — ChatGPT groups by Today/Yesterday/Previous 7/30 days then by month; Claude exposes chat history search as separate section; Notion uses Favorites + Recents + Teamspaces + Shared + Private. Without grouping + search, long sessions accumulate unmanageable history lists.
2. **Workspace-switcher re-orientation cost** — Linear Workspace switcher + breadcrumb + Command Menu (⌘K) gives four orthogonal nav surfaces; Arc Spaces (own tabs/theme/cookies) with Command Bar (Cmd-T); Craft Spaces + Quick Open (Cmd+O accepts view names). Each switcher imposes re-orientation EL on switch.
3. **Modal state loss** — Helix's modal navigation (Normal/Goto/Space) requires the user to maintain modal state in working memory — for experts this is schema in LTM; for novices it is intrinsic load. VS Code Zen Mode (⌘K Z) hides all chrome — recovery requires Cmd+Shift+P palette.

Long sessions also reveal **sidebar customization maturity** — Craft "Customize sidebar allows you to hide multiple row items and sections at once" (per Notion evidence); Notion same; Anytype Sidebar Widgets (pinned Queries or Views); Linear Favorites; Arc Pinned tabs (icon-only by default). Without customization primitives, long sessions force the user to navigate the same breadth repeatedly.

## 12. Open Questions

- **Sidebar vs. command palette as primary surface** — Raycast demonstrates palette-only (no sidebar); Helix demonstrates modal-only (palette as secondary). No user-study evidence on which is cognitively superior for which task class.
- **Optimal sidebar breadth** — Linear "dense but disciplined"; Notion "five top-level tabs plus per-tab sections"; VS Code 5-icon Activity Bar; Arc Spaces + 5 sidebar item types. Hick's Law predicts log(N) penalty but does not specify the optimal N.
- **Right-side sidebar as nav surface** — Perplexity Sources, NotebookLM Guide, Claude Artifacts, Heptabase right-rail Plugins, Roam right-sidebar secondary context — these are workspace panels (Pattern 2), not nav. No evidence on whether nav belongs on right vs. left.
- **Cross-product nav consistency** — Mintlify-standard left nav + `⌘K` search is used by GLM, Perplexity, v0, Continue, Replit, LangGraph Studio, OpenHands, Le Chat, GitHub Spark, JetBrains AI — but is documentation-side, not product-side. No evidence on whether product-side nav should match docs-side nav.
- **Mobile sidebar vs. bottom nav** — ChatGPT hamburger top-left; Lovable swipeable views; Apple Siri OS-surface; Manus `+` for Plan Mode on mobile. No evidence on optimal mobile sidebar pattern.
- **AI-sidebar integration** — Linear treats AI as first-class teammate inside issue tracker (sidebar is host-app nav, not separate AI sidebar); MS Copilot's per-app Copilot pane is host-app-embedded; Apple Siri is OS-embedded; Meta AI is multi-surface (Facebook DMs, Instagram, WhatsApp, Messenger, Threads). No evidence on whether AI should be a sidebar tab, a separate panel, or OS-embedded.
- **Sidebar a11y** — No evidence file documents ARIA roles, focus-trap, screen-reader announcements, color-contrast, Dynamic Type, reduced-motion settings for any sidebar.
