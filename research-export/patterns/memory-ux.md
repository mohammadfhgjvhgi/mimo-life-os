# Pattern: Memory UX

> PAT-3. Evidence synthesis across 10 products (4 conversational AI + 4 coding agents + 2 note systems + meeting notetakers). NO MiMo design. Pattern extraction only.

## 1. Pattern Definition

**Memory UX** refers to the design of systems by which an AI assistant (or note-taking tool) persists user-specific context across conversations, sessions, or files, so that future interactions build on prior context rather than starting fresh. Across the evidence set, the pattern exhibits five signature properties:

1. **Two-layer separation** — explicit saved memories (user-curated facts) vs. implicit chat-history references (model-gleaned facts). ChatGPT codifies this as two distinct settings: "Reference saved memories" + "Reference chat history," with a dependency rule (saved memories gates chat history). [Source: evidence/chatgpt.md §9, citing https://help.openai.com/en/articles/8590148-memory-faq]
2. **File-based vs. server-side memory** — coding agents use markdown files (CLAUDE.md, AGENTS.md, .cursorrules) loaded into context; conversational AI uses server-side memory stores (Claude Settings > Memory, ChatGPT saved memories "notepad"). [Source: evidence/claude-code.md §9; evidence/codex.md §9; evidence/cursor.md §9; evidence/windsurf.md §9; evidence/claude.md §9; evidence/chatgpt.md §9]
3. **Auto-management vs. manual curation** — ChatGPT auto-management (Jun 4 2026 GA, Plus/Pro US): "Memories are now updated automatically, with ChatGPT keeping track of the details it determines are most important." Claude Code auto memory: "notes Claude writes itself based on your corrections and preferences." vs. Cursor (manual rules only) and Codex (manual AGENTS.md only). [Source: evidence/chatgpt.md §9; evidence/claude-code.md §9; evidence/cursor.md §9; evidence/codex.md §9]
4. **Scope hierarchy** — broadest → most specific. Claude Code: Managed policy (org-wide) → User (`~/.claude/CLAUDE.md`) → Project (`./CLAUDE.md` or `.claude/`) → Local (`./CLAUDE.local.md`). Cursor: User Rules → Project Rules → Team Rules (with glob-pattern file-scoped rules). Codex: root-walks from repo root to current dir, "Codex concatenates files from the root down. Files closer to your current directory override earlier guidance." [Source: evidence/claude-code.md §9; evidence/cursor.md §9; evidence/codex.md §9]
5. **Pause vs. Reset granularity** — Claude: "Pause memory" (keeps existing, stops new) vs. "Reset memory" (permanently deletes all). ChatGPT: turn off "Reference saved memories" → also turns off "Reference chat history" (dependency). Claude Code: `--safe-mode` disables CLAUDE.md auto-discovery, skills, plugins, hooks, MCP. [Source: evidence/claude.md §9; evidence/chatgpt.md §9; evidence/claude-code.md §9]

## 2. Why It Matters (with academic evidence)

Memory UX matters because working memory is severely limited (~4±1 chunks per Cowan 2001, ~15–30 seconds without rehearsal), and any context the AI cannot persist becomes extraneous load the user must re-supply [Source: academic/cognitive-load-theory.md §1, citing https://en.wikipedia.org/wiki/Cognitive_load]. Auto-memory (Claude Code, ChatGPT auto-management) offloads this to the system, freeing the user's working memory for the task at hand.

The pattern also operationalizes **Nielsen Heuristic #6 (Recognition rather than recall)**: memory entries surfaced in a "Manage memories" UI let the user recognize what the AI knows rather than recall what they told it. ChatGPT explicitly: "Saved memories can show up in past conversations. For example, if ChatGPT remembers that you live in San Francisco, it might say 'Since you live in San Francisco…'" [Source: academic/recognition-vs-recall.md §61-83; evidence/chatgpt.md §9]

The pattern aligns with **Norman's conceptual-model principle**: persistent memory narrows the Gulf of Evaluation — the user can verify what the AI knows before relying on its output. The "Reflect" monthly recap in Claude and the per-project memory summary in Claude Projects both surface the AI's mental model of the user, making it inspectable. [Source: academic/don-norman.md §7; evidence/claude.md §9]

Finally, **trust in AI** research (arXiv:2607.24601, 2026, "Evaluating the Impact of Explainable AI on Trust in AI-Assisted Code Review") frames memory opacity as a Gulf-of-Evaluation problem — developers need to see what the AI knows to calibrate trust. Claude Code's `/memory` command ("View and edit with /memory" — audit and edit auto memory) and Claude's import/export of memory from/to other AI providers directly address this. [Source: academic/don-norman.md §69, citing https://arxiv.org/abs/2607.24601; evidence/claude-code.md §9; evidence/claude.md §9]

## 3. Evidence Across Products

### Conversational AI

- **chatgpt.md §9** — Two-layer (since April 10, 2025): (1) Reference saved memories (explicit facts; stored separately from chat history in "notepad"); (2) Reference chat history (implicit facts gleaned from past chats). Dependency rule: saved memories is upstream gate. Auto-management (Jun 4 2026 GA, Plus/Pro US): "Memories are now updated automatically, with ChatGPT keeping track of the details it determines are most important." Auto-management moves less-important memories to "background" (grayed out, still visible but model may not reference). Capacity: 2x memory capacity for Plus/Pro. Search + sort (newest/oldest) + view history (restore prior versions by date). Opacity concerns: saved memories can be auto-created without explicit request, auto-updated/merged/removed by ChatGPT itself. Reference chat history is opaque by design — no "view what chat history details ChatGPT has retained" UI; users can only ask "What do you remember about me?" [Source: evidence/chatgpt.md §9, citing https://help.openai.com/en/articles/8590148-memory-faq + https://openai.com/products/release-notes]
- **claude.md §9** — Persistent memory NOW EXISTS (correcting prompt's hypothesis). Memory introduced Sep 11, 2025 (Team + incognito for Free/Pro/Max/Team) → Enterprise Sep 18 → Max Oct 23 → Pro Oct 23 (gradual) → Free Mar 2, 2026. Jul 10, 2026 major update: "Memory on Claude now works as a set of individual, categorized entries that Claude reads and updates during your conversations, replacing the previous daily memory summary." New: Settings > Memory (legacy: Settings > Capabilities > Memory). Reads/writes memory entries in real time (not 24-hour-scheduled). Categories: role, projects, professional context; communication preferences and working style; technical preferences and coding style; project details and ongoing work. Each project has its own separate memory space and project summary. Two disable modes: Pause memory (keeps existing, stops new) + Reset memory (permanently deletes all including project memories). Import/export from/to other AI providers (experimental). Memory data in standard exports. Monthly recap (Jul 9, 2026): Settings > Reflect shows topics, peak hours, observations. Settings > Time and focus for break reminders + quiet hours. Legacy: Memory synthesis updated every 24 hours (still active for Team/Enterprise during rollout). [Source: evidence/claude.md §9, citing https://support.claude.com/en/articles/release-notes + /articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context + /articles/12123587-import-and-export-your-memory-from-claude]

Hooks supported via `~/.codex/config.toml` `allow_managed_hooks_only` flag. [Source: evidence/codex.md §9, citing https://developers.openai.com/codex/guides/agents-md (Wayback) + GitHub repo docs/config.md]
- **windsurf.md §9** — AGENTS.md is the memory file format. "Create AGENTS.md files to provide directory-scoped instructions to Cascade." Directory-scoped (different from Cursor's User/Project/Team rules and Claude Code's CLAUDE.md). Windsurf memories docs page was unreachable (JS-rendered SPA without server-rendered content; no Wayback snapshot found). No mention of "auto memory" in accessible content. ## 4. Observed Variations

- **Two-layer vs. single-layer**: ChatGPT explicitly two-layer (saved memories + chat history); Claude single-layer (categorized entries; no chat-history-reference distinction after the Jul 10 2026 update replacing daily memory summary); Codex/Cursor/Windsurf single-layer (file-based rules only, no chat-history reference). [Source: evidence/chatgpt.md §9; evidence/claude.md §9; evidence/codex.md §9; evidence/cursor.md §9; evidence/windsurf.md §9]
- **File-based vs. server-side**: Claude Code, Codex, Cursor, Windsurf use markdown files (CLAUDE.md, AGENTS.md, Project Rules) loaded into context; ChatGPT and Claude use server-side memory stores. Note systems (Obsidian, Reflect) are file-based (local-first markdown). Meeting notetakers (Amie, Granola) are server-side (transcripts + Brief entity graph). [Source: all §9 above]
- **Auto-managed vs. manual**: ChatGPT auto-management (Jun 4 2026 GA) keeps "most relevant details prioritized" and moves "less important ones to the background" — user can override by manually prioritizing. Claude Code auto memory ("notes Claude writes itself"). Claude auto-categorizes memory entries into 4 categories (role/projects/professional; communication preferences; technical/coding; project details). Codex: explicit "No auto memory (vs. Claude Code's auto memory). Manual AGENTS.md only." Cursor: "Per-session memory only. No mention of Claude-Code-style 'auto memory' — Cursor relies on user-authored rules." Windsurf: "No mention of 'auto memory' in accessible content. Manual memory file (AGENTS.md) only." [Source: evidence/chatgpt.md §9; evidence/claude-code.md §9; evidence/claude.md §9; evidence/codex.md §9; evidence/cursor.md §9; evidence/windsurf.md §9]
- **Scope hierarchy direction**: Claude Code = broadest → most specific (Managed → User → Project → Local). Codex = root-walks down (root → cwd, later files override earlier). Cursor = three orthogonal scopes (User/Project/Team). Windsurf = directory-scoped only. ChatGPT = single global saved-memories notepad + per-project (Projects feature). Claude = per-project memory spaces + per-account profile. [Source: all §9 above]
- **Capacity governance**: ChatGPT auto-management avoids "memory full" state; Jun 4 2026 release: "twice as much memory capacity" for Plus/Pro. Claude Code size guidance: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence" + auto memory "first 200 lines or 25KB" loaded per session. Codex: 32 KiB default `project_doc_max_bytes` cap. ChatGPT pre-auto-management: hard cap users had to manually delete memories. [Source: evidence/chatgpt.md §9; evidence/claude-code.md §9; evidence/codex.md §9]
- **Granular disable vs. nuclear reset**: Claude has Pause (keeps existing, stops new) + Reset (permanently deletes all). ChatGPT has dependency rule: turning off saved memories also turns off chat history (asymmetric: turning off chat history alone is allowed). Claude Code has `--safe-mode` (disables CLAUDE.md auto-discovery + skills + plugins + hooks + MCP + custom commands/agents + output styles + workflows + themes + keybindings — very nuclear). Codex has no comparable disable flag. [Source: evidence/claude.md §9; evidence/chatgpt.md §9; evidence/claude-code.md §9]
- **Cross-provider portability**: Claude memory "can be imported from / exported to other AI providers (experimental)" — unique in the set. No other product documents cross-provider memory portability. [Source: evidence/claude.md §9, citing https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude]
- **Per-project memory isolation**: Claude Projects each have separate memory space + dedicated project summary, isolated from other projects and non-project chats. ChatGPT Projects similarly scope. Coding agents scope via directory tree. [Source: evidence/claude.md §9; evidence/chatgpt.md §24 — Projects feature]
- **Memory-recall latency strategy**: Granola's Brief pre-computes context before meetings (forward-looking). Claude reads/writes memory entries in real time. ChatGPT auto-management runs as a background process (model may not reference grayed-out memories). Codex/Cursor/Windsurf rules load at session start (no real-time updates). [Source: evidence/granola.md §9; evidence/claude.md §9; evidence/chatgpt.md §9; evidence/codex.md §9]

## 5. Premium Exemplars (BEST + WHY — evidence-based)

**BEST (file-based memory with auto-management): Claude Code** — because the 4-tier scope hierarchy (Managed → User → Project → Local) gives the most granular control; auto memory ("notes Claude writes itself based on corrections and preferences") offloads curation without removing user authorship; `/memory` command lets the user audit and edit auto memory at any time (Nielsen Heuristic #1 — visibility of system status); `/init` with `CLAUDE_CODE_NEW_INIT=1` interactive multi-phase flow is the most thorough onboarding (subagent exploration + follow-up questions + reviewable proposal before writing); `--safe-mode` gives the user a clean-slate escape hatch; AGENTS.md cross-tool standard support enables portability; subagents can have their own auto memory (parallel context isolation). Size guidance ("target under 200 lines per CLAUDE.md") is the only explicit cognitive-load-aware constraint in the set. [Source: evidence/claude-code.md §9, citing https://docs.anthropic.com/en/docs/claude-code/memory]

**BEST (conversational AI server-side memory): Claude (post-Jul 10 2026)** — because the categorized-entry model (role/projects/professional; communication preferences/working style; technical preferences/coding style; project details/ongoing work) is more structured than ChatGPT's free-form notepad; real-time read/write (not 24-hour-scheduled) means memory is current; per-project memory spaces prevent cross-project pollution; Pause vs. Reset granularity gives the user explicit control over disable semantics; import/export from/to other AI providers enables portability; Reflect monthly recap surfaces the AI's mental model of the user (Norman's Gulf-of-Evaluation narrowing); Time and focus break reminders acknowledge the human cost of long sessions. [Source: evidence/claude.md §9, citing https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context]

**BEST (cross-meeting entity memory): Granola** — because the Brief is a forward-looking memory surface (pre-computes context for the next meeting from prior meetings + email/calendar) that demonstrates memory's temporal direction is bidirectional — backward (query past meetings) AND forward (prep future meetings). The 30-day free-tier limit explicitly prices memory retrieval as a paid feature, surfacing memory's commercial value. The cross-meeting entity graph (people, deals, projects maintained server-side) is unique in the set. [Source: evidence/granola.md §9, citing https://granola.ai/]

## 6. Anti-Patterns (FAIL + WHY — evidence-based)

- **ChatGPT chat-history opacity** — "Reference chat history is opaque by design — there's no 'view what chat history details ChatGPT has retained' UI; users can only ask the model 'What do you remember about me?'" This violates Nielsen Heuristic #1 (visibility of system status) and creates a Gulf of Evaluation: the user cannot verify what the AI knows, only infer from its behavior. [Source: evidence/chatgpt.md §9, citing https://help.openai.com/en/articles/8590148-memory-faq]
- **ChatGPT auto-creation without explicit request** — "ChatGPT may save those details as a memory without you needing to ask." Combined with auto-update/merge/delete: "ChatGPT can manage saved memories on its own, updating, combining, or removing them when asked." This violates Nielsen Heuristic #3 (user control and freedom) — the user's mental model of "what's remembered" can diverge from the system's state without the user's awareness. The "background" gray-out mitigates visibility but not authorship. [Source: evidence/chatgpt.md §9]
- **Cursor's per-session-only memory** — "Per-session memory only. No mention of Claude-Code-style 'auto memory' — Cursor relies on user-authored rules." Long sessions across multiple projects require the user to re-establish context manually, increasing extraneous load. Forum users compensate by external scaffolding: "1. Create a PRD Document; 2. Establish Cursor Rules; 3. Create a Features Document; 4. Generate RFCs; 5. Implementation." [Source: evidence/cursor.md §9 + §23, citing https://cursor.com/docs/rules + https://forum.cursor.com/t/guide-how-to-handle-big-projects-with-cursor/70997]
- **Codex's 32 KiB hard cap** — "Codex skips empty files and stops adding files once the combined size reaches the limit defined by `project_doc_max_bytes` (32 KiB by default)." This is a silent truncation — the user may not realize that AGENTS.md files deep in the tree were not loaded. Violates Nielsen Heuristic #1 (visibility of system status) and Heuristic #9 (help users recognize, diagnose, recover from errors). [Source: evidence/codex.md §9]
- **Claude Code memory loss after /compact** — "Troubleshoot instructions seem lost after /compact is a documented issue in the memory docs." This is a known regression — compaction (which summarizes older turns to free tokens) sometimes drops memory-related instructions. Violates Heuristic #4 (consistency and standards). [Source: evidence/claude-code.md §23, citing https://docs.anthropic.com/en/docs/claude-code/memory]
- **ChatGPT dependency-rule asymmetry** — Turning off "Reference saved memories" also turns off "Reference chat history" (one-way dependency). But turning off "Reference chat history" alone is allowed. This is a non-obvious dependency that violates Nielsen Heuristic #2 (match between system and real world) — no real-world analog for "saved facts gate gleaned facts." [Source: evidence/chatgpt.md §9]
- **ChatGPT retention after deletion** — "We may retain a log of deleted Saved Memories for up to 30 days for safety and debugging purposes." The user deletes a memory but it persists in a debug log for 30 days — a transparency gap. Combined with: "To fully remove a memory, delete both the saved memory in Manage memories and the chat where you originally shared it" — full deletion requires non-obvious dual action. [Source: evidence/chatgpt.md §9]
- **Granola's 30-day free-tier memory cutoff** — "view and work with notes older than 30 days" requires paid plan. This is a paid-feature gate on memory retrieval. While commercially rational, it means a free-tier user's "perfect meeting memory" is effectively amnesia after 30 days — a sharp cliff that violates Heuristic #4 (consistency and standards: the system behaves differently based on subscription state). [Source: evidence/granola.md §9, citing https://granola.ai/]
- **Windsurf's unreachable memories docs page** — "Windsurf memories docs page was unreachable (curl returned 1-char body — JS-rendered SPA without server-rendered content; no Wayback snapshot found)." The memory feature exists but its documentation is inaccessible — making it impossible to evaluate against the criteria above. [Source: evidence/windsurf.md §9 — gap noted]

## 7. Cognitive Load Implications (cite CLT)

- **Working-memory offload via auto-memory**: Claude Code auto memory ("notes Claude writes itself based on your corrections and preferences") and ChatGPT auto-management both offload the user's working memory (~4±1 chunks per Cowan 2001) — the user does not need to re-establish context each session. This reduces extraneous load. [Source: academic/cognitive-load-theory.md §1; evidence/claude-code.md §9; evidence/chatgpt.md §9]
- **Schema construction via categorized memory**: Claude's 4 categories (role/projects/professional; communication preferences/working style; technical preferences/coding style; project details/ongoing work) are schema-construction aids — they organize memory into chunks aligned with the user's likely retrieval cues, maximizing germane load. [Source: evidence/claude.md §9; academic/cognitive-load-theory.md §22 — germane load maximization]
- **Split-attention risk from CLAUDE.md/AGENTS.md size**: Claude Code guidance "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence" is direct CLT-grounded advice — long memory files create split-attention between memory content and current task. Codex's 32 KiB cap serves the same function but is silent (no user-visible warning). [Source: evidence/claude-code.md §9; evidence/codex.md §9; academic/cognitive-load-theory.md §30 — split-attention effect]
- **Expertise-reversal risk for auto-managed memory**: ChatGPT auto-management may "move less important memories to the background" — for expert users who rely on specific facts the model deems "less important," this expertise-reversal effect (Kalyuga et al. 2003) degrades performance. Mitigation: user can manually prioritize. [Source: academic/cognitive-load-theory.md §44; evidence/chatgpt.md §9]
- **Segmentation principle via scope hierarchy**: Claude Code's 4-tier scope (Managed → User → Project → Local) segments memory into element-interactivity levels — org-wide rules are high-interactivity (apply everywhere), local rules are low-interactivity (apply only here). This is CLT segmentation in product form. [Source: academic/cognitive-load-theory.md §51; evidence/claude-code.md §9]
- **Illusion of knowing risk (arXiv:2607.02723)**: Auto-managed memory (ChatGPT, Claude) can create an "illusion of knowing" — the user trusts the AI's memory without verifying it. ChatGPT's gray-out mitigation (visible but not referenced) makes this inspectable; Claude's Settings > Reflect monthly recap is the strongest meta-cognition surface. [Source: academic/cognitive-load-theory.md §65, citing https://arxiv.org/abs/2607.02723; evidence/chatgpt.md §9; evidence/claude.md §9]

## 8. Progressive Disclosure Relationship

- **Claude's Agent Skills 3-level progressive disclosure** (loaded at startup with skill name+description; second level = skill body; third level = bundled files) parallels its memory model — categorized entries are loaded incrementally, with the user able to drill into Settings > Memory for full detail. Memory by default operates silently; the user sees entries only when navigating to Settings. [Source: evidence/claude.md §18, citing https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills]
- **ChatGPT memory surfaces**: Memory update toast auto-dismissed; user can click "Manage memories" to drill in. Sidebar conversation history shows only titles; user clicks to expand full transcript. Custom Instructions hidden in Settings. Memory management UI hidden in Settings > Personalization > Memory > Manage memories; requires deliberate navigation. Canvas shortcuts appear as a top toolbar only when Canvas is open. The pattern: surface only what's needed for the current action; reveal advanced controls on demand. - **Claude Code /init as progressive disclosure onboarding**: `/init` generates a starting CLAUDE.md automatically. `CLAUDE_CODE_NEW_INIT=1` enables an interactive multi-phase flow that "asks which artifacts to set up: CLAUDE.md files, skills, and hooks. - **Nielsen (2006) progressive disclosure claim**: improves learnability, efficiency, error rate. Memory UX operationalizes this — silent memory = primary task, Manage memories UI = advanced surface. ## 10. Performance Implications

- **ChatGPT auto-management**: runs as background process; "memory full" state avoidance. "Twice as much memory capacity" for Plus/Pro (Jun 4 2026 release). No published latency for memory retrieval at query time. [Source: evidence/chatgpt.md §9]
- **Claude real-time memory reads/writes**: "Claude reads, writes, and updates memory entries in real time as you chat rather than on a fixed daily schedule." Real-time operations imply per-message memory overhead. [Source: evidence/claude.md §9]
- **Claude Code context budget**: "Loaded into every session (first 200 lines or 25KB)" — explicit context-budget limit. Size guidance: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence" — direct performance-adherence tradeoff documented. [Source: evidence/claude-code.md §9]
- **Codex 32 KiB cap**: silent truncation — performance is bounded but the user may not know files were skipped. "Codex rebuilds the instruction chain on every run, so there is no cache to clear manually." [Source: evidence/codex.md §9]
- **Claude context window compaction**: "infinite-length conversations (with some exceptions) and significantly reduce length limit errors by summarizing earlier messages when a chat approaches its context limit" (Nov 24, 2025). 1M token context window in beta with Claude Sonnet 4.6 (Feb 17, 2026). [Source: evidence/claude.md §23]
- **Reflect semantic index (client-side embeddings)**: "Similar notes" feature via embeddings — client-side computation. "Improved performance for pages with many backlinks" (repeatedly addressed in changelog) is the long-session performance signal. [Source: evidence/reflect.md §9 + §23]
- **Granola Brief pre-computation**: forward-looking memory implies a pre-compute job that runs before each meeting — latency not documented. [Source: evidence/granola.md §9 — latency gap noted]
- **Amie auto-recording mode**: "fully-automatic recordings... will record every call without you having to do anything" + auto-stop — performance is meeting-cycle-bound, not query-bound. [Source: evidence/amie.md §23]

## 11. Long-Session Impact

- **ChatGPT** — Three structural challenges: (1) context window overflow → automatic compaction (user cannot see the compaction summary); (2) memory accumulation → "memory full" state (mitigated by auto-management GA); (3) topic drift → sidebar groups by date not topic (Projects are the structural answer). Resume after absence: server-side state, click past chat in sidebar to resume. Mobile continuity historically buggy (Codex changelog Jul 2026). [Source: evidence/chatgpt.md §23]
- **Claude** — Sustained multi-hour performance: Sonnet 4.5 "maintaining focus for more than 30 hours on complex, multi-step tasks"; Opus 4 "independently for 7 hours with sustained performance" on Rakuten refactor. Edit prior chat messages to branch. Multiple artifacts in a conversation kept open in parallel, switchable via slider. Project isolation prevents context pollution. Cowork scheduled tasks (work continues when laptop closed). Persistent Cowork thread from phone. Memory persistence across sessions (real-time read/write). Reflect/monthly recap shows long-session patterns. [Source: evidence/claude.md §23]
- **Claude Code** — Auto-compact preserves context. Session persistence to disk by default. Session resume (`-c`/`-r`/interactive picker). Session ID explicit UUID control. Cloud sessions for very long runs. Background agents for non-blocking. Worktrees for parallel long sessions on same repo. Known issue: "Troubleshoot instructions seem lost after /compact." [Source: evidence/claude-code.md §23]
- **Codex** — `/compact` for context preservation. `codex resume` (picker), `codex resume --last`. `codex fork` to fork a previous interactive session. Session archive/delete/unarchive. Cloud agents for very long runs in isolated environments. No `--bg` (but `codex exec-server` experimental). OTEL monitoring for long-running sessions. [Source: evidence/codex.md §23]
- **Cursor** — Forum users recommend external scaffolding for big projects (PRD + Cursor Rules + Features Doc + RFCs + Implementation). Plan Mode created for "longer agents." [Source: evidence/cursor.md §23, citing https://forum.cursor.com/t/guide-how-to-handle-big-projects-with-cursor/70997 + https://cursor.com/blog/plan-mode]
- **Windsurf** — Auto-continue on limit + resumable sessions + checkpoints/summaries. Multiple Cascades for parallel long-running work. [Source: evidence/windsurf.md §23]
- **Obsidian** — Multi-pane workspace + bookmarks + tab groups mitigate outliner fatigue (no outliner is primary; Markdown is freeform). CLI "TUI mode" with autocomplete reduces typing fatigue for power users. Plugin ecosystem offers "Outliner" by Viacheslav Slinko for WorkFlowy-style behavior. [Source: evidence/obsidian.md §23]
- **Reflect** — Daily notes as anchor (every session starts/ends on today's). Split-pane view. History browser for time-travel. Random note for serendipity. Tasks aggregation. AI chat with notes for reflection across sessions. Persistent search results. Lock screen audio widget. Improved performance for pages with many backlinks (long-session friction point repeatedly addressed). [Source: evidence/reflect.md §23]
- **Amie** — Designed for full-workday workflow (record → summarize → action-item → schedule → follow-up). "7-day journey" framing suggests heavy daily usage. Testimonials: "We use Amie daily, and without it, we'd be at least 50% less productive." Auto-recording mode removes manual overhead. Auto-stop and auto-record-on-join reduce button-pressing across back-to-back meetings. [Source: evidence/amie.md §23]
- **Granola** — Designed for "back-to-back meetings" (tagline). Architecture choices that reduce long-session fatigue: user does not take detailed notes during call (reduced cognitive load); Brief pre-computes context; post-meeting actions one-click; corpus accumulates without user effort. Apple Watch app extends capture to walking meetings. [Source: evidence/granola.md §23, citing https://granola.ai/]
