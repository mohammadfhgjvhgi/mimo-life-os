## 1. Pattern Definition

**Workspace UX** is the interaction pattern governing how the primary working surface of a product is composed: how panes (chat, preview, code editor, file tree, sidebar, terminal, canvas), tabs, split views, and overlay surfaces are arranged, toggled, and resized; how a single workspace is isolated (sandbox, vault, graph, repo, project, space); how multiple workspaces are switched (Spaces, accounts, environments); and how the layout adapts between AI-heavy "agentic" mode and editor-first "classic" mode. The workspace is the *spatial container* in which Conversation UX (Pattern 1) lives; it determines whether chat is the whole screen (ChatGPT/Claude consumer), a side panel (Cursor, JetBrains, MS Copilot pane), a CLI in a working directory (Claude Code, Codex, Aider), or a whiteboard-anchored overlay (Heptabase, Tana). [Source: evidence/chatgpt.md §6, citing https://web.archive.org/web/2025/https://openai.com/index/introducing-canvas; evidence/lovable.md §6, citing https://docs.lovable.dev/features/projects/editor.md; evidence/zed.md §6, citing https://zed.dev/docs/getting-started; evidence/arc.md §6, citing https://resources.arc.net/hc/en-us/articles/19335393146775-Split-View-View-Multiple-Tabs-at-Once]

## 2. Why It Matters

Workspace layout directly determines **split-attention load** (Sweller, Chandler & Tierney 1990, *Cognition and Instruction* 8(4):293–332) — one of CLT's most replicated effects. Physically integrating related information (chat + preview + diff in one view) reduces extraneous load; scattering across non-overlapping surfaces increases it. [Source: academic/cognitive-load-theory.md §5, citing Sweller, Chandler & Tierney 1990; §6 — "split-attention between text and diagram... physically integrating text and diagram reduces EL and improves learning."]

Jakob Nielsen's Heuristic #1 "Visibility of system status" and Heuristic #6 "Recognition Rather than Recall" both apply: workspace layout is the primary mechanism by which the user *sees* what the AI is doing and *recognizes* where state lives, rather than recalling it from a prior screen [Source: academic/recognition-vs-recall.md §6 — "Visible state (progress bars, status indicators) vs. requiring user to recall what they last did"; academic/jakob-nielsen.md cross-ref Heuristic #1].

Amershi et al. (2019) G4 "Show contextually relevant information" requires the workspace to surface the right context at the right time — Cursor's Browser visual editor overlay, Manus's Computer pane, and Lovable's chat+preview split are direct implementations [Source: academic/human-ai-interaction.md §4 — G4 "Show contextually relevant information"].

Shneiderman's Eight Golden Rules rule #1 "Consistency" and rule #7 "Support internal locus of control" apply directly: workspace layout must be predictable (Consistency) and the user must always be able to navigate/escape (Locus of control) [Source: academic/ben-shneiderman.md cross-ref].

### 3.5 CLI-anchored workspace (working directory is the workspace)
- **Claude Code**: Working directory is the workspace. `--add-dir <directories...>` for additional directories (repeatable). No split view in terminal mode. VS Code extension adds editor overlay. **Cloud sessions** give cloud workspace with `--environment <environment_id>` for self-hosted environments (ccpool_...). Plugins via `--plugin-dir <path>` (local) or `--plugin-url <url>` (remote zip). Settings via `--settings <file-or-json>`. MCP via `--mcp-config` and `--strict-mcp-config`. [Source: evidence/claude-code.md §6, citing `claude --help` 2025-08-07]
- **Codex**: Working directory = workspace. Default current directory; override `--cd <DIR>`; extend `--add-dir <DIR>`. `/status` shows workspace directories. `/tmp` is in workspace by default. Cloud environments: "Codex cloud: Runs in isolated OpenAI-managed containers, preventing access to your host system or unrelated data." `codex sandbox` subcommand: macOS `sandbox-exec` profile, Linux Landlock+seccomp. IDE extension separate from CLI. [Source: evidence/codex.md §6, citing https://developers.openai.com/codex/security and `codex exec --help`]
- **Aider**: Workspace = developer's terminal inside (or at root of) git repo. Refuses to operate cleanly outside git repo: "It asks to create a git repo if you launch it in a directory without one." No separate UI surface beyond terminal. Optional browser GUI: `aider --browser` / `aider --gui`. IDE watch mode: `--watch-files` lets you write `// ai!` comments inside any editor and Aider reacts. [Source: evidence/aider.md §6, citing https://aider.chat/docs/git.html and `aider --help`]
- **Devin**: Web app workspace with embedded IDE visible alongside session transcript. Three cards: **Shell** ("Devin's terminal, where you can watch commands being executed and view output logs"), **IDE** ("Devin's embedded code editor equipped with all the IDE tools and shortcuts you're familiar with"), **Browser** ("Watch Devin browse through documentation, test web applications it builds... You can jump in to help Devin navigate through browsing tasks via the Interactive Browser"). Devin runs in sandboxed cloud VM with full Linux desktop (or Windows): "Devin sees the screen as a 1024×768 pixel display and can perform actions like clicking, typing, scrolling, dragging, and taking screenshots." Multi-surface: Devin Desktop, Devin CLI, Devin in Windsurf, Devin in JetBrains (ACP), Devin in Zed/Xcode (ACP). [Source: evidence/devin.md §6, citing https://docs.devin.ai/get-started/devin-intro.md and https://docs.devin.ai/work-with-devin/computer-use.md]
- **Warp**: Terminal blocks + Warp Drive panel + Code Review panel + Code editor + File Tree. "Modern terminal UX: Cursor movement, block-based navigation, multi-line editing, syntax highlighting, and rich completions. Built with Rust for high performance." Built-in Code editor with LSP support: "File tree, code editor with LSP support, and interactive code review experience." Warp Drive = persistent knowledge/workspace layer: "When you open the Warp Drive panel, you will find a personal workspace where you can store your Workflows, Notebooks, Prompts, and Environment Variables and organize them into folders. If you are a member of a team using Warp Drive, your team's workspace will also be available in the side panel." Warp Drive on the web is a docs subtopic. Warp Agent CLI workspace: built-in multiplexer — "directly manages pty connections similarly to tmux, unlocking more powerful agent workflows." [Source: evidence/warp.md §6, citing https://docs.warp.dev/ and https://www.warp.dev/agent-cli]
- **Grok (developer)**: `xai-grok-shell` TUI; Agent Dashboard via `grok dashboard`; headless mode `grok -p "prompt"` with output formats plain/json/streaming-json; sessions at `~/.grok/sessions`; TOML config at `~/.grok/config.toml` with `[cli]` and `[ui]` sections; env vars `GROK_THEME`, `GROK_SHOW_THINKING_BLOCKS`, `GROK_GROUP_TOOL_VERBS`, `GROK_COLLAPSED_EDIT_BLOCKS`, `GROK_PROMPT_SUGGESTIONS`; worktrees `grok worktree <list|show|rm|gc>`. [Source: evidence/grok.md §6, citing https://docs.x.ai/llms.txt]

### 3.6 Multi-workspace isolation (sandbox/runtime variants)
- **OpenHands**: Multiple workspace types — (a) LocalWorkspace (direct local FS execution), (b) RemoteWorkspace (HTTP/WebSocket delegation to agent-server), (c) DockerSandbox (isolated Docker containers for security and reproducibility), (d) ApptainerSandbox (rootless Apptainer for HPC/shared computing), (e) CloudWorkspace (OpenHands Cloud managed sandboxes with optional SaaS credential inheritance), (f) API-based Sandbox (fully-managed infrastructure). V1 design principle: "Sandboxing should be opt-in, not universal" — unlike V0 where every tool call executed in a Docker sandbox by default. [Source: evidence/openhands.md §6, citing https://docs.openhands.dev/sdk/arch/sdk.md and https://docs.openhands.dev/sdk/arch/design.md]
- **Anytype**: Workspace is the **Vault** — "Your cryptographic Key is generated locally on your device when you create your Vault." Vault contains one or more **Spaces/Channels** (isolated sync-and-permission domains). Personal Spaces vs Collaborative Spaces — "Shared environments where you can work seamlessly with family, project teams, or entire communities. Chats and discussions live directly inside your spaces." Critical isolation constraint: "Types are specific to each Channel... at the moment, you cannot share Types between spaces that stay in sync because they are separated with different encryption keys." Each Channel has its own encryption keys. Includes Chat surface, Discussions surface, Publish surface (publish Objects as static webpages on personal subdomain). [Source: evidence/anytype.md §6, citing https://doc.anytype.io/anytype/basics/key.md and https://doc.anytype.io/anytype/organize/types.md]
- **Craft**: Workspace is the **Space** — Multiple Spaces supported (Personal, Work, etc.); each Space contains Folders, Tags, Collections, Documents, Pages, Blocks. Spaces isolated for MCP/API: "Each MCP connection in Craft is linked to a single space. If you want to give an external tool access to documents across multiple spaces, you need to create a separate MCP connection for each space." External Locations (local storage); Keep on Device Folders; Document Version History; Recovering Deleted Content; multiple accounts. Tabbed multi-document surface with Focus Mode. [Source: evidence/craft.md §6, citing https://craft-support.mintlify.app/en/integrate/mcp.md and https://craft-support.mintlify.app/en/account-and-subscription/storage-and-recovery/external-locations.md]
- **Reflect**: Workspace is the **graph** (one graph per user account by default; multiple graphs supported — "For those of you who like creating multiple graphs we have added a little color setting so you can easily see which area you're in"). Workspace surface: left sidebar (Daily Notes, Notes, Tasks, Brain) + main content pane + AI palette + incoming backlinks panel beneath each note. YJS sync engine — "your offline changes will be merged in a more intelligent manner." History browser: "time-machine for your notes. You can view all of your changes to a note and revert to any point in time." Reflect Open: workspace = folder of Markdown files; sync via iCloud Drive or GitHub; "There is no Reflect account or Reflect-hosted notes database. We don't run product analytics." [Source: evidence/reflect.md §6, citing changelog.txt and reflect-open.txt]
- **Roam**: Workspace = single graph containing all pages and blocks. Multiple graphs switchable. CLI enumerates graph types: `--type hosted` (default, cloud) or `--type offline` (local-only). Within graph: left sidebar (shortcuts) + main content pane + right sidebar (secondary pages) + bottom "Linked References" / "Unlinked References" panels + graph overview map. AI-agent guidelines mechanism: page `[[roam/agent guidelines]]` surfaced to AI agents via `get_graph_guidelines` — Roam's de-facto system-prompt surface. [Source: evidence/roam.md §6, citing https://raw.githubusercontent.com/Roam-Research/roam-tools/master/README.md]
- **Granola**: Workspace = meeting-notes-as-documents. Each meeting becomes a note card with title, date, structured sections (Topics/Next Steps/Action Items). "There is no multi-pane workspace model in the crawlable surface — Granola is a single-note-centric app with a list of recent notes. There is no concept of 'projects' or 'files'; the atomic unit is the meeting note." [Source: evidence/granola.md §6, citing https://granola.ai/]

## 5. Premium Exemplars

**VS Code** — best-evidenced per-element customizability: Custom Layout (1.84) "lets users reposition, hide, and reorder every UI element — Activity Bar can move to top, Panel can move to right or left, Side Bar can be on either side" [Source: evidence/vscode.md §6, citing https://code.visualstudio.com/docs/configure/custom-layout]. Editor groups with split views up to three side-by-side. Zen Mode (⌘K Z) for distraction-free work. This is the most flexible workspace topology observed and directly serves Shneiderman Golden Rule #7 "Support internal locus of control" by giving the user total layout agency.

**v0** — best-evidenced agentic three-pane workspace: chat + preview/code editor + sidebar, with sandbox-VM-backed Preview tab, Console panel (Logs + Terminal tabs), built-in code editor attached to same filesystem (syntax highlighting, line numbers, find/replace, global search, file explorer, diff view, split view), Design Mode overlay (Option+D) turning the cursor into a selection tool with Cmd+I Inspect toggle [Source: evidence/v0.md §6, citing https://v0.dev/docs/sandbox and https://v0.dev/docs/design-mode]. The "single filesystem across editor + terminal + agent" property is uniquely well-documented — every actor reads/writes the same files.

**Arc** — best-evidenced *creative* Split View: "When you create a split view, it becomes its own new tab in the sidebar that you can come back to later" [Source: evidence/arc.md §6, citing https://resources.arc.net/hc/en-us/articles/19335393146775]. This solves the "transient split vs. saved split" tension that VS Code's split view (transient, dies when closed) does not. Spaces (Cmd+1/2/...) with own tabs/theme/cookies is the cleanest multi-context isolation observed for a browser-class product.

**OpenHands** — best-evidenced workspace isolation taxonomy: six workspace types (LocalWorkspace, RemoteWorkspace, DockerSandbox, ApptainerSandbox, CloudWorkspace, API-based Sandbox) with explicit V1 design principle "Sandboxing should be opt-in, not universal" [Source: evidence/openhands.md §6, citing https://docs.openhands.dev/sdk/arch/sdk.md and https://docs.openhands.dev/sdk/arch/design.md]. Most systematic treatment of the trust/security/sandbox trade-off.

**NotebookLM** — best-evidenced 3-pane source-grounded chat workspace: Sources (left, with type icons and per-query grounding scope) + Chat+Notes (center, with save-as-Note affordance) + Notebook Guide (right, auto-generated summary + key topics + suggested questions + one-click artifact generators: Audio Overview, Video Overview, Mind Map, Study Guide, Briefing Doc, FAQ, Infographic, Slide Deck) + per-claim inline citations click-to-jump to original quote [Source: evidence/notebooklm.md §6, citing https://support.google.com/notebooklm/]. The tightest chat-citation-source loop observed.

**Zed** — best-evidenced dual-mode workspace: Panel Layout toggle (Agentic vs Classic) explicitly switches between AI-agent-heavy work and editor-focused work; multi-buffers allow "edit across files" workflows; Agent Panel states intent + lists file ops + executes with user watching [Source: evidence/zed.md §6, citing https://zed.dev/docs/getting-started]. Most clearly articulates the "two modes of work" pattern.

**Lovable** — best-evidenced dockable preview workspace: Preview toolbar dockable at bottom-center of preview, draggable anywhere (snaps to corners), minimizable to a tab, or hidden; sidebar collapsible (Cmd+B) for full-window preview; mobile app arranges "the same areas as swipeable views instead of a top bar" [Source: evidence/lovable.md §6, citing https://docs.lovable.dev/features/preview-toolbar.md and https://docs.lovable.dev/features/projects/editor.md]. Most flexible preview-pane positioning observed.

## 6. Anti-Patterns

**Bolt (Safari)** — "In Safari, Code view is read-only (must use Chrome/Chromium/Opera/Brave/Edge/Vivaldi to edit code)" [Source: evidence/bolt.md §6, citing https://support.bolt.new/building/using-bolt/code-view.md]. Browser-specific degradation of a core workspace surface violates Shneiderman Golden Rule #1 "Consistency" — the same affordance should behave the same regardless of host browser. (Note: This is a technical constraint of WebContainer API not supporting Safari, but the UX outcome is degraded.)

**Notion (no native split-view)** — "Notion does not natively support side-by-side page editing. Users work around this by opening multiple windows." [Source: evidence/notion.md §6, citing notion-help-sidebar.html]. For a knowledge-management product, the absence of side-by-side comparison forces context-switching (CLT split-attention effect).

**Linear (no split view)** — "Split view NOT natively supported for issues side-by-side — Linear chooses to keep one issue detail open at a time (mitigated by Peek/Quick view with hover-to-preview)." [Source: evidence/linear.md §6]. Explicit design choice, but limits comparison-heavy workflows (reviewing two issues, two PRs, two coding sessions side-by-side).

**MS Copilot (Teams ephemeral)** — "Copilot conversations close when the side panel closes" [Source: evidence/ms-copilot.md §7 cross-ref §6]. Violates Amershi G12 "Remember recent interactions" — closing the side panel destroys the conversation state.

**Granola (no multi-pane)** — "There is no multi-pane workspace model in the crawlable surface — Granola is a single-note-centric app with a list of recent notes. There is no concept of 'projects' or 'files'; the atomic unit is the meeting note." [Source: evidence/granola.md §6, citing https://granola.ai/]. Adequate for a meeting-notes product, but evidence that single-note workspaces do not support comparison or multi-meeting synthesis workflows.

**ChatGPT Canvas version history** — "implicit version history via back/forward navigation, not a named 'versions' list." [Source: evidence/chatgpt.md §6]. Compare to Claude's explicit "Version selector allows switching between versions" and Gemini Canvas's "Previous Version / Next Version." ChatGPT Canvas's lack of named version list forces recall ("which back-arrow count was the good version?") rather than recognition — violates Nielsen Heuristic #6.

## 7. Cognitive Load Implications

CLT predicts the following workspace-UX effects [Source: academic/cognitive-load-theory.md §5–7, citing Sweller 1988 *Cognitive Science* 12(2):257–285 and Sweller, Chandler & Tierney 1990]:

- **Split-attention effect** — workspace layouts that physically separate related information (chat in one pane, diff in another, file tree in a third, terminal in a fourth) increase EL unless the user can integrate them mentally. v0's "built-in editor attached to the same filesystem, so edits from the editor, v0, or the terminal all read and write the same files" directly addresses this by ensuring semantic integration. [Source: academic/cognitive-load-theory.md §5 — split-attention effect (Sweller, Chandler & Tierney 1990).]

- **Redundancy effect** — workspace layouts that duplicate state (e.g., chat saying "I edited foo.ts" + diff card showing the edit + file tree highlighting foo.ts) increase EL unless one channel suffices. Claude Artifacts, Lovable activity cards, and Cursor Browser visual editor each choose *one* integration point (artifact panel / activity card / visual overlay) — CLT-aligned.

- **Expertise reversal** — Helix's fully configurable `[editor.statusline]` and `[editor.gutters]` arrays serve experts who want maximum information density; Things3's "fields are neatly tucked away in the corner until you need them" serves novices who want minimal initial surface. CLT predicts these can't be the same product [Source: academic/cognitive-load-theory.md §5 — expertise-reversal effect (Kalyuga, Ayres, Chandler & Sweller 2003)].

- **Working-memory limit (~4 chunks per Cowan 2001)** — multi-pane workspaces with >4 simultaneous visible panes exceed working-memory capacity for state-tracking. Zed's Agentic-vs-Classic toggle and Lovable's collapsible sidebar (Cmd+B) directly manage this by hiding panes when not needed [Source: academic/cognitive-load-theory.md §1, §10 — Cowan 2001 modernization of Miller's 7±2 to 4±1].

- **Schema construction (germane load)** — Manus Cloud Computer's persistent file system ("Files Manus creates on it stay there. Tools Manus installs stay installed. If you want Manus to pick up where it left off last week, it can, because the work is still sitting on the machine") supports schema construction across sessions — the user's mental model of the workspace persists, reducing re-orientation cost [Source: academic/cognitive-load-theory.md §3 — germane load definition].

## 8. Progressive Disclosure Relationship

Progressive disclosure (Nielsen 2006) interacts with workspace UX in five documented patterns [Source: academic/progressive-disclosure.md §4–7, citing Nielsen 2006 nngroup.com/articles/progressive-disclosure/]:

1. **Pane reveal on demand** — Lovable's preview toolbar dockable / draggable / minimizable-to-tab / hidden; VS Code Zen Mode (⌘K Z) hides all chrome except editor; Helix's `bufferline = "multiple"` (only show buffer line when >1 buffer); Cursor's Browser visual editor overlay only when invoked; v0's Design Mode overlay toggled with Option+D. Each is "initially simplified surface with drill-down on demand" — direct instantiation of Nielsen 2006 criterion #3 "discoverability."

2. **Picker / command palette as transient overlay** — Helix `Space ?` command palette; Raycast's centered translucent window; v0 slash-command menu; Warp `/agent`; Notion `/ai`. Each hides complexity behind a keyboard shortcut — the canonical progressive-disclosure widget (GTK Disclosure, macOS "Show Details" triangle, Apple HIG "Disclosure Views").

3. **Layered workspace modes** — Zed Agentic vs Classic; Le Chat Chat/Work/Vibe Code; Replit Plan/Build + Lite/Economy/Power; Lovable Build/Plan; Linear multiple AI surfaces (Linear Asks vs Triage Intelligence vs Coding Sessions). Each mode progressively reveals more capability as the user moves from quick chat to autonomous agent.

4. **Tool-call / activity-card disclosure** — Lovable's expandable activity cards (collapsed by default); Dust's "Completed in N sec" affordance opening details panel; Cursor's checkpoint timeline preview-on-click; Codex `/diff` to surface Git diff on demand. All are "initially simplified feedback that hides potential system errors and helps users build working heuristics" — empirically validated by Springer & Whittaker 2018 (arXiv:1811.02164) [Source: academic/progressive-disclosure.md §5].

5. **Context-menu / right-click disclosure** — Bolt's right-click in Files list reveals "New file… / Delete / Target file / Lock file / Lock all"; Cursor's right-click affordances in editor; Heptabase AI Action buttons appear on hover over any card. Each is "discoverability criterion" — obvious how to drill down [Source: academic/progressive-disclosure.md §4].

**Opacity-theatre risk** — arXiv:2605.10930 (2026) "false trust engendered by LLM explanations" requires that progressive disclosure not become opacity theatre; users must always be able to drill down to verify [Source: academic/progressive-disclosure.md §7–8, citing arXiv:2605.10930]. Bolt's undocumented activity-card UI (per evidence/bolt.md §7 "Evidence gap") is the documented failure case in this corpus.

## 10. Performance Implications

Workspace topology affects perceived performance in three documented ways:
- **Live preview updates** — Lovable "live, interactive version of your app that updates as Lovable works"; Cursor Browser "agents run in parallel, and within seconds your changes are live"; Manus Cloud Browser "You see everything Manus is doing in real-time." Real-time visual updates reduce the perceived duration of agent work [Sources as cited in §3.3].
- **Single-shared-filesystem across panes** — v0's "built-in editor attached to the same filesystem, so edits from the editor, v0, or the terminal all read and write the same files" eliminates cross-pane sync latency and race conditions [Source: evidence/v0.md §6].
- **Isolated task copies** — Replit "Background tasks run 'in isolated copies of your project' so the main version is never modified until Apply" — user perceives zero blocking while agent works in parallel [Source: evidence/replit.md §6, citing https://docs.replit.com/core-concepts/agent/task-system.md].
- **Persistent cloud workspaces** — Manus Cloud Computer "If you want Manus to pick up where it left off last week, it can, because the work is still sitting on the machine"; Cursor Cloud Agents "VMs in the cloud with full development environments instead of on your local machine" — eliminate cold-start cost of re-instantiating environments [Source: evidence/manus.md §6; evidence/cursor.md §6].
- **Configurable statusline** — Helix `[editor.statusline]` with `spinner` element shows agent activity state, reducing "is it working?" polling cost [Source: evidence/helix.md §6, citing https://docs.helix-editor.com/editor.html].

## 11. Long-Session Impact

Multi-hour workspace use faces three documented failure modes:
1. **Pane sprawl** — solved by Arc Spaces (own tabs/theme/cookies), Craft Spaces (isolated MCP per Space), Reflect graph color setting, Heptabase sub-whiteboards nesting. Without isolation primitives, long sessions accumulate context noise.
2. **State loss on crash** — Lovable draft persistence ("draft answers persist in browser so a refresh doesn't lose them"); v0 "Typed prompts survive clarifying questions, permission approvals, and queued submissions"; Reflect YJS sync engine "your offline changes will be merged in a more intelligent manner"; Reflect History browser "time-machine for your notes... revert to any point in time"; Craft Document Version History; Obsidian sync user-avatars (LC/TG/SA) on shared vaults. [Sources as cited in §3.]
3. **Workspace re-orientation cost** — solved by Amie notch overlay (always-accessible recording control); Raycast single-window dismiss-on-Esc (no re-orientation cost); Apple Siri cross-device conversation continuity ("ask a question on your iPhone and pick up where you left off on your iPad"); Linear mobile coding sessions; Replit cloud-hosted accessible from any device. [Sources as cited in §3.]

Long sessions also reveal **workspace-mode switching cost** — Zed's Agentic vs Classic toggle, Le Chat's Chat/Work/Vibe Code modes, Replit's Plan/Build/Economy/Power modes. Each mode switch incurs re-orientation EL; long sessions that require frequent mode switching benefit from persistent state across modes.

## 12. Open Questions

- **Cross-workspace search** — Roam's `get_graph_guidelines` surfaces AI-agent instructions; Reflect's graph color setting; Craft's per-Space MCP isolation; Anytype's per-Channel encryption isolation. No evidence file documents a unified cross-workspace search surface.
- **Multi-window vs multi-tab vs multi-Workspace** — Arc favors Spaces; Notion favors Tabs + New Window; Linear favors Tabs; VS Code favors Editor Groups; Raycast explicitly rejects multi-window. No evidence on which is cognitively superior for which task class.
- **Agentic vs Classic layout evidence** — Zed's Panel Layout toggle is documented as "two distinct workspace modes — one for AI-agent-heavy work, one for editor-focused work" but no user-study evidence on when to switch.
- **Mobile workspace topology** — Lovable mobile swipeable views; v0 mobile no-split-view; Apple Intelligence cross-device; Replit cloud-hosted. No evidence on whether mobile workspaces should be simplified vs. full-fidelity.
- **Hardware-anchored workspace a11y** — Ray-Ban Meta "no HUD / no AR display" by design; Meta Ray-Ban Display (Connect 2025) introduces display + neural wristband. No evidence on accessibility of neural-wristband input.
- **Workspace-level cost transparency** — only v0 and Lovable document per-message Credits used; no evidence on workspace-level cost (compute-hours, storage, egress) transparency.
