# Agent UX Pattern

> Pattern synthesis (PAT-2). Evidence-based synthesis from 11 product evidence files (manus, cursor, claude-code, codex, openhands, langgraph-studio, dust, devin, sweep, github-spark, replit). No MiMo design recommendations. Every claim cites `evidence/<product>.md §<section>`.

---

## 1. Pattern Definition

**Agent UX** is the design pattern by which an AI product exposes an *autonomous or semi-autonomous agent* — a system that reasons, plans, takes actions (tool calls, file edits, terminal commands, browser navigation, sub-agent delegation), and produces artefacts, with the user in a supervisory, approving, or steering role. It is the *collaboration* surface between human and AI agent: what the user sees of the agent's reasoning, what the user can interrupt or steer, how the agent's actions are gated, how sub-agents and parallel agents are surfaced, and how the final artefact is rendered and reviewable.

Six observable parts:

1. **Agent concept / mental model** — what does the product call its agent? (Claude Code "subagents", OpenHands "Agent + TaskToolSet", Dust "deep-dive agent", Manus "Skills + Plan Mode", Cursor "Agent + Composer + Cloud Agents", Devin "parallel Devins + Managed Devins", GitHub Spark "Copilot cloud agent", Replit "Agent + task system").
2. **Reasoning visibility** — does the user see the agent's thoughts/plan before/during execution? (Manus Plan Mode Markdown plan, Cursor Plan Mode Markdown plan, Gemini Edit Plan, OpenHands ActionEvent thought/reasoning, LangGraph graph traversal, Dust live step streaming).
3. **Action gating / approval** — Allow Once / Always Allow (Manus Desktop), `--permission-mode plan/acceptEdits/auto/bypassPermissions/manual/dontAsk` (Claude Code), sandbox modes (Codex), AlwaysConfirm/NeverConfirm/ConfirmRisky (OpenHands), Accept tasks / Revise plan (Replit), Accept/Reject ⌘Y/⌘N (Sweep).
4. **Multi-agent surfaces** — parallel Devins (Devin), TaskToolSet sub-agents (OpenHands), @dust-task 6 concurrent sub-agents (Dust), Agent teams (Claude Code), Cloud Agents dashboard (Cursor), Managed Devins coordinator (Devin), Fleet Mode (GitHub Spark).
5. **Steering / interruption** — send messages mid-run (Dust), Stop button (Lovable, Dust, Manus), queue follow-ups (Cursor, Replit), sleep/wake (Devin), Take Over flow (Manus Cloud Browser), Begin take over (Replit App Testing).
6. **Artefact / completion semantics** — PR (Devin, Sweep), code diff (Cursor, Lovable, v0), version history (Bolt), Markdown plan (Manus, Cursor, Lovable, Bolt, Gemini), work details (v0), activity cards (Lovable).

The pattern is *not* "agent with tools" — it is the *user-experience layer* over the agent's lifecycle: invocation → planning → execution → supervision → artefact review.

## 2. Why It Matters (with academic evidence)

**Amershi et al. 2019 HAX guidelines** — the foundational industry HAX framework — directly motivate agent UX. The 18 guidelines span four phases; agent UX maps heavily onto "During interaction" (G3 time services based on context; G4 show contextually relevant information; G7 support efficient invocation; G8 support efficient dismissal/interruption; G9 support efficient correction; G10 scope services when uncertain; G11 make clear why the system did what it did) and "When wrong" (G12 remember recent interactions; G13 learn from user behavior; G14 update and adapt cautiously; G15 encourage granular feedback; G16 convey the consequences of user actions; G17 provide global controls). [Source: academic/human-ai-interaction.md §4 — Amershi et al. 2019, doi:10.1145/3290605.3300233]

**Paimann et al. 2026 (arXiv:2607.19941)** "Eight Core UX Principles for Human-AI Agent Interaction in the Workplace" — derived via participatory design workshop, paper-and-pencil, expert review, meta-analysis, and in-depth interviews. Lists "transparency", "discoverability", and "cognitive load" as core UX principles for human-AI agent interaction. Directly grounds the agent-UX pattern. [Source: academic/human-ai-interaction.md §2, §4, citing arXiv:2607.19941, accessed 2026-08-07; cross-referenced in academic/cognitive-load-theory.md §7, academic/progressive-disclosure.md §7, academic/information-scent.md §7]

**Trust calibration** (Lee & See 2004; Parasuraman & Riley 1997): agent UX must calibrate trust — neither over-trust (misuse: user follows wrong agent actions) nor under-trust (disuse: user ignores correct agent actions). Approval gates (Manus Allow Once / Always Allow; Codex sandbox modes; OpenHands AlwaysConfirm/NeverConfirm/ConfirmRisky; Replit Accept tasks / Revise plan; Sweep ⌘Y/⌘N) are the canonical trust-calibration mechanisms. [Source: academic/trust-in-ai.md §3, §4 — Lee & See 2004; Parasuraman & Riley 1997]

**False trust finding** (Palod et al. 2026, arXiv:2605.10930): "Reasoning traces and post-hoc explanations are 'persuasive but not informative' — they increase user acceptance regardless of correctness. Only **contrastive dual explanations** (arguments for AND against the AI's answer) genuinely improve users' ability to distinguish correct from incorrect AI outputs." Implication: agent UX that surfaces only the agent's chosen path (most products) engenders false trust. LangGraph's conditional-edge visualisation (showing branch candidates) and OpenHands's UserRejectObservation with feedback are correctives. [Source: academic/trust-in-ai.md §4 — Palod et al. 2026]

**Gao et al. 2026 (arXiv:2607.24601) trust/agreement trade-off**: Condition A (full explanation): trust M=3.99/5 (highest); agreement lower. Condition B (moderate explanation): agreement 89.22% (highest). Condition C (no explanation): lowest trust and agreement. Conclusion: more explanation prompts developers to question AI recommendations more frequently. Implication: agent UX explainability depth is a *trust/agreement trade-off*, not a monotonic "more is better" curve. [Source: academic/trust-in-ai.md §4]

**Cognitive Load Theory** (Sweller 1988): agent UX carries heavy extraneous load because agent actions are typically many, fast, and complex. Multi-agent UIs presenting multiple agent states simultaneously increases EL; progressive disclosure of agent detail is CLT-grounded. [Source: academic/cognitive-load-theory.md §7 — "Multi-agent UIs: presenting multiple agent states simultaneously increases EL; progressive disclosure of agent detail is CLT-grounded", citing arXiv:2607.19941]

**Progressive Disclosure** (Nielsen 2006; Springer & Whittaker 2018): agent UX must reveal depth progressively — plan summary → activity card → step detail → tool call. Manus's three-level Skills PD (metadata → instructions → resources) is the cleanest realisation. [Source: academic/progressive-disclosure.md §3, §7]

**Explainable AI** (Rudin 2019; Doshi-Velez & Kim 2017): agent UX is the user-facing realisation of XAI's transparency principle. OpenHands's event-stream (every ActionEvent captures thought + reasoning + security risk) and LangGraph's state inspection are direct realisations. [Source: academic/explainable-ai.md §2, §3]

## 3. Evidence Across Products

### Manus (Plan Mode + 3 execution environments + Skills)
- **Plan-then-execute lifecycle**: (1) User prompt → (2) Plan Mode evaluates and asks clarifying questions or generates Markdown plan → (3) User reviews / edits / confirms → (4) Manus executes per plan → (5) Plan can be re-opened mid-task. "Manus will not start building until you confirm or dismiss the plan. This prevents any unintended changes to your website, slides, or video." [evidence/manus.md §8, citing https://manus.im/blog/manus-plan-mode]
- **Three browser surfaces**: Cloud Browser (default) — "Manus's dedicated browser environment that runs in the cloud. Unlike traditional AI assistants that can only read text, Manus can actually operate this browser like a real person—visiting websites, clicking buttons, filling forms, extracting data, and completing multi-step workflows." Browser Operator (local, Nov 18 2025) — "transforms your web browser into an autonomous agent … allows Manus to securely perform tasks on your behalf directly within your local browser, using your existing logins and sessions." Take Over flow (Cloud Browser) — for SMS codes, CAPTCHA, MFA: (1) Manus encounters verification; (2) User notified; (3) User completes verification; (4) User hands control back; (5) Manus continues. [evidence/manus.md §8]
- **My Computer (Desktop, Mar 16 2026)**: "Manus executes command line instructions (CLI) in your computer's terminal." Examples: organize flower-shop photos (computer vision + file ops), batch-rename invoices, build a Swift meeting-translation Mac app in 20 minutes. "Twenty minutes later: a fully working Mac app. No Xcode opened. No code written manually." [evidence/manus.md §8, citing https://manus.im/blog/manus-my-computer-desktop]
- **Cloud Computer (Apr 30 2026)**: always-on cloud machine; persistent file system; hosted databases (MySQL); self-hosted open-source tools (Home Assistant, Metabase). "A Cloud Computer gives you two things your laptop can't: It never turns off … Your files and setup stay put. Every regular Manus chat starts from a blank slate—it has no access to what you did yesterday. A Cloud Computer works more like your own laptop." [evidence/manus.md §8, §12]
- **Multi-modal agent capabilities**: Image Generation, Image Understanding, Video Understanding, Voice Output, Speech to Text. [evidence/manus.md §8]
- **Wide Research** ("game-changing technical innovation" per $100M ARR blog) — implies parallel/multi-source research mode. [evidence/manus.md §8]
- **Auto-decide AI features** (analogous to v0): when a generated app needs AI, Manus decides how to build them rather than asking. [evidence/manus.md §8]
- **Meeting Minutes, Slides, Data Visualization, Design View (Dec 22 2026)** with Mark Tool. [evidence/manus.md §8]
- **Skills**: "modular, file-system-based resources that encapsulate a specific capability or workflow." Three loading levels (Progressive Disclosure). Add via: Build with Manus (from successful interaction), Upload .skill/.zip/folder, Add from official library, Import from GitHub. [evidence/manus.md §8, citing https://manus.im/docs/features/skills]
- **Per-command approval fatigue is the core trust cost**: "Every command that Manus attempts to execute on your local machine requires your explicit approval. You will be prompted to Allow Once for a single operation or Always Allow for a trusted, recurring task. You are always in command." [evidence/manus.md §21, citing https://manus.im/docs/features/desktop]
- **Explainability**: Plan document as the explainability primitive ("The mistake gets caught before any code is written"); audit trail for Browser Operator ("Every action Manus takes is meticulously logged, providing a clear audit trail"); Cloud Browser History; Scheduled Tasks execution history; Project "what Manus can learn" summaries; Skills review; live runtime visibility. [evidence/manus.md §22]

### Cursor (Agent + Composer + Cloud Agents)
- **Agent is the core visual concept**. Tools: "Intelligently read the content of a file"; "Execute terminal commands and monitor output"; "Control a browser to take screenshots, test applications, and verify visual changes"; "Generate images from text descriptions or reference images"; "Ask clarifying questions during a task. While waiting for your response, the agent continues reading files, making edits, or running commands." [evidence/cursor.md §8, citing https://cursor.com/docs/agent (RSC payload)]
- **Plan Mode visualization**: Markdown plan file with file paths, code references, todos. Inline editable. [evidence/cursor.md §8, citing https://cursor.com/blog/plan-mode]
- **Cloud Agents dashboard**: "shows which environment and Build an agent used, along with environment details and version history. On the agent page, hover over the repository name at the top of the page to inspect the environment used for that run." [evidence/cursor.md §8, citing https://cursor.com/docs/background-agent (RSC payload)]
- **Clarifying questions**: async — "While waiting for your response, the agent continues reading files, making edits, or running commands." [evidence/cursor.md §8]
- **Checkpoints** (primary per-session trust mechanism): "If Agent takes a wrong turn, click any checkpoint in the chat timeline to preview your files at that point, then restore to revert all files to that state." Checkpoints are separate from Git — user does NOT need to commit to roll back. [evidence/cursor.md §21, citing https://cursor.com/docs/agent (RSC payload)]
- **Queue follow-up messages** lets the user redirect without aborting. [evidence/cursor.md §21]
- **Team Rules**: enforced rules "cannot be disabled in Customize" — admin-level trust for organizations. [evidence/cursor.md §21]
- **Explainability**: "Plan Mode is the primary explainability mechanism: the agent writes a plan first, the user can edit it, then build. 'Most new features at Cursor now begin with Agent writing a plan.'" No "why did the agent do X" introspection panel documented. [evidence/cursor.md §22]

### Claude Code (subagents + agent teams + background agents)
- **Agent concept**: "Claude Code combines a model that reasons about your code with built-in tools for file operations, search, execution, and web access." [evidence/claude-code.md §8, citing https://docs.anthropic.com/en/docs/claude-code/features-overview]
- **Built-in tools**: Bash, Edit, Read, Glob, Grep, WebFetch. Tool restriction (`--tools "Bash,Edit,Read"`, `--tools ""`, `--tools "default"`). Tool filtering (`--allowedTools "Bash(git *) Edit"` / `--disallowedTools`). [evidence/claude-code.md §8]
- **Permission modes**: acceptEdits, auto, bypassPermissions, manual, dontAsk, plan. [evidence/claude-code.md §8, §21]
- **Subagents**: isolated execution context, returns summarized results. "Subagents are isolated workers that run separately from your main conversation." [evidence/claude-code.md §8]
- **Agent teams** (experimental): "Coordinate multiple independent Claude Code sessions with shared tasks and peer-to-peer messaging." [evidence/claude-code.md §8]
- **Background agents**: `--bg, --background` starts a session as background agent; managed with `claude agents`. Cloud agents: `--cloud [description|session_id|url]`. Custom agents: `--agents <json>` defines custom agents at launch (e.g., `{"reviewer": {"description": "Reviews code", "prompt": "You are a code reviewer"}}`). [evidence/claude-code.md §8]
- **Agent display in terminal**: text-based rendering. `--ax-screen-reader` for "flat text, no decorative borders or animations." [evidence/claude-code.md §8]
- **Effort levels**: low, medium, high, xhigh, max via `--effort <level>`. Model aliases: 'fable', 'opus', 'sonnet' or full names like 'claude-fable-5'. [evidence/claude-code.md §8]
- **Hooks**: lifecycle event triggers. PreToolUse, PostToolUse. "Put guardrails in hooks. An instruction like 'never edit .env' in CLAUDE.md or a skill is a request, not a guarantee. A PreToolUse hook that blocks the edit is enforcement." [evidence/claude-code.md §21]
- **Trust**: workspace trust dialog (skipped in non-interactive mode); `--allow-dangerously-skip-permissions`; Safe mode disables all customizations; `claude doctor`; Strict MCP (`--strict-mcp-config`); `--setting-sources user,project,local`. [evidence/claude-code.md §21]
- **Explainability**: Plan mode (`--permission-mode plan`); `/context`; `/memory`; tool calls visible in terminal output; `--verbose`; `-d, --debug [filter]` with category filtering. "No 'why did the agent do X' introspection panel documented (terminal-based, no GUI)." [evidence/claude-code.md §22]

### Codex (TUI agent loop + sandbox modes)
- **Agent loop is the agent**: "No separate 'Agent' panel — the TUI conversation IS the agent." Agent loop diagram: user input → model reasoning → tool actions → final response. [evidence/codex.md §8, citing https://openai.com/index/unrolling-the-codex-agent-loop (Wayback)]
- **Default tools**: shell tool, plan tool, web search tool (Responses API). Tool calls visible in conversation transcript. [evidence/codex.md §8]
- **`/status`** shows active model, approval policy, writable roots, current token usage. [evidence/codex.md §8]
- **Multiple agents**: Cloud supports parallel agents in different environments. `codex exec` for non-interactive runs. `codex review` for code review. `codex mcp-server` starts Codex as an MCP server (stdio). [evidence/codex.md §8]
- **Sandbox modes**: read-only, workspace-write, danger-full-access. OS-level enforcement: macOS Seatbelt policies + sandbox-exec; Linux Landlock + seccomp; Windows experimental. [evidence/codex.md §12, §21, citing security docs (Wayback)]
- **Approval modes**: Auto (preset), Read-only, untrusted, never, on-request. `--approve-for-me` routes approval requests through automatic review using the workspace-write sandbox. `--dangerously-bypass-approvals-and-sandbox` (alias: `--yolo`). `--dangerously-bypass-hook-trust`. [evidence/codex.md §12, §21]
- **Trust**: Default deny ("By default, the agent runs with network access turned off and can write only inside the current workspace"); `/approvals` slash command to switch modes mid-session; `/undo` to revert most recent turn; `/diff` to inspect changes before committing; version control recommendation ("Work on a feature branch and keep git status clean before delegating"); telemetry off by default (opt-in OTEL); prompt injection warning ("Use caution when enabling network access or web search in Codex. Prompt injection can cause the agent to fetch and follow untrusted instructions"); Codex cloud isolation ("isolated OpenAI-managed containers"). [evidence/codex.md §21]
- **Explainability**: `/status`; `/diff`; `/review` ("Run after Codex completes work or when you want a second set of eyes on local changes"); plan tool (built-in); audit log (`~/.codex/log/codex-tui.log` or session-*.jsonl); per-event OTEL categories (`codex.conversation_starts`, `codex.api_request`, `codex.sse_event`, `codex.user_prompt` (length; content redacted unless enabled), `codex.tool_*`). "No 'why did the agent do X' introspection panel documented." [evidence/codex.md §22]

### OpenHands (event-stream + TaskToolSet + SecurityAnalyzer)
- **Event-Stream Architecture (Appendix-Only Log)**: "The Event System provides an immutable, type-safe event framework that drives agent execution and state management. Events form an append-only log that serves as both the agent's memory and the integration point for auxiliary services." Four core responsibilities: Type Safety (Pydantic), LLM Integration, Append-Only Log, Service Integration. Event types: MessageEvent, ActionEvent (tool call with thought, reasoning, security risk), ObservationEvent, UserRejectObservation, AgentErrorEvent, SystemPromptEvent, CondensationSummaryEvent. Events split into LLM-Convertible (visible to the LLM) and Internal (NOT visible to the LLM). [evidence/openhands.md §8, §21]
- **Reasoning-Action Loop (Stateless)**: single-step execution model where each `step()` call processes one reasoning cycle. Steps: Pending Actions → Condensation → LLM Query → Response Parsing → Confirmation Check → Action Execution. Key characteristics: Stateless, Event-Driven, Interruptible (each step is atomic and can be paused/resumed). [evidence/openhands.md §8]
- **AgentDelegateAction → TaskToolSet** (V1): "lets a parent agent launch sub-agents that handle complex, multi-step tasks autonomously. Each sub-agent runs **synchronously** — the parent blocks until the sub-agent finishes and returns its result. Sub-agents can be **resumed** later using a task ID, preserving their full conversation context." Parallel delegation supported via `tool_concurrency_limit` (default 1; 2-8 moderate; >8 high parallelism). Verbatim: "the main agent has `tool_concurrency_limit=8`, allowing it to delegate to all three sub-agents simultaneously" + "Do NOT delegate one at a time - call all three delegate tools in a single response." File-Based Agents (Markdown files with YAML frontmatter). ACP Agent (Agent-Client Protocol): "Delegate to an ACP-compatible server (Claude Code, Gemini CLI, etc.) instead of calling an LLM directly." [evidence/openhands.md §8]
- **Confirmation Mode (WAITING_FOR_CONFIRMATION)**: three policies — AlwaysConfirm (require approval for all actions), NeverConfirm (execute all without approval), ConfirmRisky (only require approval for risky actions, requires security analyzer). User can reject with feedback: `conversation.reject_pending_actions("User rejected because actions seem too risky. Please try a safer approach.")` — agent gets feedback on why its action was rejected, enabling it to try a different approach. [evidence/openhands.md §21]
- **SecurityAnalyzer**: "Evaluates action risk before execution." Risk captured in ActionEvent itself. [evidence/openhands.md §21]
- **Hooks (Lifecycle Observability)**: PreToolUse (before tool execution, can block with exit 2), PostToolUse (after tool execution), UserPromptSubmit (before processing user message, can block), Stop (when agent tries to finish, can block), SessionStart, SessionEnd. Hooks match the Claude Code hook contract — exit code 0 = proceed, exit code 2 = block. [evidence/openhands.md §21]
- **Explainability**: architectural rather than operational. Every ActionEvent captures thought + reasoning + security risk. Every ObservationEvent captures the tool execution result. Append-only event log is canonical trace. **Observability & Tracing** via OpenTelemetry. **Metrics Tracking** — token usage, costs, latency. **Critic (Experimental)** — real-time evaluation of agent actions using an LLM-based critic model. **Iterative Refinement** — agents refine their work based on critique feedback until quality thresholds are met. "This is a stark contrast to Continue (no published trace) and Replit (operational work-log + video replay)." [evidence/openhands.md §22]

### LangGraph Studio (animated graph traversal + time travel)
- **Studio renders the compiled graph as a static diagram**, and during a run the active node is visually highlighted as the graph's execution pointer traverses the edges in real time. The slider at the top of the page controls the "super-step" granularity visible in the thread log; dragging it right exposes more granular detail (turns / nodes / state keys), dragging left collapses. Each node, when clicked, opens an **Inspect** panel showing its input state, output state, and any LLM/tool calls. "Crucially the agent graph is itself the navigation surface — you don't scroll a list of traces, you watch the agent *move* through its decision space." Streaming events are forwarded by the queue worker over SSE. Conditional edges during animation show as branch candidates so the developer can see *which* path was chosen and why. [evidence/langgraph-studio.md §8]
- **Time-travel via checkpoint history**: every checkpoint stores the full graph state after each super-step. `get_state_history(config)` returns this history in reverse chronological order. **Replay** re-executes nodes from a prior checkpoint — "Replay re-executes nodes—it doesn't just read from cache. LLM calls, API requests, and interrupts fire again and may return different results." **Fork** creates a new branch with modified state via `update_state` — "update_state does not roll back a thread. It creates a new checkpoint that branches from the specified point. The original execution history remains intact." **Subgraph time travel**: setting `checkpointer=True` on the subgraph gives it its own checkpoint history. Interrupts (HITL) are always re-triggered during time travel. UI affordances: **Edit node state** (JSON editor); **Fork** (new forked run); **Re-run from here** (new forked run without state edits). Per-node LLM calls can be opened in Playground with the full prompt context. [evidence/langgraph-studio.md §22]
- **Trust**: Local execution is a core trust signal — agent runs on `127.0.0.1:2024` (default bind); only the Studio UI is hosted at `smith.langchain.com`. Tracing is opt-out: "If you don't want data traced to LangSmith, set `LANGSMITH_TRACING=false`." Default `--host` is `127.0.0.1` for security; `0.0.0.0` is explicitly discouraged. Cloudflare `--tunnel` requires manual allow-listing of the tunnel URL in Studio's UI ("This manual step is required for security - Studio requires explicit user confirmation before connecting to external URLs."). [evidence/langgraph-studio.md §21]

### Dust (deep-dive agent + multi-agent observability)
- **Two complementary observability surfaces**:
  - **(a) Conversation-level "steering"**: every step (thinking blocks, tool calls, searches, file operations) appears live as it happens. "Every step now appears live in the conversation... instead of hiding behind a single activity indicator." Users can send messages mid-run; the agent finishes its current round of parallel actions then picks up the queued message with full context. Stop button keeps all completed work — "everything it's already done is kept. You only stop what comes next." [evidence/dust.md §8]
  - **(b) Workspace-level "Agent Builder Observability"**: announced in Product Update 19 (Dec 2025) — "Builder Observability lets you see exactly where they're crushing it (and where they're not)... which tools your agents use, when they use them, and how behavior shifts between versions. It allows you to see real usage patterns, identify bottlenecks, and iterate based on real behavior." Per-agent observability is materialised in **Workspace Analytics**: "Agents by credits: the top 100 agents by credits consumed, with their model, description, top users, and top skills... Skill usage: executions and unique users per skill over time... Tool usage: executions and unique users per tool over time." "This is genuinely differentiated — most agent platforms surface traces; Dust surfaces *aggregate agent behaviour* (which skills fired, which users, which tools, model drift over versions)." [evidence/dust.md §8, §22]
- **Sub-agent parallelism** (deep-dive): up to 6 concurrent @dust-task sub-agents, each with its own fresh context window. [evidence/dust.md §12]
- **Trust**: no model training ("Dust does not train any model or fine-tune any foundation model based on your conversations. Self-improving Skills only uses conversations to improve the instructions and configuration of your own skills"); data isolation ("There is no cross-workspace data sharing"); permissioned agents ("@deep-dive respects your workspace's access controls. It only accesses data you're authorized to see, operates under your identity when using tools with Personal authentication, and respects space-level and query-level permissions. Sub-agents inherit the same permissions"); audit logs; Trust Center; ZDR option ("Streaming mode (ZDR-eligible)"); privacy in analytics ("analytics and exports never include the content of messages. Only metadata such as timestamps, user and agent identifiers, conversation IDs, credit consumption, and the source of each message is captured"). [evidence/dust.md §21, §22]
- **Explainability**: @-mentions as citations to humans (when agent uses a fact, it includes citation link to underlying document; when it needs human input, it @-mentions a teammate — visible, accountable, audit-trail-forming); live step streaming; per-message detail panel ("Completed in N sec") showing which skills were loaded and which tool calls were made; per-agent observability; self-improving skills (nightly analysis surfaces evidence-based edit suggestions to skill builders with reasoning tied to specific feedback signals). [evidence/dust.md §22]

### Devin (parallel Devins + Managed Devins + ACU)
- **Async, multi-session, parallelizable**: "Spin up multiple parallel Devins, each equipped with its own interactive, cloud-based IDE. This means you can easily multitask, tackling numerous tasks concurrently and stepping in to steer when needed." [evidence/devin.md §8, citing https://cognition.ai/blog/devin-2]
- **Managed Devins**: "Devin can break down large tasks and delegate them to a team of managed Devin sessions, each running in its own isolated VM. The coordinator session scopes the work, monitors progress, resolves conflicts, and compiles results." [evidence/devin.md §8, citing https://docs.devin.ai/work-with-devin/advanced-capabilities.md]
- **Coordinator capabilities**: spin up child sessions, message them, monitor ACU (Agent Compute Unit) consumption, sleep/terminate, schedule messages to itself. [evidence/devin.md §8]
- **Computer Use**: Devin has full desktop control (mouse, keyboard, screenshots, any GUI app). [evidence/devin.md §8, citing https://docs.devin.ai/work-with-devin/computer-use.md]
- **Testing & video recordings**: "Devin tests your changes end-to-end and sends you video recordings as proof." [evidence/devin.md §8]
- **Handoff from CLI to cloud**: "Hand off a task from the Devin CLI to a cloud Devin session with `/handoff`" — also from Claude Code, Codex, or any coding agent. [evidence/devin.md §8, citing https://docs.devin.ai/work-with-devin/devin-handoff.md]
- **Trust**: Pull Requests as the trust boundary ("Devin is subject to the exact same branch protections and SDLC policies as any human engineer"); Devin Review (bug catcher labelled by confidence, security scanning with CWE classification, smart-diff organization); Auto-Fix automates review iteration but the human still merges; video recordings as proof; Progress tab transparency ("every shell command is logged and browsable"); Security posture (SOC 2, FedRAMP High In-Process, Customer Managed Keys AWS KMS, AI Guardrails prompt-injection screening, Attribution Filtering). [evidence/devin.md §21]
- **Explainability**: Plan step (Interactive Planning — Devin announces its plan before executing); Progress steps (each step is a discrete log entry with shell command, code edit, or browser action attached); Devin Review explanations ("precise explanations" for each diff hunk, "Checks for bugs and labels them by confidence level"); cited answers in Ask Devin and DeepWiki (links to source files / line ranges); bug catcher confidence levels ("Severe bugs require immediate attention"); CWE classification for security findings; Session Insights. [evidence/devin.md §22]
- **Long-session**: Parallel Devins + Kanban-style Agent Command Center (Devin Desktop); ACU consumption tracking per session and per organization; Sleep / wake (`sleep` Slack keyword pauses a session; any message wakes it); Scheduled Sessions for recurring work; Stacked PRs manage very large changes reviewably; Playbooks capture learnings from successful sessions for reuse; Auto-triage and Automations. [evidence/devin.md §23]

### Sweep (JetBrains agent + Next-Edit Autocomplete)
- **Sweep Agent** (⌘ J): "An integrated agent that automatically searches your codebase, edits your code, and then runs tests / checks for linter errors. ## 4. Observed Variations

Seven distinct agent-UX variations observed across the 11 products:

1. **CLI/TUI agent** (Claude Code, Codex) — terminal-native; no GUI; tool calls visible in transcript; slash commands for status/diff/review/undo; background agents via `--bg`; cloud agents via `--cloud`. Effort levels + permission modes are the primary autonomy dial.
2. **IDE-integrated agent** (Cursor, Sweep) — agent panel inside JetBrains/VS Code; plan-mode Markdown file; checkpoints separate from Git; accept/reject per applied code block (Sweep ⌘Y/⌘N).
3. **Synchronous chat-loop agent** (Replit Agent, Lovable, Bolt, v0) — agent runs in foreground; user sees task board / activity cards / live preview; Stop button halts; plan approval gate before execution.
4. **Live runtime motion agent** (Manus) — three execution environments (Sandbox / Desktop / Cloud Computer), each with a live pane showing the agent's actions. Plan Mode breaks execution into stages. Take Over flow for MFA/CAPTCHA handoff.
5. **Event-stream agent** (OpenHands) — append-only event log; ActionEvent + ObservationEvent pairs; LLM-Convertible vs Internal event split; stateless step() loop; TaskToolSet sub-agents with resume via task ID; ACP Agent can orchestrate Claude Code/Codex/Gemini as sub-agents.
6. **Animated graph traversal agent** (LangGraph Studio) — graph as navigation surface; per-node Inspect panel; slider for super-step granularity; time-travel via checkpoint history; Fork creates new branch without rollback.
7. **Durable multi-agent** (Dust, Devin) — Temporal workflows for durability (Dust); parallel Devins in isolated VMs (Devin); up to 6 concurrent @dust-task sub-agents (Dust); Managed Devins coordinator (Devin); per-agent observability (Dust Workspace Analytics).

An eighth hybrid — **autonomous cloud agent** (Cursor Cloud Agents, Manus Cloud Computer, Devin Managed Devins, GitHub Copilot cloud agent, Claude Code cloud agents, Codex Cloud) — runs in a cloud VM; user may close the client; results delivered via dashboard/PR/Slack.

A ninth — **PR-as-artefact agent** (Devin, Sweep) — agent's primary output is a Pull Request subject to existing branch protections; trust boundary is the existing code-review process.

## 6. Anti-Patterns (which FAIL and WHY — evidence-based)

**Cursor's missing introspection panel.** Anti-pattern: "No 'why did the agent do X' introspection panel documented" [evidence/cursor.md §22]. Same finding in Codex (§22) and Claude Code (§22). Once execution begins, the user cannot ask "why did you do that?" mid-run. This violates Amershi et al. 2019 G11 ("Make clear why the system did what it did") [academic/human-ai-interaction.md §4] and risks Palod et al. 2026's false-trust failure mode — users accept agent actions without verifying [academic/trust-in-ai.md §4]. By contrast, OpenHands's event-stream and LangGraph's per-node Inspect panel satisfy G11.

**Codex `--yolo` flag as documented escape hatch.** Anti-pattern: `--dangerously-bypass-approvals-and-sandbox` (alias: `--yolo`) is documented [evidence/codex.md §12, §21, citing security docs]. Documenting a "yolo" flag invites misuse — Parasuraman & Riley (1997) automation abuse category [academic/trust-in-ai.md §4]. While sandbox modes are progressive (read-only → workspace-write → danger-full-access), the documented `--yolo` shortcut normalises the most dangerous mode. Same pattern in Claude Code (`--dangerously-skip-permissions`).

**Manus per-command approval fatigue.** Anti-pattern: "Every command that Manus attempts to execute on your local machine requires your explicit approval. You will be prompted to Allow Once for a single operation or Always Allow for a trusted, recurring task. You are always in command." [evidence/manus.md §21, citing https://manus.im/docs/features/desktop]. While approval gates are good (Amershi et al. G16), per-command approval fatigue leads to either (a) user disengagement (clicking "Always Allow" without reading) or (b) abandonment of Desktop mode. This is the *over-correction* of trust calibration — Parasuraman & Riley's "disuse" failure mode.

**Sweep's lack of parallel-agent orchestration.** Anti-pattern: "No documented cross-session chat history, no org-level knowledge base, no parallel-agent orchestration. (Gaps vs Devin.)" [evidence/sweep.md §23]. Sweep is single-agent only; users with multi-task workflows must run multiple Sweep instances manually. Compared to Devin's parallel Devins + Managed Devins + Agent Command Center, Sweep is structurally limited.

**Cursor evidence reliance on RSC payload + forum.** Observation: multiple Cursor agent-UX claims cite "https://cursor.com/docs/agent (RSC payload)" or "https://forum.cursor.com/t/understanding-cursors-ai-feature/7204" [evidence/cursor.md §8, §21]. RSC (React Server Components) payloads are JSON, not human-readable docs; forum posts are community-sourced. This is an evidence-quality concern rather than an agent-UX anti-pattern, but it limits confidence in Cursor-specific agent-UX claims.

**Claude Code's terminal-only rendering excludes GUI users.** Anti-pattern: "Agent display in terminal: text-based rendering. `--ax-screen-reader` for 'flat text, no decorative borders or animations.'" [evidence/claude-code.md §8]. "No 'why did the agent do X' introspection panel documented (terminal-based, no GUI)" [evidence/claude-code.md §22]. The CLI execution UX is power-user-optimised; users without terminal fluency cannot effectively supervise long-running agent execution. Accessibility: `--ax-screen-reader` is a positive affordance for screen-reader users but the broader UX assumes terminal literacy.

**Replit's Begin take over 10-minute timeout.** Observation: "If you do not respond within 10 minutes, the Agent will continue as if you pressed 'Skip.'" [evidence/replit.md §8]. This is a sensible default (prevents indefinite hang) but may lead to silent failures if the user misses the notification. No documented mechanism for escalating or replaying the take-over opportunity.

**Sweep Bash tool IntelliJ version dependency.** Observation: "The bash tool functionality in Sweep depends on your IntelliJ IDE version and terminal engine configuration: IntelliJ IDE version 2025.2+ (Reworked Terminal ✅ / Classic Terminal ✅); 2025.1 and below (Reworked Terminal ❌ / Classic Terminal ✅)." [evidence/sweep.md §8]. The agent's capabilities are gated by the host IDE version — a coupling that creates silent capability regression when users don't upgrade.

## 7. Cognitive Load Implications (cite CLT)

**CLT source**: Sweller (1988); Sweller, Ayres & Kalyuga (2011); Chandler & Sweller (1991). [Source: academic/cognitive-load-theory.md §2, §4]

**Intrinsic load (IL)** in agent UX is determined by (a) the *number of agents the user must track simultaneously* (Devin parallel Devins; Dust 6 @dust-task sub-agents; Claude Code agent teams), (b) the *depth of the agent's reasoning chain* (multi-step plans > single-shot completions), (c) the *duration of the agent's run* (Gemini 5-10 min; Dust 5-20 min research phase; Devin long-running parallel sessions).

**Extraneous load (EL)** in agent UX comes from:
- **Multi-agent state tracking** — Dust's 6 concurrent sub-agents each with their own context window [evidence/dust.md §12] require the user to track 6 separate streams. Mitigated by Dust's per-agent Workspace Analytics aggregation.
- **Hidden reasoning** when the agent is opaque (Cursor/Codex/Claude Code no introspection panel — §6 anti-pattern) — the user mentally simulates the agent's reasoning, incurring EL.
- **Approval fatigue** (Manus per-command Allow Once / Always Allow) — repeated approval decisions deplete working memory and lead to disengagement.
- **Tool-call verbosity** — OpenHands's append-only event log is comprehensive but the user must filter; mitigated by LLM-Convertible vs Internal event split (only LLM-Convertible events appear in the conversation).
- **Plan-document complexity** — Manus/Cursor/Lovable/Bolt Plan Mode Markdown plans can be long; mitigated by inline-edit affordances that let users redline rather than rewrite.

**Germane load (GL)** is maximised when agent UX surfaces *structure*:
- LangGraph's graph-as-navigation surface teaches the user the agent's decision space — over time the user builds a schema of the graph topology.
- OpenHands's event-stream teaches the user the agent's reasoning chain — each ActionEvent captures thought + reasoning + security risk; over time the user internalises the action vocabulary.
- Manus's plan-then-execute lifecycle teaches the user what the agent will do before it does it — schema construction before observation.
- Devin's Playbooks capture learnings from successful sessions for reuse — schema externalisation.

**Expertise-reversal effect** (Kalyuga 2011; academic/cognitive-load-theory.md §4): expert developers benefit from CLI/TUI agent UX (Claude Code, Codex) because they can read tool-call transcripts natively; novice developers benefit from GUI agent UX (Lovable activity cards, v0 tool-execution cards, Manus live panes, Replit Board view). The 11 studied products span this expertise spectrum — CLI tools target experts; GUI tools target novices; hybrid tools span both.

**Chunking (Miller's Law 7±2)**: LangGraph's turn → node → key slider lets the user choose chunk granularity; Dust's per-message "Completed in N sec" detail panel is a single-chunk summary that expands to per-step detail; Lovable's activity cards are one chunk per action; Replit's task board chunks work into discrete task cards. All four are CLT-grounded chunking patterns. [academic/cognitive-load-theory.md §6 — "Chunking content: respects working memory limit (~4 chunks)"]

**arXiv:2607.19941 (Paimann et al. 2026)** lists "cognitive load" as one of eight core UX principles for human-AI agent interaction — directly inheriting CLT. [Source: academic/cognitive-load-theory.md §7, citing arXiv:2607.19941, accessed 2026-08-07]

## 8. Progressive Disclosure Relationship

**Academic grounding**: Nielsen (2006) PD criteria + Springer & Whittaker (2018, arXiv:1811.02164) on AI transparency. [Source: academic/progressive-disclosure.md §3, §4, §7]

**Manus Skills Progressive Disclosure (explicitly named)**: three levels — Level 1: Metadata (name + description) — loaded at startup — ~100 tokens/Skill; Level 2: Instructions (SKILL.md content) — loaded when triggered via slash command — <5k tokens; Level 3: Resources (scripts, reference files) — loaded on demand when referenced — consumed only when used. "This ensures that the agent only loads the information it needs, when it needs it, preserving the valuable context window." [evidence/manus.md §18, citing https://manus.im/docs/features/skills] — the cleanest realisation of PD in agent UX across the studied products.

**Claude Code layered extensions** (recommended order): (1) CLAUDE.md (always-on context); (2) Skills (on-demand invocable); (3) Code intelligence plugin (always-on LSP); (4) MCP (external services); (5) Subagents (isolated workers); (6) Agent teams (multi-session coordination, experimental); (7) Hooks (event automation); (8) Plugins (packaging + distribution). "Build your setup over time: You don't need to configure everything up front." Triggers listed ("Claude gets a convention or command wrong twice → Add it to CLAUDE.md"). [evidence/claude-code.md §18, citing https://docs.anthropic.com/en/docs/claude-code/features-overview]

**Codex progressive disclosure**: On launch, Codex detects whether the folder is version-controlled and recommends: version-controlled folders: Auto (workspace write + on-request approvals); non-version-controlled folders: read-only. Slash commands as progressive disclosure. Approval modes from strict to loose: read-only → untrusted → on-request → never. Configuration layering: `~/.codex/config.toml` (base) → `<name>.config.toml` (profile) → `-c` overrides (CLI). [evidence/codex.md §18]

**Cursor layered reveal**: User starts with Cmd-K (simplest). Cmd-L chat is one level up. Cmd-I Composer is multi-file. Plan Mode is full-agent. Cloud Agents are remote autonomous. [evidence/cursor.md §18]

**Devin layered**: Default = a session is a chat box + progress steps; advanced tools (Computer Use, Managed Devins, Security Swarm, DeepWiki MCP, Playbooks) not surfaced unless invoked. Slash commands typing `/` reveals dropdown menu; commands expand into prompt templates on selection. Explore Advanced Capabilities page provides ready-made prompt templates. Devin CLI: only essential commands surfaced by default. Pricing transparency is a separate page. [evidence/devin.md §18]

**Sweep layered**: Default = autocomplete is on; agent sidebar is hidden until ⌘ J. Inline Edit (⌘ I) appears only when a selection is active. AI Code Review invoked via JetBrains search menu (shift-shift → "AI Code Review") — deliberately out of the way until needed. AI Commit Messages appear automatically when the Commit window opens with an empty message field. MCP Servers, JetBrains Gateway, Custom Prompts, BYOK under "Advanced" in docs nav. [evidence/sweep.md §18]

**LangGraph Studio layered**: Thread log: **turn → node → key**, all collapse/expand. Slider sets the global expansion threshold. Pretty vs JSON mode is a per-step toggle. Per-node: clicking a node shows its state diff; clicking **View LLM Runs** opens the LLM call list; clicking an LLM call opens it in Playground. The **Edit node state** modal opens JSON editor; **Fork** is the destructive-but-safe action. "This layering — Overview → Node → LLM call → Prompt — is the canonical LangGraph progressive-disclosure stack." [evidence/langgraph-studio.md §18]

**Dust layered**: (1) conversation message → (2) "Completed in N sec" details panel → (3) per-step tool call inspection → (4) skill usage summary at the bottom. Agent Builder: top-level tabs → per-tab advanced sub-sections. Skills dynamically load. [evidence/dust.md §18]

**Replit PD**: Default flow is "describe → agent builds" with no required config. Plan mode is OPT-IN (a separate mode toggle). Lite / Economy / Power modes default to Economy; Advanced settings (App Testing, High effort, Turbo) are hidden behind an "Advanced settings" expander. The task board is a separate view (Board view). Visual Editor (Design) is invoked only when the user clicks an element with the Edit tool. Voice Mode is one-way input. [evidence/replit.md §18]

**Academic warning (Palod et al. 2026)**: PD must not become "opacity theatre" — users must be able to drill down to verify. Cursor/Codex/Claude Code's missing introspection panel (§6 anti-pattern) is opacity theatre. By contrast, LangGraph's per-node LLM call Playground opening, OpenHands's event-stream, and Dust's per-message detail panel are verifiability affordances that prevent opacity theatre. [Source: academic/progressive-disclosure.md §7; academic/trust-in-ai.md §4]

**Springer & Whittaker (2018, arXiv:1811.02164)** finding supports Manus's Plan Mode opt-in ("Plan Mode is manual. It stays out of your way until you call it") and Sweep's hidden-by-default agent sidebar: "Initially *simplified* feedback that hides potential AI errors and helps users build working heuristics > always-on full transparency. Incremental (continuous) transparency feedback can be distracting and undermine simple heuristics — users retract positive evaluations after experience." [academic/progressive-disclosure.md §7]

## 9. Accessibility Considerations

**Claude Code** — explicit screen-reader affordance: `--ax-screen-reader` flag for "flat text, no decorative borders or animations" [evidence/claude-code.md §8]. The only studied product with a documented screen-reader-specific agent-UX mode.

**Cursor, Manus, OpenHands, LangGraph Studio, Dust, Devin, Sweep, GitHub Spark, Replit, Codex** — none document screen-reader-specific agent-UX affordances in the evidence files. *Insufficient evidence — pattern-wide gap noted.*

**Replit Voice Mode**: "Voice Mode turns your speech into text in the chat box. It does not read Agent's responses aloud" — i.e., voice is a one-way input affordance, not a fully voice-driven mode [evidence/replit.md §18]. This is a positive input-modality affordance but not a full accessibility surface.

**Manus Take Over flow** for MFA/CAPTCHA — accessibility affordance for users who cannot use voice-only verification; the human takes over the verification step [evidence/manus.md §8].

**Devin video recordings as proof** — visual artefact that supports review for users who cannot monitor live sessions [evidence/devin.md §21].

**Pattern-wide gap**: agent UX is heavily visual (Manus live panes, LangGraph animated graph, OpenHands event-stream visualisation, Replit Board view, Devin Agent Command Center Kanban). Users with visual impairments are poorly served by the visual-first agent-UX paradigm across all studied products except Claude Code's `--ax-screen-reader` flag. This is a significant pattern-wide accessibility gap.

**Pattern-wide gap #2**: agent approval gates (Manus Allow Once / Always Allow, Codex approval modes, OpenHands Confirmation) require rapid visual interaction. No studied product documents non-visual approval affordances (e.g., audio cues, voice approval) for users with motor or visual impairments.

## 10. Performance Implications

**Agent-UX latency buckets** (Dust's documented buckets): simple questions under a minute; deep dive planning 30s–2min; research phase 5–20min; synthesis 1–3min [evidence/dust.md §12]. These buckets define the UX latency budget for each agent type.

**Gemini Deep Research** (5-10 min runtime): mitigated by async continuation — "While you wait for you can leave the chat. When it's ready, Gemini will notify you." [evidence/gemini.md §12].

**Manus Cloud Computer** (always-on, persistent file system): "A Cloud Computer gives you two things your laptop can't: It never turns off … Your files and setup stay put." [evidence/manus.md §12]. **Implication**: cloud agent UX removes the boot/perf cost; user sees only the live motion.

**Dust Temporal workflows** (durable): "work can survive deployments and infrastructure issues without losing progress" [evidence/dust.md §12]. **Implication**: agent UX must handle *resumption* — when an agent resumes after infrastructure failure, the user must see the prior state restored.

**OpenHands tool_concurrency_limit** (default 1, moderate 2-8, high >8): parallel tool execution increases throughput but raises cognitive load (§7). [evidence/openhands.md §8, §12]

**LangGraph per-node timings** (inline display): Studio shows per-node timings inline (token/latency metrics from LangSmith integration). [evidence/langgraph-studio.md §12]. **Implication**: per-node latency visibility is the developer-facing perf surface.

**Devin ACU (Agent Compute Unit)**: consumption tracked per session and per organization; users monitor ACU spend over time. [evidence/devin.md §8, §23]

**Replit parallel background tasks**: "Core runs 1 background task at a time, while Pro supports up to 10 concurrent background tasks". [evidence/replit.md §8]

**GitHub Spark Fleet Mode** (parallel agents): exposed as SDK capability. [evidence/github-spark.md §8]

**Cursor Cloud Agents**: "Cursor manages VM provisioning, isolation, snapshots, startup, artifacts, and capacity." [evidence/cursor.md §21, citing https://cursor.com/docs/background-agent (RSC payload)]

**Synthesised finding**: agent-UX performance perception correlates with (a) async continuation for >2min runs (Gemini, Manus Cloud Computer, Cursor Cloud Agents, Devin, Dust durable agents); (b) cloud always-on execution (Manus Cloud Computer; Devin Managed Devins); (c) per-node/per-step latency visibility (LangGraph Studio, OpenHands Metrics Tracking, Dust Workspace Analytics); (d) explicit parallelism limits (Replit 1 vs 10; OpenHands tool_concurrency_limit; Dust 6 @dust-task).

## 11. Long-Session Impact

**Devin long-running parallel Devins**: Parallel Devins + Kanban-style Agent Command Center (Devin Desktop); ACU consumption tracking per session and per organization; Sleep / wake (`sleep` Slack keyword pauses a session; any message wakes it); Scheduled Sessions for recurring work; Stacked PRs manage very large changes reviewably; Playbooks capture learnings from successful sessions for reuse; Auto-triage and Automations. [evidence/devin.md §23]

**Dust long-running durable agents** (Sep 2025 changelog): Temporal workflows survive deployments and infrastructure issues. Tool output pruning ("Amnesia" prevention) keeps context manageable across long sessions. [evidence/dust.md §12]

**Manus Cloud Computer** (always-on): persistent file system across sessions. [evidence/manus.md §12]

**OpenHands stateless step() loop**: stateless (no mutable state between steps), event-driven (reads from event history, writes new events), interruptible (each step is atomic and can be paused/resumed). [evidence/openhands.md §8]. **Implication**: long sessions are inherently resumable because state is in the event log, not in memory.

**Claude Code background agents** (`--bg`): runs session in background; managed with `claude agents`. Cloud agents (`--cloud [description|session_id|url]`) provide async continuation. Worktrees + tmux for parallel long-running sessions. [evidence/claude-code.md §12, §8]

**Cursor Cloud Agents**: "can build, test, and interact with the changed software." Cloud Agents dashboard shows environment, version history. [evidence/cursor.md §8, §12]

**Replit long-session**: Background tasks; Message Queue for queued follow-up messages; Follow-up tasks (Agent suggests next tasks at the end of a run); Task lifecycle (Draft → Active → Queued → Ready → Applying → Done, with Archiving and Cancelling); Cost monitoring via Managing Your Spend. [evidence/replit.md §23]

**GitHub Spark long-session**: Session Persistence and Session limits are explicit SDK capabilities. "Copilot Memory → Manage for yourself / Manage as administrator" implies persistent memory across sessions. [evidence/github-spark.md §23]

**Sweep long-session**: "One chat per task" is the explicit recommendation — long sessions hurt model intelligence. Edit your previous message to redirect Sweep rather than stacking follow-ups. Checkpoints + Revert Changes. AI Commit Messages with "learn from your last 10 commits". SWEEP.md / CLAUDE.md project-level instructions persist across sessions. "No documented cross-session chat history, no org-level knowledge base, no parallel-agent orchestration." [evidence/sweep.md §23]

**Pattern-wide observation**: long-session agent-UX quality correlates with (a) durable workflow infrastructure (Dust Temporal; OpenHands event-stream; Devin ACU tracking), (b) cloud always-on execution (Manus Cloud Computer; Devin Managed Devins; Cursor Cloud Agents; GitHub Copilot cloud agent; Claude Code `--cloud`), (c) explicit session lifecycle policy (Replit task lifecycle; OpenHands stateless step(); Devin sleep/wake), (d) cost/ACU monitoring (Devin ACU; Replit Managing Your Spend; Manus credit system). Products without explicit long-session policies (Sweep) risk context overflow or context-loss between sessions.
