# Pattern: Navigation UX

> PAT-3. Evidence synthesis across 13 products (editors, launchers, project trackers, PKM, browsers, calendars, email, terminal). NO MiMo design. Pattern extraction only.

## 1. Pattern Definition

**Navigation UX** refers to the design of surfaces and affordances by which a user moves between locations, contexts, or objects within a product. Across the evidence set, the pattern exhibits six signature properties:

1. **Sidebar + Command Menu dual** — most products ship a persistent left sidebar for browse-mode navigation PLUS a Cmd-K command palette for search-mode navigation. Linear: "sidebar + command menu dual… ⌘K: universal navigation — fuzzy search issues, projects, views, settings, commands." Notion: "sidebar + breadcrumb + Cmd-K." [Source: evidence/linear.md §5; evidence/notion.md §5]
2. **Activity Bar (vertical icon strip)** — VS Code's canonical pattern: "vertical strip on the far left side of the workbench. It provides quick access to top-level views" — Explorer, Search, Source Control, Run & Debug, Extensions, plus extension-contributed views. Adopted by Linear/Notion as a denser sidebar variant. [Source: evidence/vscode.md §5, citing https://code.visualstudio.com/api/ux-guidelines/activity-bar]
3. **Breadcrumb + back/forward** — Notion: "Breadcrumb at top of every page: shows page hierarchy, click any ancestor to navigate up… Forward/back: Cmd+[ and Cmd+] for browser-style history." Anytype: "Back/Forward buttons — browser-style navigation." Arc: "back/forward buttons" in top bar. [Source: evidence/notion.md §5; evidence/anytype.md §5; evidence/arc.md §5]
4. **Graph view as navigational surface** — Obsidian: "force-directed network; homepage demo shows 'Graph of Writing is t…' as a navigational surface. 'Visualize the relationships between your notes. Find hidden patterns in your thinking through a visually engaging and interactive graph.'" Anytype: Graph view accessible from any Object via the "Graph icon that is located near the back and forward buttons." [Source: evidence/obsidian.md §5; evidence/anytype.md §5]
5. **Tabs (browser-like)** — Arc (Spaces = stacks of Pinned + Today + Unpinned tabs), Linear (multiple tabs ⌘T within desktop app), Anytype ("Open multiple Objects side by side in a tab bar"), Warp (terminal blocks + tabbed sessions). [Source: evidence/arc.md §5; evidence/linear.md §5; evidence/anytype.md §5; evidence/warp.md §5]
6. **Search-first vs. browse-first** — Raycast has NO sidebar, NO Activity Bar, NO breadcrumbs; "the entire navigation is the command palette itself." Mental model is "search-first, browse-second." Things3's Quick Find doubles as navigation. [Source: evidence/raycast.md §5; evidence/things3.md §5]

## 2. Why It Matters (with academic evidence)

Navigation UX matters because every navigation step is a working-memory tax — the user must hold their current goal while evaluating where to go next. CLT frames this as extraneous load: poor navigation imposes "search-for-relevant-info" cost that is "under designer control" and reducible. Sidebar + Cmd-K dual reduces this by providing two complementary foraging paths: browse (sidebar, high scent for known hierarchies) and search (Cmd-K, high scent for known targets). [Source: academic/cognitive-load-theory.md §30, citing Chandler & Sweller 1991 on the split-attention and search-for-relevant-info effects]

The pattern also operationalizes **information foraging theory** (Pirolli & Card, Xerox PARC): users follow "information scent" — perceptual cues (link text, descriptions, snippets) that suggest how promising a path is. They continue along a path while scent remains strong and switch when scent weakens. Strong navigation = strong scent. Nielsen (2004 Alertbox): "deceivingly strong information scent costs sales" — sidebar items with misleading labels create abandonment. [Source: academic/information-scent.md §7 + §56, citing https://en.wikipedia.org/wiki/Information_foraging]

The pattern aligns with **Nielsen Heuristic #6 (Recognition rather than recall)**: visible sidebar items, breadcrumbs, and tab labels let the user recognize their location rather than recall the path. Things3's `⌘1`–`⌘6` jump to Inbox/Today/Upcoming/Anytime/Someday/Logbook is recognition-over-recall in pure form. [Source: academic/recognition-vs-recall.md §61-83; academic/jakob-nielsen.md §61; evidence/things3.md §5]

Finally, the pattern aligns with **Norman's seven stages of action** — minimizing the Gulf of Execution (the gap between user's goal and the actions available) and the Gulf of Evaluation (the gap between system state and user's understanding). Cmd-K command menus narrow the Gulf of Execution (one keystroke to any action); breadcrumbs + sidebar narrow the Gulf of Evaluation (current location is always visible). [Source: academic/don-norman.md §7 + §40, citing https://jnd.org/the-design-of-everyday-things-revised-and-expanded/]

## 3. Evidence Across Products

- **vscode.md §5** — Activity Bar (leftmost vertical icon strip) is primary navigation between modes: Explorer, Search, Source Control, Run & Debug, Extensions, plus extension-contributed views (GitHub, Docker, Testing). Side Bar shows active view content. Panel (bottom) hosts Terminal/Output/Problems/Debug Console. Status Bar (bottom strip) shows branch, errors/warnings, language mode, line/col, encoding, indent. No Spaces concept — uses Multi-root Workspaces: "You can work with multiple project folders in VS Code with a feature called Multi-root Workspaces." Breadcrumbs show "current file location and the current cursor's symbol location." [Source: evidence/vscode.md §5, citing https://code.visualstudio.com/api/ux-guidelines/activity-bar + /docs/editing/userinterface + /docs/editor/workspaces]
- **raycast.md §5** — NO traditional sidebar, NO Activity Bar, NO breadcrumbs. "The entire navigation is the command palette itself." Root search: typing searches across all installed commands, extensions, applications, file paths, calculations, and clipboard history simultaneously. Root sections: top-level results grouped by type (Commands, Applications, File Search, Clipboard History, Quicklinks, AI Chat, Calculator). Store command: opens extension store inside Raycast. Navigation within a command: most commands render a list (Detail/Form/Grid views) with keyboard arrows + Enter. Mental model is **search-first, browse-second**. No hierarchical tree. [Source: evidence/raycast.md §5]
- **linear.md §5** — Sidebar + command menu dual. Left sidebar: Workspace switcher, Inbox, My Issues (Active/Backlog/Projects), Favorites, Workspace sections (Teams, Views, Roadmap, Initiatives). Collapsible with `⌘\` (similar to VS Code). Top tabs within a view: All / Active / Backlog / Projects. Breadcrumb at top of issue detail: Workspace → Team → Project → Issue. Command Menu (⌘K): universal navigation — fuzzy search issues, projects, views, settings, commands. Tabs (in-app): Linear supports multiple tabs (⌘T) within desktop app — like a browser. Sidebar is **dense but disciplined** — fewer top-level items than Notion, more than VS Code's Activity Bar. [Source: evidence/linear.md §5]
- **notion.md §5** — Sidebar + breadcrumb + Cmd-K. Sidebar (left, ~260px): top-level tabs — Home, Chats with Notion AI, Meetings, Inbox, Library. Plus workspace-level: Favorites, Recents, Teamspaces, Shared, Private. Workspace switcher at top-left: switch workspaces, log out, settings. Search (top of sidebar or Cmd-K): "jump to a recently viewed page" or "type what you're looking for." Breadcrumb at top of every page: shows page hierarchy, click any ancestor to navigate up. In-page navigation: `Cmd+Shift+U` to go up one level. Forward/back: Cmd+[ and Cmd+] for browser-style history. Database peek view: navigate between database entries with Ctrl+Shift+K (prev) / Ctrl+Shift+J (next) on Mac. Sidebar is **more complex** than Linear's — five top-level tabs plus per-tab sections. Reflects "everything workspace" positioning. [Source: evidence/notion.md §5, citing notion-help-sidebar.html + notion-keyboard.html]
- **arc.md §5** — Sidebar-centric. Left sidebar (vertical, ~280px): Spaces (each is a stack of Pinned + Today + Unpinned tabs). Click a Space to switch. Sidebar item types: Pinned tabs (icon-only by default, favicon), Today tabs (favicon + title), folders of Pinned tabs (collapsible), Notes, Easels (visual canvas). Top of sidebar: profile switcher, New Tab button. Bottom of sidebar: Command Bar hint, Settings, Library (archives). Top bar (when tab active): back/forward buttons, URL bar (auto-hides when not focused — Arc's "clean" principle), sidebar toggle, split view toggle. Command Bar (Cmd-T): universal fuzzy search — URLs, history, bookmarks, Arc commands. Replaces URL bar for most navigation. Sidebar toggle (Cmd+S): hide/show sidebar for full-screen browsing. Profile switcher: separate cookie jars per profile within a Space. [Source: evidence/arc.md §5]
- **obsidian.md §5** — File explorer (left-sidebar tree of vault folder). Graph view: force-directed network; "Visualize the relationships between your notes. Find hidden patterns in your thinking through a visually engaging and interactive graph." Wikilinks `[[Note]]` and tags `#tag` form the implicit namespace. Backlinks appear inline (demo note shows "1 backlink"). Canvas files use open JSON Canvas format designed by Obsidian (https://jsoncanvas.org). CLI navigation commands: `obsidian daily`, `obsidian search query="…"`, `obsidian read`, `obsidian files sort=modified`. Help site itself is published via Obsidian Publish at https://obsidian.md/help/ — itself a working example of Obsidian's navigation. [Source: evidence/obsidian.md §5, citing https://obsidian.md/ + /canvas/ + /cli]
- **heptabase.md §5** — Left Sidebar = "Tabs and bookmarks of the browser." Right Sidebar = "Plugins of the browser." Global Tool = "Search tool of the browser." No file tree (cards live in Card Library; whiteboards are first-class objects); navigation is browser-like. Sub-whiteboards allow nesting. Whiteboard toolbar (left-side): Select, Note card, Upload files, Connect (arrows), Text, Section, Search, Journal, Calendar, Mindmap, sub-whiteboard, whiteboard shortcut. [Source: evidence/heptabase.md §5, citing https://wiki.heptabase.com/getting-started-with-heptabase + /fundamental-elements]
- **tana.md §5** — No file tree. Navigation is **graph-based**: nodes link to nodes via references; daily notes are the entry point; search nodes act as saved queries. Workspace switching: "Option (Mac) or Alt (Windows) while clicking on a workspace to open its day node for today." Sidebar pattern: "pin your own sidebar," "Tasks view groups and filters your work into bookmarkable slices," "new search popover gets you to anything in Tana from wherever you are" (Jun 11, 2026 blog). [Source: evidence/tana.md §5, citing https://tana.inc/outliner-pkm + /search-nodes + /daily-notes + /blog]
- **anytype.md §5** — Sidebar (Channel Sidebar) is the primary navigation hub. Contains: Create button + dropdown, Types section, Queries, Collections, Bin, Graph. Customizable via "Sections" and "Widgets." Search palette: `Cmd/Ctrl + K` ("Quickly find what you're looking for"). Docs explicitly recommend memorizing "Cmd/Ctrl + K (search), `/` (slash menu), and `@` (mention) cover most of what you do." Graph view: visual node-and-edge graph of all Objects and their Links, accessible from any Object via the "Graph icon that is located near the back and forward buttons." Tabs: "Open multiple Objects side by side in a tab bar." Back/Forward buttons (browser-style). Sidebar Widgets: pinned Queries or Views in sidebar for immediate access. No documented "home" page — the Sidebar is the home. [Source: evidence/anytype.md §5, citing https://doc.anytype.io/anytype/basics/sidebar.md + /settings/keyboard-shortcuts.md + /create/objects.md + /features/tabs.md + /basics/sidebar/widgets.md]
- **things3.md §5** — Sidebar + Quick Find + Type Travel. `⌘1`–`⌘6` jump to Inbox, Today, Upcoming, Anytime, Someday, Logbook respectively. `⌘ /` toggles sidebar visibility. `⇧⌘O` opens a navigation popover. `⌘ L` shows the selected item in its parent list. `Return` or `⌘ →` enters a selected project; `⌘ ←` goes back. Quick Find doubles as navigation: "Navigating via Quick Find works the same as initiating a search. Instead of entering a search term, you type the name of your destination... Type 'tod…' to jump to the Today list. Type 'finan…' to jump to the Finances area." Special lists accessible only through Quick Find: Tomorrow, Deadlines, Repeating, All Projects, Logged Projects. Multiple windows supported on Mac (and iPadOS 26): `^⌘N` new window, `⌘ Return` or `⌘ + click` from Quick Find in new window. [Source: evidence/things3.md §5, citing https://culturedcode.com/things/support/articles/2785159/ + /articles/2803584/]
- **amie.md §5** — Sidebar groups AI Notes (formerly part of calendar+todos UI) into a dedicated place. Per changelog #117 (Feb 2025): "for todos + cal nothing really changes. ai notes (in sidebar) have gotten so damn powerful. so we gave them their dedicated place." Calendar navigation: multi-account (Google, Outlook, Apple) calendars, availability across all enabled calendars in one view. Menu-bar calendar on Pro plan. Hotkey 'p' toggles event privacy. Search within transcript is `⌘+F` (changelog #119, April 29, 2025). [Source: evidence/amie.md §5, citing https://amie.so/changelog + /pricing]
- **superhuman.md §5** — Mail navigation centers on Split Inbox with multiple priority-based tabs. From homepage demo: "Important 12 / Calendar 13 / Docs 8 / Other 19" — visible tab labels with email counts. Custom Auto Labels can become tabs: "split your inbox into tabs using these custom Auto Labels. So even when your inbox is overflowing, you can focus on a specific topic — and get through emails of the same type, at the same time." Calendar visible without losing flow: "Whenever you suggest a date, we'll show your calendar for that day. Looking busy? Just hit a shortcut, and we'll show the next day. We'll even update your email automatically." A full keyboard-shortcuts page on help.superhuman.com was attempted but returned 404/Cloudflare challenge. Marketing homepage shows chat-style left nav: products (Go, Mail, Calendar, Docs, Databases) at the top, solutions, AI (Agents, Grammarly, Agent Store, Connections), resources. [Source: evidence/superhuman.md §5, citing https://superhuman.com + /ai + /products/mail]
- **warp.md §5** — Terminal keyboard navigation: "Command Search or Workflow Search CTRL-SHIFT-R" opens the workflows/command search panel. Warp Drive navigation panel toggle: "CTRL-SHIFT-\\" switches the Warp Drive side panel. Warp Drive keyboard navigation: "Press UP / DOWN or j / k to navigate to the object you want. Press Enter to (1) execute an object, (2) open/collapse a workspace or folder, or (3) open the trash. Press CMD-ENTER [Mac] / CTRL-ENTER [Windows/Linux] to open an object's context menu. Press CMD-SHIFT-( and CMD-SHIFT-) to switch focus between the terminal and Warp Drive. Press LEFT-ARROW to collapse a workspace or folder. Press RIGHT-ARROW to open a workspace or folder. Press Esc to return to Warp Drive from your trash." Command Palette also exposes "Switch Focus to Left Panel" and "Switch Focus to Right Panel" commands. [Source: evidence/warp.md §5, citing https://docs.warp.dev/terminal/entry/yaml-workflows/ + /knowledge-and-collaboration/warp-drive-overview/]

## 4. Observed Variations

- **Activity Bar density**: VS Code ~6 top-level icons; Linear denser (Inbox/My Issues/Favorites/Teams/Views/Roadmap/Initiatives); Notion densest (5 top-level tabs × multiple sections per tab); Arc Sidebar = Spaces (much smaller unit — Space = cookie jar + tab stack). [Source: evidence/vscode.md §5; evidence/linear.md §5; evidence/notion.md §5; evidence/arc.md §5]
- **Search-first vs. browse-first**: Raycast (search-first, no sidebar), Things3 (Quick Find doubles as navigation), Warp (Command Palette exposes Switch Focus commands) lean search-first. Linear/Notion/Arc/Anytype lean browse-first with search as accelerator. [Source: evidence/raycast.md §5; evidence/things3.md §5; evidence/warp.md §5; evidence/linear.md §5; evidence/notion.md §5; evidence/arc.md §5; evidence/anytype.md §5]
- **Graph-as-navigation vs. tree-as-navigation**: Obsidian and Anytype ship Graph view as a primary navigational surface. Heptabase uses whiteboard spatial arrangement (the whiteboard IS the navigation; sub-whiteboards nest). Tana has no file tree — "navigation is graph-based: nodes link to nodes via references." VS Code/Linear/Notion use traditional tree/hierarchy. [Source: evidence/obsidian.md §5; evidence/anytype.md §5; evidence/heptabase.md §5; evidence/tana.md §5; evidence/vscode.md §5; evidence/linear.md §5; evidence/notion.md §5]
- **Tabs at different granularities**: Arc (tabs are first-class — Pinned/Today/Unpinned within each Space), Linear (⌘T in-app tabs browser-like), Anytype (multiple Objects side by side in tab bar), Warp (terminal sessions as tabs). VS Code has editor tabs (per file) but no Spaces concept — uses Multi-root Workspaces instead. [Source: evidence/arc.md §5; evidence/linear.md §5; evidence/anytype.md §5; evidence/warp.md §5; evidence/vscode.md §5]
- **Browser-style back/forward**: Notion (Cmd+[ / Cmd+]), Anytype (back/forward buttons), Arc (back/forward in top bar) — all three adopt browser history semantics. Things3 uses `⌘ ←` for back. [Source: evidence/notion.md §5; evidence/anytype.md §5; evidence/arc.md §5; evidence/things3.md §5]
- **Workspace/Space/Profile switching**: Arc Spaces (separate cookie jars per profile within a Space), Linear Workspace switcher (top-left), Notion Workspace switcher (top-left — switch, log out, settings), Tana Option/Alt+click workspace to open day node, VS Code Multi-root Workspaces (no Spaces concept). [Source: evidence/arc.md §5; evidence/linear.md §5; evidence/notion.md §5; evidence/tana.md §5; evidence/vscode.md §5]
- **CLI navigation**: Obsidian CLI (`obsidian daily`, `obsidian search`, `obsidian read`, `obsidian files sort=modified`) is unique in exposing navigation as a scriptable surface. Warp exposes terminal keyboard navigation. Others are GUI-only. [Source: evidence/obsidian.md §5; evidence/warp.md §5]
- **Sidebar-as-home vs. no-home**: Anytype explicitly: "There is no documented 'home' page — the Sidebar is the home." Contrast with Notion (Home is a top-level tab) or Things3 (Today is the default landing list). [Source: evidence/anytype.md §5; evidence/notion.md §5; evidence/things3.md §5]
- **Numbered-tab jumping**: Things3 `⌘1`–`⌘6` jump to Inbox/Today/Upcoming/Anytime/Someday/Logbook — the cleanest recognition-over-recall shortcut in the set. Linear cmd+number switches tabs. [Source: evidence/things3.md §5; evidence/linear.md §23]

## 5. Premium Exemplars (BEST + WHY — evidence-based)

**BEST (command palette + sidebar dual): Linear** — because the sidebar is "dense but disciplined — fewer top-level items than Notion, more than VS Code's Activity Bar," the Cmd-K command menu is universal (fuzzy search issues, projects, views, settings, commands), tabs are browser-like (⌘T), the breadcrumb at issue detail (Workspace → Team → Project → Issue) gives location context, `⌘\` collapses sidebar for focus mode. Local-first architecture means 1-hour sessions don't degrade. Inbox Zero workflow for triage. cmd+number to switch tabs. This is the canonical implementation of the dual-mode pattern. [Source: evidence/linear.md §5 + §23]

**BEST (search-first navigation): Raycast** — because "the entire navigation is the command palette itself" with NO sidebar/Activity Bar/breadcrumbs to compete for attention. Root search types across all installed commands, extensions, applications, file paths, calculations, and clipboard history simultaneously. Root sections group results by type (Commands/Applications/File Search/Clipboard History/Quicklinks/AI Chat/Calculator). Navigation within a command uses keyboard arrows + Enter. Memory stays ~150MB (vs. VS Code's 1-2GB Extension Host). "Architected against session fatigue — because each invocation is short and independent." This is the cleanest information-foraging implementation: every cue is scent, no tree to traverse. [Source: evidence/raycast.md §5 + §23]

**BEST (graph-as-navigation): Anytype** — because the Graph view is accessible from any Object via the "Graph icon that is located near the back and forward buttons" (giving graph + browser-style navigation in one toolbar), the Sidebar (Channel Sidebar) is customizable via "Sections" and "Widgets" (pinned Queries/Views for one-click access), `Cmd/Ctrl + K` search palette + `/` slash menu + `@` mention cover most operations, Tabs allow multiple Objects side by side. The typed-relational schema means the Graph is semantically rich (typed Links between Objects), not just `[[page]]` links. [Source: evidence/anytype.md §5 + §10, citing https://doc.anytype.io/anytype/basics/sidebar.md + /create/objects.md + /features/tabs.md]

**BEST (recognition-over-recall shortcuts): Things3** — because `⌘1`–`⌘6` jump to Inbox/Today/Upcoming/Anytime/Someday/Logbook maps spatial/numeric key positions to temporal life categories (Inbox=now, Today=now, Upcoming=soon, Anytime=ongoing, Someday=later, Logbook=past). Quick Find doubles as navigation. Special lists (Tomorrow, Deadlines, Repeating, All Projects, Logged Projects) accessible only through Quick Find — surfacing niche navigation through search. Magic Plus button is "the universal artifact-creation primitive." Calm visual design: "Things never feels messy or overbearing, no matter the length of your task list." [Source: evidence/things3.md §5 + §13 + §23, citing https://culturedcode.com/things/features/ + /support/articles/2785159/ + /things/guide/]

## 6. Anti-Patterns (FAIL + WHY — evidence-based)

- **Notion's sidebar complexity** — five top-level tabs (Home, Chats with Notion AI, Meetings, Inbox, Library) plus workspace-level sections (Favorites, Recents, Teamspaces, Shared, Private). "Sidebar is more complex than Linear's — five top-level tabs plus per-tab sections. This reflects the 'everything workspace' positioning." Long sessions: "Sidebar grows — recently-viewed pages accumulate; can clutter sidebar." Violates Nielsen Heuristic #8 (aesthetic and minimalist design — only show what's needed). [Source: evidence/notion.md §5 + §23]
- **Notion long-page scroll lag** — "Long pages slow down — large pages with hundreds of blocks lag on scroll." This is a performance cliff that increases extraneous load (the user must wait for scroll to settle). Violates Heuristic #1 (visibility of system status — the system doesn't visibly respond). [Source: evidence/notion.md §23]
- **Arc sidebar congestion** — "Pinned tabs + folders can make the sidebar feel cramped." Today tabs accumulate to 20-30 before pressure to clean up. "Arc does not aggressively suspend background tabs (compare Chrome's Tab Groups + freezing)." Memory accumulation. [Source: evidence/arc.md §23]
- **Superhuman help-page 404** — "A full keyboard-shortcuts page on help.superhuman.com was attempted but the page returned 404 / Cloudflare challenge." Navigation documentation is itself unreachable — making the keyboard-first navigation model opaque to new users. Violates Heuristic #10 (help and documentation). [Source: evidence/superhuman.md §5]
- **VS Code tab overflow menu** — "VS Code shows a '…' overflow menu rather than scrolling" when dozens of editor tabs per group accumulate. The overflow menu is a recognition tax — the user must remember which tab is hidden. Violates Heuristic #6 (recognition rather than recall). [Source: evidence/vscode.md §23]
- **ChatGPT Canvas model-gating navigation break** — Canvas is unavailable with GPT-5 Pro / GPT-5.2 Pro. Users switching model variants silently lose the artifact surface with no inline explanation in the composer. The user's mental model of "Canvas is always there" is broken — a navigation cliff disguised as a feature gate. Violates Heuristic #2 (match between system and real world). [Source: evidence/chatgpt.md §13, citing https://help.openai.com/en/articles/11909943-gpt-5-in-chatgpt]
- **Cursor forum-recommended external scaffolding** — "Forum users on big projects explicitly recommend: '1. Create a PRD Document; 2. Establish Cursor Rules; 3. Create a Features Document; 4. Generate RFCs for Individual Features; 5. Implementation.'" This implies long sessions degrade without external navigation scaffolding — the in-product navigation is insufficient for big projects. [Source: evidence/cursor.md §23, citing https://forum.cursor.com/t/guide-how-to-handle-big-projects-with-cursor/70997]
- **Tana outliner fatigue** — "single-pane outliner paradigm (same as Roam/Logseq) can be exhausting after long sessions." No file tree means no spatial escape from linear traversal. Mitigations only partial. [Source: evidence/tana.md §265]

## 7. Cognitive Load Implications (cite CLT)

- **Extraneous load reduction via dual-mode navigation**: Linear's sidebar + Cmd-K dual gives the user two foraging paths — browse (high scent for known hierarchies, low working-memory cost) and search (high scent for known targets, requires query formulation). CLT segmentation principle: each mode is a low-element-interactivity surface; switching modes is a low-cost context switch. [Source: academic/cognitive-load-theory.md §51; evidence/linear.md §5]
- **Recognition-over-recall reduction**: Things3's `⌘1`–`⌘6` mapped shortcuts and Notion's breadcrumb at top of every page are pure recognition-over-recall — the user sees the location rather than recalling the path. Nielsen Heuristic #6. Reduces working-memory load (~4±1 chunks per Cowan 2001). [Source: academic/recognition-vs-recall.md §61-83; academic/cognitive-load-theory.md §1; evidence/things3.md §5; evidence/notion.md §5]
- **Split-attention risk in dense sidebars**: Notion's five-top-level-tab sidebar risks split-attention (CLT split-attention effect, Chandler & Sweller 1991) — the user must scan multiple sections to find the current location. Linear's "dense but disciplined" sidebar is the mitigation. [Source: academic/cognitive-load-theory.md §30; evidence/notion.md §5; evidence/linear.md §5]
- **Germane load via graph navigation**: Obsidian and Anytype's Graph view lets the user re-represent the same data spatially — schema-building through visualization is a germane-load-maximizing technique. The user forms mental models of relationships, not just lists. [Source: academic/cognitive-load-theory.md §40 — worked-example effect via re-representation; evidence/obsidian.md §5; evidence/anytype.md §5]
- **Information foraging cost (Pirolli & Card)**: Strong information scent reduces foraging cost. Sidebar items with misleading labels create abandonment (Nielsen 2004 "deceivingly strong information scent costs sales"). Raycast's root-section grouping by type (Commands/Applications/File Search/Clipboard History/Quicklinks/AI Chat/Calculator) provides the strongest scent in the set — every result is labeled by type. [Source: academic/information-scent.md §7 + §56; evidence/raycast.md §5]
- **Expertise-reversal risk for Cmd-K**: Novices may not know what to search for; experts reach for Cmd-K instinctively ("Command menu muscle memory kicks in" — Linear). Things3's Quick Find (search-as-navigation) mitigates by accepting partial input ("tod…" → Today). [Source: academic/cognitive-load-theory.md §44 — expertise-reversal; evidence/linear.md §23; evidence/things3.md §5]

## 8. Progressive Disclosure Relationship

- **VS Code Activity Bar as primary disclosure level**: top-level modes (Explorer/Search/Source Control/Run & Debug/Extensions) are the first disclosure; the Side Bar shows the active view's content (second level); the Panel (bottom) hosts Terminal/Output/Problems/Debug Console (third level). Each level is independently toggleable. [Source: evidence/vscode.md §5]
- **Heptabase sub-whiteboards** as progressive disclosure by spatial nesting — zoom into a sub-topic without leaving the main whiteboard context. Sub-whiteboards are the disclosure primitive. [Source: evidence/heptabase.md §5 + §18]
- **Tana zoom-in** to a node (focus mode) is classic outliner progressive disclosure (matching Roam/Logseq). Tana's blog describes daily notes as entry points, search nodes as saved queries that surface only matching items — progressive disclosure by filter. [Source: evidence/tana.md §5 + §18]
- **Anytype content-driven disclosure**: Sidebar Sections — Types/Queries/Collections/Bin only reveal items that have content. "Only Types with at least one Object in them will display in this section." Toggled Headings collapse and expand sections of long Objects. Inline Queries — embedded live-filtered Views, only expanding when the user wants to see them. [Source: evidence/anytype.md §18]
- **Arc Spaces as disclosure level**: each Space is a separate cookie jar + tab stack — switching Spaces is a context switch (250ms animation). Within a Space, Pinned (icon-only by default, favicon) → Today tabs (favicon + title) → Unpinned is a 3-level disclosure by recency/persistence. [Source: evidence/arc.md §5]
- **Roam bottom-up by depth**: A page initially shows only its own block tree. "Linked References" panel reveals every page/block that links to it (collapsible). "Unlinked References" panel reveals text matches that could become links (collapsible, separately). Block-level disclosure: every block can be collapsed/expanded. `Cmd/Ctrl+Enter` on a block "zooms in" to show only its subtree. Right sidebar opens additional pages without navigating away. [Source: evidence/roam.md §18]

## 10. Performance Implications
