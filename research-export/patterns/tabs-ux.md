## 1. Pattern Definition

**Tabs UX** is the interaction pattern governing parallel-context management — the user's ability to have multiple distinct work contexts open simultaneously and switch between them. This includes: (a) **browser-like document tabs** (Arc, Notion, Linear, Craft, Heptabase, Obsidian, Anytype); (b) **IDE editor tab groups / split views** (VS Code, Cursor, JetBrains, Zed, Helix bufferline + window mode); (c) **multi-session AI conversations** (Codex `codex resume`/`fork`/`archive`, Claude Code `--session-id`/`--teleport`, Devin multi-surface, Sweep "one chat per task" `⌘N`); (d) **split views / panes** showing two tabs simultaneously (Arc Split View is itself a tab; VS Code editor groups; Helix vsplit/hsplit; Reflect split-pane; Obsidian split views); (e) **cloud workspace tabs** (Manus dedicated browser tab in tab group, Cursor Cloud Agent VMs, OpenHands Agent Canvas flipping between multiple Agent Servers); (f) **pop-out windows** (Notion New Window, Obsidian pop-out, Things3 multiple windows, Craft tab+window dual); and (g) **cross-surface continuity** (Apple Siri iPhone→iPad, MS Copilot multiple surfaces, Meta AI multi-DM reachability). Tabs are the *parallel-context primitive* that distinguishes multi-task workspaces from single-thread chat products. [Source: evidence/linear.md §5 + §6, citing Linear help docs; evidence/notion.md §5 + §6, citing notion-keyboard.html and notion-help-sidebar.html; evidence/arc.md §5 + §6, citing https://resources.arc.net/hc/en-us/articles/19335393146775-Split-View-View-Multiple-Tabs-at-Once; evidence/craft.md §5, citing introduction_shortcuts.md]

## 2. Why It Matters

Tabs UX addresses **Miller's Law** (Miller 1956, *Psychological Review* 63(2):81–97 — working memory capacity ~7±2 chunks; modernized to ~4±1 per Cowan 2001) [Source: academic/millers-law.md §1–4, citing Miller 1956 and Cowan 2001]. Without tabs, the user must hold all parallel contexts in working memory simultaneously — direct violation. Tabs externalize parallel contexts into a visible list (recognition) rather than forcing recall.

Amershi et al. (2019) G12 "Remember recent interactions" and G18 "Notify users about changes" apply: tabs are the visible surface of recent interaction state [Source: academic/human-ai-interaction.md §4]. When MS Copilot Teams "Copilot conversations close when the side panel closes" [Source: evidence/ms-copilot.md §7 cross-ref §6, citing `learn-m365-overview.txt`], G12 is violated — the tab/conversation state is destroyed.

Jakob Nielsen's Heuristic #6 "Recognition Rather than Recall" [Source: academic/recognition-vs-recall.md §1–3, citing Nielsen 1994 nngroup.com/articles/ten-usability-heuristics/] is the primary academic basis for tabs — they let the user *recognize* an open context (via title/favicon/preview) rather than *recall* it from a closed history list. v0's sidebar hover card "previews how a turn ended, such as its closing summary or the question it is waiting on" is the strongest documented implementation of tab-state recognition [Source: evidence/v0.md §5, citing https://v0.dev/changelog Jul 31 2026].

Shneiderman Golden Rule #7 "Support internal locus of control" requires that the user can always navigate/escape/close — tab close (Arc X, VS Code Cmd+W, Craft Cmd+W, Notion Cmd+W), tab reopen (Craft Cmd+Shift+T, Notion Cmd+Shift+T), and tab switching (Cmd+1–9, Ctrl+Tab) are direct implementations. Tab loss = control loss.

## 3. Evidence Across Products

### 3.1 Browser-like document tabs (knowledge products)
- **Notion**: Tabs (Cmd+T) — "Use cmd/ctrl + T to create a new Notion tab." Each tab navigates independently within the desktop app. New window (Cmd+Shift+N). Option+Shift+click opens page as new window. Cmd+click opens link as new Notion tab. **No native split-view** — "Notion does not natively support side-by-side page editing. Users work around this by opening multiple windows." [Source: evidence/notion.md §5 + §6, citing notion-keyboard.html and notion-help-sidebar.html]
- **Craft**: Tabs — `Cmd + T` (new tab), `Cmd + 1` through `Cmd + 9` (switch to tab N), `Ctrl + Tab` (next tab), `Cmd + Shift + T` (reopen last closed tab) [Source: introduction_shortcuts.md — Tab Management section]. Tabbed multi-document surface with Focus Mode for distraction-free writing. Multiple Spaces supported (Personal, Work, etc.) — tab+window dual: each Space is isolated for MCP/API ("Each MCP connection in Craft is linked to a single space. If you want to give an external tool access to documents across multiple spaces, you need to create a separate MCP connection for each space."). Multiple accounts supported. [Source: evidence/craft.md §5 + §6, citing introduction_shortcuts.md and https://craft-support.mintlify.app/en/integrate/mcp.md]
- **Anytype**: Tabs — "Open multiple Objects side by side in a tab bar" [Source: https://doc.anytype.io/anytype/features/tabs.md]. Back/Forward buttons (browser-style). Sidebar (Channel Sidebar) is the primary navigation hub containing Create button + dropdown, Types section, Queries, Collections, Bin, Graph. Each Channel has its own encryption keys — "you cannot share Types between spaces that stay in sync because they are separated with different encryption keys." [Source: evidence/anytype.md §5 + §6, citing https://doc.anytype.io/anytype/features/tabs.md and https://doc.anytype.io/anytype/organize/types.md]
- **Heptabase**: Browser-like tabs in left sidebar — "Tabs and bookmarks of the browser." Multiple whiteboards can be open in tabs. Right-sidebar "plugins" (right rail of context tools). Whiteboard is 2D infinite canvas. **Sub-whiteboards nest inside whiteboards** (preserving context). [Source: evidence/heptabase.md §5 + §6, citing https://wiki.heptabase.com/getting-started-with-heptabase and https://wiki.heptabase.com/fundamental-elements]
- **Obsidian**: Tabs, split views, and pop-out windows are core. Mobile page emphasizes: "Tabs, Command Palette, plugins, custom hotkeys — everything that makes Obsidian great is here." Mobile tab switcher: "Drag and drop tabs to reorder them." Changelog fix: "Fixed 'Open local graph' and similar commands opening tabs in a new tab group on phones, where tab groups are not supported." Sync share UI shows user avatars on shared vaults. [Source: evidence/obsidian.md §5 + §6, citing https://obsidian.md/mobile and https://obsidian.md/changelog/2026-07-30-mobile-v1.13.4/ and https://obsidian.md/sync]
- **Linear**: Multiple tabs (⌘T opens a new tab; ⌘W closes). Each tab navigates independently. **Split view NOT natively supported** for issues side-by-side — "Linear chooses to keep one issue detail open at a time (mitigated by Peek/Quick view with hover-to-preview)." Linear explicitly rejects multi-pane complexity — even the new "Coding Sessions" UI keeps a single conversation view at a time. [Source: evidence/linear.md §5 + §6, citing changelog references to coding sessions]
- **Reflect**: Split-pane view — "you can now edit and view two notes at the same time. To activate split-pane, try clicking a backlink while holding down the command key (or control if you're on Windows)… Highlight a backlink (using the arrow keys) and then press command+enter." Multiple windows supported. Cross-app deep links (mobile). [Source: evidence/reflect.md §5 + §6, citing changelog.txt]

### 3.2 IDE editor tab groups / split views (editor-class)
- **VS Code**: Editor area supports **tab groups** (split views) — up to N horizontal and vertical splits; "VS Code allows you to open up to three editor groups side by side" is the default-encouraged limit but unlimited splits are possible. Custom Layout (1.84) lets users reposition, hide, and reorder every UI element — Activity Bar can move to top, Panel can move to right or left, Side Bar can be on either side. Zen Mode (⌘K Z) hides all chrome except editor. Breadcrumbs in editor: "show the current file location and the current cursor's symbol location." [Source: evidence/vscode.md §5 + §6, citing https://code.visualstudio.com/docs/editing/userinterface and https://code.visualstudio.com/docs/configure/custom-layout]
- **Cursor**: Inherits VS Code split-view, terminal panel, multi-tab. **Cursor Browser** is a NEW dedicated panel — Chromium instance inside Cursor with visual editor overlay. Cloud Agents have their OWN workspace: "VMs in the cloud with full development environments instead of on your local machine." [Source: evidence/cursor.md §5 + §6, citing VS Code baseline + forum and https://cursor.com/blog/browser-visual-editor and https://cursor.com/docs/background-agent]
- **Zed**: Center editor pane (with optional splits) + Multi-buffers — "an editor primitive that allows multiple files / regions to be displayed in a single buffer — useful for 'edit across files' workflows." Panel Layout toggle (Agentic vs Classic) means workspace has two distinct modes. [Source: evidence/zed.md §5 + §6, citing https://zed.dev/docs/getting-started]
- **Helix**: Buffer line at top — `bufferline = "always" | "never" | "multiple"` (only shown if >1 buffer in use, when set to "multiple"). Window mode via `Ctrl-w`: `v` vsplit, `s` hsplit, `h j k l` move between splits, `H J K L` swap splits, `q` close, `o` only-keep-current. Pickers: file picker, buffer picker, jumplist picker, diagnostics picker, symbol pickers, command palette (`Space ?`). No concept of "project" or "workspace" as separate top-level entity — workspace is just the set of currently-open buffers and split windows. [Source: evidence/helix.md §5 + §6, citing https://docs.helix-editor.com/editor.html and https://docs.helix-editor.com/keymap.html]
- **JetBrains AI**: JetBrains IDE navigation tradition preserved (Project tool window, Editor tabs, tool windows, Run configurations). AI Assistant is delivered as a tool window / intention action. [Source: evidence/jetbrains-ai.md §5 + §6, citing https://www.jetbrains.com/help/idea/ai-assistant.html]
- **Warp**: Terminal blocks + Warp Drive panel + Code Review panel + Code editor + File Tree. "Modern terminal UX: Cursor movement, block-based navigation, multi-line editing, syntax highlighting, and rich completions. Built with Rust for high performance." Built-in Code editor with LSP support: "File tree, code editor with LSP support, and interactive code review experience." Warp Drive organized into folders. **Warp Agent CLI workspace**: built-in multiplexer — "directly manages pty connections similarly to tmux, unlocking more powerful agent workflows." [Source: evidence/warp.md §5 + §6, citing https://docs.warp.dev/ and https://www.warp.dev/agent-cli]

### 3.3 Multi-session AI conversations (chat-history-as-tabs)
- **Codex CLI**: `codex resume` (picker), `codex resume --last` (most recent), `codex fork` (fork a session). Session lifecycle: `codex archive`, `codex delete`, `codex unarchive` for session management. `codex exec --ephemeral`: "Run without persisting session files to disk." `/new`: "Start a new conversation inside the same CLI session. Reset the chat context without leaving the CLI when you want a fresh prompt in the same repo." `/compact`: "Summarize the visible conversation to free tokens. Use after long runs so Codex retains key points without blowing the context window." [Source: evidence/codex.md §5 + §7, citing https://developers.openai.com/codex/cli/slash-commands and `codex --help`]
- **Claude Code**: `-c, --continue` continues the most recent conversation in the current directory. `-r, --resume [value]` resumes by session ID or opens interactive picker. `--session-id <uuid>` for explicit conversation ID. `--no-session-persistence` for ephemeral sessions (only works with `--print`). `--teleport [session]` for resuming teleport sessions. `--worktree [name]` creates a new git worktree for the session. `--tmux` for iTerm2 panes or classic tmux. [Source: evidence/claude-code.md §5 + §7, citing `claude --help` 2025-08-07]
- **Aider**: Per-repo history persistence — `.aider.chat.history.md` (chat), `.aider.input.history` (input), `.aider.llm.history.txt` (LLM transcripts). `--restore-chat-history` rehydrates prior sessions. Optional **browser GUI** via `aider --browser` / `aider --gui`. IDE watch mode: `--watch-files` lets you write `// ai!` comments inside any editor and have Aider react. [Source: evidence/aider.md §5 + §6 + §7, citing `aider --help` 2026-08-07 and https://aider.chat/docs/usage/commands.html]
- **Sweep**: `⌘N` / Ctrl N new chat. Best-practice guidance: **"One chat per task"** — "Otherwise, the previous messages in the thread can hurt the intelligence of the model." Toggle Normal/Search mode: ⌘ . / Ctrl . (likely a context-search toggle). [Source: evidence/sweep.md §5 + §7, citing https://docs.sweep.dev/agent and https://docs.sweep.dev/shortcuts]
- **Cursor**: Checkpoints in the chat timeline — "click any checkpoint in the chat timeline to preview your files at that point, then restore to revert all files to that state. Checkpoints are stored locally and separate from Git." Cloud Agents run in their own workspace VMs. [Source: evidence/cursor.md §5 + §6 + §7, citing https://cursor.com/docs/agent]
- **Windsurf (Cascade)**: "Cascade will resume from where it left off." Retrieval within conversation: "When you do this, Cascade will retrieve the most relevant and useful information like the conversation summaries and checkpoints, and specific parts of the conversation that you query for." "Cascade automatically continue its response if it hits a limit." [Source: evidence/windsurf.md §7, citing https://docs.codeium.com/windsurf/cascade]
- **ChatGPT**: Context compaction across long threads — Codex/ChatGPT desktop changelog v0.144.0 (2026-07-09): "Resumed ChatGPT threads recover when compaction references a retired model by retrying with the currently selected model." Confirms long threads trigger automatic context compaction. Multiple conversations share sidebar; Projects group conversations. [Source: evidence/chatgpt.md §5 + §7, citing https://web.archive.org/web/2025/https://learn.chatgpt.com/docs/changelog]
- **Claude**: Editing prior chat messages creates "a different version of the conversation, with its own set of artifacts." Side panel supports multiple artifacts in a single conversation; **slider icon in upper right** switches between artifacts and selects which artifact Claude should reference for updates. As of July 7 2026: "Chat and Cowork share one home now, with one place for your projects and artifacts across both." [Source: evidence/claude.md §5 + §6 + §7, citing https://support.claude.com/en/articles/9796387-what-are-artifacts and https://support.claude.com/en/articles/release-notes]

## 4. Observed Variations

1. **Tab count limit** — VS Code "up to three editor groups side by side" (default-encouraged but unlimited); Helix `bufferline = "multiple"` (only show buffer line when >1 buffer); Arc unlimited tabs per Space; Notion unlimited; Craft Cmd+1 through Cmd+9 (implies 9-tab quick-switch limit). [Sources as cited in §3.]
2. **Tab identity primitive** — Linear tabs are issue-detail views (one issue at a time per tab); Notion tabs are pages; Craft tabs are documents; Arc tabs are URLs (with own cookies per profile); Heptabase tabs are whiteboards; Helix tabs are buffers; VS Code tabs are files; Codex sessions are conversations; Manus Browser Operator tabs are task-named tab groups. [Sources as cited in §3.]
3. **Split View semantics** — Arc's Split View is *itself a tab* (returnable later) — unique; VS Code editor groups are transient (die when closed); Helix splits die when last buffer closes; Reflect split-pane is two notes side-by-side; Obsidian split views support pop-out windows. [Sources as cited in §3.4.]
4. **Tab state persistence** — Manus Cloud Computer "Files Manus creates on it stay there. Tools Manus installs stay installed. If you want Manus to pick up where it left off last week, it can, because the work is still sitting on the machine."; Cursor Cloud Agents VMs persistent; Aider per-repo history files (`.aider.chat.history.md`, `.aider.input.history`, `.aider.llm.history.txt`); Codex `codex archive`/`delete`/`unarchive` for session management; MS Copilot Teams "Copilot conversations close when the side panel closes" (ephemeral — explicit anti-pattern). ## 5. Premium Exemplars

**Arc** — best-evidenced *creative* Split View: "When you create a split view, it becomes its own new tab in the sidebar that you can come back to later" [Source: evidence/arc.md §5 + §6, citing https://resources.arc.net/hc/en-us/articles/19335393146775-Split-View-View-Multiple-Tabs-at-Once]. Unique among products studied — solves the "transient split vs. saved split" tension that VS Code's split view (transient, dies when closed) does not. Multiple Spaces (Cmd+1, Cmd+2) with own tabs/theme/cookies is the cleanest multi-context isolation observed for a browser-class product.

**Codex CLI** — best-evidenced session-lifecycle tab primitives: `codex resume` picker / `--last` / `codex fork`, `codex archive` / `delete` / `unarchive`, `codex exec --ephemeral`, `/new`, `/compact`. "Most complete slash-command + session-state vocabulary observed" [Source: evidence/codex.md §5 + §7, citing https://developers.openai.com/codex/cli/slash-commands].

**Craft** — best-evidenced keyboard-complete tab UX: Cmd+T (new tab), Cmd+1 through Cmd+9 (switch to tab N), Ctrl+Tab (next tab), Cmd+Shift+T (reopen last closed tab), plus New Window support, plus Cmd+\ sidebar toggle, plus Cmd+O Quick Open, plus Cmd+Option+1–5 Jump to Views. "Richest navigation surface in the evidence set — comparable to a serious IDE like VS Code." [Source: evidence/craft.md §5, citing introduction_shortcuts.md]

**Claude Artifacts** — best-evidenced multi-artifact tab surface within a single conversation: "Side panel supports multiple artifacts in a single conversation; a slider icon in the upper right lets the user switch between them and select which artifact Claude should reference for updates." Editing prior chat messages creates "a different version of the conversation, with its own set of artifacts" — explicit version+artifact tab coupling. [Source: evidence/claude.md §6, citing https://support.claude.com/en/articles/9796387-what-are-artifacts]

**Apple Siri** — best-evidenced cross-device tab continuity: "A dedicated app brings together all your conversations in one place, so you can ask a question on your iPhone and pick up where you left off on your iPad. You can also pin conversations for easy access or start a new one." [Source: evidence/apple-intelligence.md §5 + §7, citing https://www.apple.com/apple-intelligence/]

**Manus Browser Operator** — best-evidenced *task-as-tab* pattern: "Manus opens a new tab within a tab group named after your current task. You can watch the task unfold in real-time, take over by clicking into the tab, or stop the process instantly by closing it." Closing the tab = stopping the task — direct tab↔task binding. [Source: evidence/manus.md §5 + §6, citing https://manus.im/blog/manus-browser-operator]

**Cursor** — best-evidenced *checkpoint-as-tab* pattern: "click any checkpoint in the chat timeline to preview your files at that point, then restore to revert all files to that state. Checkpoints are stored locally and separate from Git." Cloud Agents have their OWN workspace (parallel VMs). [Source: evidence/cursor.md §5 + §7, citing https://cursor.com/docs/agent]

## 6. Anti-Patterns

**ChatGPT Canvas (no named version list)** — "implicit version history via back/forward navigation, not a named 'versions' list." Compare to Claude's explicit "Version selector allows switching between versions" and Gemini Canvas's "Previous Version / Next Version." [Source: evidence/chatgpt.md §6, citing https://web.archive.org/web/2025/https://openai.com/index/introducing-canvas]. ChatGPT Canvas's lack of named version list forces recall ("which back-arrow count was the good version?") rather than recognition — violates Nielsen Heuristic #6.

**MS Copilot Teams (ephemeral per-session state)** — "Copilot conversations close when the side panel closes" [Source: evidence/ms-copilot.md §7, citing `learn-m365-overview.txt`]. Violates Amershi G12 "Remember recent interactions" — the tab/conversation state is destroyed when the panel closes.

**Notion (no native split-view)** — "Notion does not natively support side-by-side page editing. Users work around this by opening multiple windows." [Source: evidence/notion.md §5, citing notion-help-sidebar.html]. For a knowledge-management product, the absence of side-by-side comparison forces context-switching (CLT split-attention effect) — only partially mitigated by Cmd+T (tabs) and Cmd+Shift+N (new window).

**Linear (no split view)** — "Split view NOT natively supported for issues side-by-side — Linear chooses to keep one issue detail open at a time (mitigated by Peek/Quick view with hover-to-preview)." [Source: evidence/linear.md §6]. Explicit design choice, but limits comparison-heavy workflows (reviewing two issues, two PRs, two coding sessions side-by-side). Anti-pattern for cross-issue analysis tasks.

**Bolt (Safari Code view read-only)** — "In Safari, Code view is read-only (must use Chrome/Chromium/Opera/Brave/Edge/Vivaldi to edit code)" [Source: evidence/bolt.md §6, citing https://support.bolt.new/building/using-bolt/code-view.md]. Browser-specific degradation of a core tab surface violates Shneiderman Golden Rule #1 "Consistency" — the same affordance should behave the same regardless of host browser.

**Granola (no multi-pane / no tab model)** — "There is no multi-pane workspace model in the crawlable surface — Granola is a single-note-centric app with a list of recent notes. There is no concept of 'projects' or 'files'; the atomic unit is the meeting note." [Source: evidence/granola.md §6, citing https://granola.ai/]. Adequate for a meeting-notes product but evidence that single-note workspaces do not support comparison or multi-meeting synthesis workflows.

**Meta AI (no documented cross-surface sync)** — "Multi-surface: same assistant is reachable in Facebook DMs, Instagram DMs, WhatsApp chats, Messenger, Threads — conversation context may or may not sync across surfaces; not directly evidenced. Gap noted." [Source: evidence/meta-ai.md §6]. Without documented cross-surface sync, the user cannot rely on continuing a conversation across Meta's surfaces.

## 7. Cognitive Load Implications

CLT predicts the following tabs-UX effects [Source: academic/cognitive-load-theory.md §5–7, citing Sweller 1988 and Cowan 2001]:

- **Externalization of parallel contexts reduces EL** — Without tabs, the user must hold all parallel contexts in working memory (~4 chunks per Cowan 2001). Tabs externalize these into a visible list (recognition over recall), freeing working-memory capacity for the task itself. v0's sidebar hover card "previews how a turn ended, such as its closing summary or the question it is waiting on, and the in-progress status reads 'v0 is working'" is the strongest documented implementation of tab-state externalization [Source: academic/recognition-vs-recall.md §6 — "Recent prompts / conversations panel: ChatGPT, Claude, Gemini all provide this — recognition of past interactions rather than recall"].

- **Tab breadth → Hick's Law penalty** — Tab counts >7±2 (Miller 1956) or >4±1 (Cowan 2001) exceed working-memory capacity for tab-state tracking. Craft Cmd+1 through Cmd+9 implies a 9-tab quick-switch limit. Arc unlimited tabs per Space — relies on sidebar grouping (Pinned/Today/Unpinned) to manage breadth. Linear "fewer top-level items" discipline. [Source: academic/millers-law.md cross-ref; academic/hicks-law.md cross-ref.]

- **Split views reduce split-attention** — Arc Split View (two URLs side-by-side), VS Code editor groups (up to three files side-by-side), Reflect split-pane (two notes side-by-side), Helix vsplit/hsplit. Physically integrating two contexts into one view reduces EL vs. switching between two full-screen tabs (CLT split-attention effect, Sweller, Chandler & Tierney 1990) [Source: academic/cognitive-load-theory.md §5].

- **Tab versioning reduces EL of "which version was good?"** — Claude explicit Version selector; Gemini Previous/Next Version; Lovable action chips (Undo latest / Revert to this); Cursor checkpoints in chat timeline; Reflect History browser time-machine; LangGraph per-node Fork. Each converts recall ("which iteration was the right one?") into recognition (named/listed versions) [Source: academic/recognition-vs-recall.md §6].

- **Modal tab navigation (Helix) imposes intrinsic load** — Helix's `Ctrl-w` then `v`/`s`/`h j k l`/`H J K L`/`q`/`o` requires the user to hold modal state in working memory. For experts this becomes schema in LTM (germane load); for novices it is intrinsic load that could be eliminated by a simpler tab UI.

- **Cloud-workspace tabs (Manus Cursor, OpenHands) reduce re-orientation EL** — Manus Cloud Computer "If you want Manus to pick up where it left off last week, it can, because the work is still sitting on the machine" — eliminates the re-orientation cost of re-instantiating an environment from scratch. Schema construction (germane load) is preserved across sessions [Source: academic/cognitive-load-theory.md §3 — germane load definition].

## 8. Progressive Disclosure Relationship

Progressive disclosure (Nielsen 2006) interacts with tabs UX in five documented patterns [Source: academic/progressive-disclosure.md §4–7, citing Nielsen 2006 nngroup.com/articles/progressive-disclosure/ and Springer & Whittaker 2018 arXiv:1811.02164]:

1. **Tab state on hover** — v0 sidebar hover card "previews how a turn ended, such as its closing summary or the question it is waiting on, and the in-progress status reads 'v0 is working'" — discloses tab state without requiring click-into. Direct instantiation of Nielsen 2006 criterion #3 "discoverability" and Springer & Whittaker 2018 "initially simplified feedback" [Source: academic/progressive-disclosure.md §5].

2. **Tab close / reopen as disclosure** — Craft Cmd+Shift+T (reopen last closed); VS Code Cmd+W (close); Arc X above either panel or X next to Split Tab; Helix `Ctrl-w q` (close), `Ctrl-w o` (only-keep-current). Each lets the user reduce visible complexity on demand — "initially simplified surface with drill-down on demand."

3. **Tab versioning as progressive disclosure** — ChatGPT Canvas back/forward (transient history); Claude Artifacts Version selector + slider icon to switch between artifacts in single conversation; Gemini Previous/Next Version; Cursor checkpoints in chat timeline; Lovable action chips; Reflect History browser time-machine; LangGraph per-node Fork. Each is "initially simplified feedback that hides potential system errors and helps users build working heuristics" per Springer & Whittaker 2018 [Source: academic/progressive-disclosure.md §5].

4. **Multi-artifact slider** — Claude "a slider icon in the upper right lets the user switch between them and select which artifact Claude should reference for updates" — discloses multiple artifacts in a single conversation progressively. ChatGPT Canvas lacks this — back/forward only [Source: evidence/claude.md §6; evidence/chatgpt.md §6].

5. **Cloud-workspace tab persistence** — Manus Cloud Computer "Files Manus creates on it stay there. Tools Manus installs stay installed. If you want Manus to pick up where it left off last week, it can, because the work is still sitting on the machine" — progressively discloses prior work without re-loading. Cursor Cloud Agents VMs persistent. [Sources as cited in §3.5.]

**Opacity-theatre risk** — arXiv:2605.10930 (2026) requires that progressive disclosure not become opacity theatre [Source: academic/progressive-disclosure.md §7–8, citing arXiv:2605.10930]. ChatGPT Canvas's back/forward without named version list borders on this — the user must drill down through undifferentiated back-arrow presses. Claude's explicit Version selector avoids this.

## 9. Accessibility Considerations

Evidence sparse but notable:
- **Apple Siri cross-device continuity** — "ask a question on your iPhone and pick up where you left off on your iPad. You can also pin conversations for easy access or start a new one" — supports users who switch devices (low-vision users using iPhone VoiceOver then Mac VoiceOver) [Source: evidence/apple-intelligence.md §5 + §7, citing https://www.apple.com/apple-intelligence/].
- **Things3 multi-window support** — `^⌘N` open new window, `⌘ Return` open from Quick Find in new window, "Open a project or area in a new window" — supports users who need comparison views (low-vision users with large windows, multi-monitor users). iPadOS 26 Mac-like windowed mode with traffic light controls. [Source: evidence/things3.md §5 + §6, citing https://culturedcode.com/things/support/articles/2785159/ and https://culturedcode.com/things/blog/2025/09/things-for-os-26/].
- **Craft keyboard-complete tab UX** — Cmd+T, Cmd+1–9, Ctrl+Tab, Cmd+Shift+T, Cmd+O Quick Open, Cmd+Option+1–5 Jump to Views — most-evidenced keyboard-only tab operation among note-taking products [Source: evidence/craft.md §5, citing introduction_shortcuts.md].
- **Helix keyboard-only tab/split nav** — `Ctrl-w` then `v`/`s`/`h j k l`/`H J K L`/`q`/`o`; `bufferline = "multiple"` — fully keyboard-driven. Implicitly accessible to keyboard-only / screen-reader users, though AccessKit support is "in-progress not shipped" [Source: evidence/helix.md §5 + §6, citing https://docs.helix-editor.com/keymap.html; cross-ref evidence/helix.md §19].

**Insufficient evidence — gap noted:** No evidence file documents ARIA roles for tablist / tab / tabpanel; no evidence on focus-trap behavior when switching tabs; no evidence on screen-reader announcement of tab state changes (e.g., "tab closed," "new tab created"); no evidence on color-contrast / Dynamic Type / reduced-motion settings for tab transitions; no evidence on touch-target sizing for mobile tab strips; no evidence on tab-close confirmation dialogs for unsaved state.

## 10. Performance Implications

Tabs UX affects perceived performance in three documented ways:
- **Persistent cloud tabs eliminate cold-start** — Manus Cloud Computer "If you want Manus to pick up where it left off last week, it can, because the work is still sitting on the machine"; Cursor Cloud Agents VMs persistent; OpenHands CloudWorkspace managed sandboxes — eliminate environment re-instantiation cost [Source: evidence/manus.md §6, citing https://manus.im/blog/manus-cloud-computer; evidence/cursor.md §6, citing https://cursor.com/docs/background-agent; evidence/openhands.md §6, citing https://docs.openhands.dev/sdk/guides/agent-server/cloud-workspace.md].
- **Real-time parallel tab updates** — Manus "You see everything Manus is doing in real-time, including browser screenshot frames"; Lovable "live, interactive version of your app that updates as Lovable works"; Cursor Browser "agents run in parallel, and within seconds your changes are live" — tab-state perceived as instant [Sources as cited in §3.5].
- **Tab parallelism with AI agents** — OpenHands Agent Canvas "flip between them" — multiple Agent Servers running simultaneously; Cursor Cloud Agents run in parallel VMs; Devin multi-surface (web app + Slack + PR comments simultaneously); Linear's seven parallel AI surfaces — user perceives parallelism without sequential blocking [Sources as cited in §3.5, §3.8].
- **Tab hover preview eliminates click-cost** — v0 sidebar hover card previews chat state without click — eliminates click-then-back navigation cost [Source: evidence/v0.md §5, citing https://v0.dev/changelog Jul 31 2026].

## 11. Long-Session Impact

Multi-hour tab use faces three documented failure modes:
1. **Tab sprawl** — solved by Arc Spaces (own tabs/theme/cookies); Craft Spaces (isolated MCP per Space); Reflect graph color setting; Heptabase sub-whiteboards nesting; Manus Cloud Computer persistence. Without isolation primitives, long sessions accumulate unmanageable tab counts (Hick's Law penalty).
2. **State loss on crash / close** — Lovable draft persistence ("draft answers persist in browser so a refresh doesn't lose them"); v0 "Typed prompts survive clarifying questions, permission approvals, and queued submissions"; Reflect YJS sync engine "your offline changes will be merged in a more intelligent manner"; Reflect History browser "time-machine for your notes... revert to any point in time"; Craft Document Version History; Aider per-repo history files (`.aider.chat.history.md`, `.aider.input.history`, `.aider.llm.history.txt`); Codex `codex archive`/`delete`/`unarchive`. [Sources as cited in §3.3, §3.7.]
3. **Tab recovery / reopen** — Craft Cmd+Shift+T (reopen last closed); Arc right-click Split Tab → "Separate All Tabs"; MS Copilot Teams anti-pattern (no recovery — "Copilot conversations close when the side panel closes"). [Sources as cited in §3.1, §3.6.]

Long sessions also reveal **per-tab cost transparency** — only v0 and Lovable document per-message Credits used; no broad pattern across consumer chat products for per-tab resource cost (compute-hours, storage) transparency.

## 12. Open Questions
