# Pattern: Knowledge UX

> PAT-3. Evidence synthesis across 11 products + NotebookLM (gold standard). NO MiMo design. Pattern extraction only.

## 1. Pattern Definition

**Knowledge UX** refers to the design of structures and surfaces by which a product represents, surfaces, queries, and cites user-curated or AI-retrieved information. Across the evidence set, the pattern exhibits five signature properties:

1. **Grounding** — every AI claim is tied to a specific source artifact (notebook, web URL, doc, drive file) rather than free-floating. Gold standard: NotebookLM "accompanying each response with citations, showing you the most relevant original quotes from your sources." [Source: evidence/notebooklm.md §10 + §22, citing https://blog.google/technology/ai/introducing-notebooklm-google-ai/]
2. **Bidirectional link graph** — explicit `[[links]]` create computed backlinks (Roam, Logseq, Obsidian, Reflect, Heptabase, Tana, Anytype). [Source: evidence/roam.md §10; evidence/logseq.md §10; evidence/obsidian.md §10; evidence/reflect.md §9; evidence/heptabase.md §10; evidence/tana.md §10; evidence/anytype.md §10]
3. **Typed-relational schema** — user-defined Types with Properties/Views/Templates (Anytype richest: Note/Task/Project/Meeting + custom Types + typed Links between Objects + six View layouts: List/Grid/Calendar/Kanban/Gallery/Graph). [Source: evidence/anytype.md §10]
4. **Query language / saved queries** — Datalog (Roam, Logseq), Search Nodes (Tana), Bases (Obsidian), Queries (Anytype), Dataview plugin (Obsidian). [Source: evidence/roam.md §10; evidence/logseq.md §10; evidence/tana.md §10; evidence/obsidian.md §10; evidence/anytype.md §10]
5. **Citation granularity spectrum** — per-claim citation linking to specific passage/quote (NotebookLM, Heptabase per-paragraph citations) → per-source numbered citation (Perplexity) → source-typed citation `[web:1]` (Perplexity Agent API) → no citation, just source panel (Gemini Deep Research). [Source: evidence/notebooklm.md §22; evidence/heptabase.md §22; evidence/perplexity.md §22; evidence/gemini.md §22]

## 2. Why It Matters (with academic evidence)

Knowledge UX matters because ungrounded AI claims produce what CLT calls an "illusion of knowing" — low germane load without schema construction (arXiv:2607.02723, "Doom Researching", 2026) [Source: academic/cognitive-load-theory.md §65, citing https://arxiv.org/abs/2607.02723]. Per-claim citations force the user to verify claims against sources, converting passive recognition into active schema-building (germane load).

The pattern also operationalizes **information foraging theory** (Pirolli & Card, Xerox PARC, early 1990s): information scent — the perceptual cues (link text, descriptions, snippets) that suggest how promising a path is — must be strong and honest. Nielsen (2004 Alertbox) warned that "deceivingly strong information scent costs sales" — strong-looking scent that doesn't deliver creates abandonment. Citation chips and backlinks are scent affordances: they signal "this claim traces to this source" so the user can forage efficiently. [Source: academic/information-scent.md §7 + §56, citing https://en.wikipedia.org/wiki/Information_foraging + https://www.nngroup.com/articles/progressive-disclosure/]

Finally, the pattern aligns with **Nielsen Heuristic #6 (Recognition rather than recall)** — bidirectional links, backlink panels, and unlinked-references panels let the user recognize related content rather than recall it. [Source: academic/recognition-vs-recall.md §61-83, citing https://www.nngroup.com/articles/ten-usability-heuristics/; Source: academic/jakob-nielsen.md §61, citing Heuristic #6]

## 4. Observed Variations

- **Per-claim quote citation vs. per-source citation**: NotebookLM and Heptabase link to specific paragraph/passage/quote; Perplexity links to source as a whole with numbered `[1]`. The former minimizes Gulf of Evaluation (Norman) — the user verifies the exact grounding, not the source in aggregate. [Source: evidence/notebooklm.md §22; evidence/heptabase.md §22; evidence/perplexity.md §22; academic/don-norman.md §7]
- **Block-level UID vs. page-level reference**: Roam `((uid))` atomic blocks are individually addressable (every block is a node). Reflect has no block-level UID semantics — only page-level backlinks. Tana has node-level (every bullet is a node). The granularity determines the minimum addressable knowledge unit. [Source: evidence/roam.md §10; evidence/reflect.md §10; evidence/tana.md §10]
- **Typed-relational vs. tag-graph**: Anytype uses user-defined Types + typed Links (Recipe→Person typed relation). Tana uses Supertags (#meeting, #task). Reflect/Roam/Logseq/Obsidian use untyped `#tags` and `[[page]]` links (the type IS the page). Typed-relational schema requires more upfront design but yields queryable relationships. [Source: evidence/anytype.md §10; evidence/tana.md §10; evidence/reflect.md §10; evidence/roam.md §10]
- **Server-side RAG vs. local-first**: Claude Projects use server-side RAG with 10x capacity expansion at context limits. Gemini uses Connected Apps + per-Gem uploads (server-side). Obsidian/Heptabase/Anytype/Logseq are local-first (no server processes user content); Anytype explicitly markets "no Anytype server that processes user content" as an explainability advantage. [Source: evidence/claude.md §10; evidence/gemini.md §10; evidence/anytype.md §22]
- **Saved-query semantics**: Tana Search Nodes ("saved queries that surface supertagged items"), Anytype Queries ("question you ask your knowledge base—answered instantly and kept up to date automatically"), Obsidian Bases (database view with sort filters), Roam `{{query: ...}}` blocks, Logseq Live Queries (Datalog inline). All materialize a query as a viewable artifact, but with different persistence models (Tana=sidebar widget, Anytype=embeddable inline, Obsidian=.base file, Roam=block, Logseq=block). [Source: evidence/tana.md §10; evidence/anytype.md §10; evidence/obsidian.md §10; evidence/roam.md §10; evidence/logseq.md §10]
- **Passive vs. active knowledge channel**: Gemini "automatically uses public information from certain Google services" even when Connected Apps is OFF — a passive channel that's hard to inspect. Contrast with Claude Projects (only what you upload) or Perplexity (only the live web at query time). Passive channels create explainability opacity (Reflect explicitly notes "no documented 'what the AI sees' panel"). [Source: evidence/gemini.md §10; evidence/claude.md §10; evidence/perplexity.md §10; evidence/reflect.md §22]
- **Token-billed citation depth**: Perplexity Sonar Deep Research bills citation tokens ($2/1M) and reasoning tokens ($3/1M) separately — the model literally spends tokens producing more citations. This is the only product where citation depth is metered as a cost. [Source: evidence/perplexity.md §10, citing https://docs.perplexity.ai/getting-started/pricing]

## 5. Premium Exemplars (BEST + WHY — evidence-based)

**BEST (citation grounding): NotebookLM** — because per-claim citations link to specific passages/quotes (not just sources), the source set is user-curated (not the open web — so foraging scent is high and honest), and the artifact generators (Audio Overview, Mind Map, Briefing Doc, Flashcards) provide multiple structural explanations of the same source set, addressing different learning modalities (germane load via re-representation). Audio Overview is also the strongest a11y affordance in the set. [Source: evidence/notebooklm.md §10 + §19 + §22, citing https://blog.google/technology/ai/introducing-notebooklm-google-ai/ + https://blog.google/technology/ai/notebooklm-audio-overviews/]

**BEST (graph-grounded AI explainability): Heptabase** — because per-paragraph citations point to specific paragraph blocks or timestamps ("just click to jump to the corresponding location"), chat context is explicit & user-curated (add cards or entire whiteboard via `+` or `@`), AI Action buttons appear on hover over cards (every AI transform grounded in a specific card), and AI Tutor shows "Thought completed" status before each action — step-level transparency unmatched in the set. The spatial whiteboard model also makes the grounding perceptually visible (not just textually cited). [Source: evidence/heptabase.md §22, citing https://wiki.heptabase.com/work-with-ai]

**BEST (typed-relational knowledge schema): Anytype** — because the Type/Property/Link/View/Query/Collection/Templated model is the richest in the evidence set, with explicit bidirectional typed Links (Recipe Object → Person Object), six View layouts (List/Grid/Calendar/Kanban/Gallery/Graph), inline queries embedded in any Object, AND the schema is enforced locally (open-source AnySync protocol) with no server processing of user content — combining structural richness with explainability-by-architecture. [Source: evidence/anytype.md §10 + §22, citing https://doc.anytype.io/anytype/organize/types.md + /create/links.md + /organize/views.md + /organize/queries.md]

**BEST (token-transparent citation depth): Perplexity** — because source-typed citations `[web:1]` distinguish web-tool-derived from user-source-artifact claims, Pro Search reveals its steps (queries run + URLs fetched), and citation depth is metered as cost (citation tokens $2/1M) — making the "how hard did the AI search" question inspectable. However, it lacks the user-curated knowledge graph of NotebookLM/Anytype — the live web is the knowledge. [Source: evidence/perplexity.md §10 + §22, citing https://docs.perplexity.ai/changelog + /getting-started/pricing]

## 6. Anti-Patterns (FAIL + WHY — evidence-based)

- **Perplexity's 4-axis choice overload** — Focus × Pro × Model × Context-Size are "partially orthogonal and partially redundant — a user choosing Sonar Deep Research + Pro Search on + High context + Academic Focus is making 4 reinforcing choices for the same goal." This is a textbook CLT extraneous-load failure: the user must hold 4 orthogonal mental models simultaneously before any query. Violates Nielsen Heuristic #2 (match between system and real world — no real-world analog for this matrix). [Source: evidence/perplexity.md §18, citing https://docs.perplexity.ai/getting-started/pricing]
- **Gemini's mode+model+source conflation** — "Add Files" exposes Files upload + Image upload + Deep Research + Canvas behind one button; "Sources" within Deep Research exposes Google Search + Gmail + Drive + NotebookLM in the same surface; "Pro" vs "Thinking" model selection reached via secondary flow; "@app" mention syntax adds Connected Apps into the prompt box. The Help Center repeatedly uses "If you've never made a Gem before, first click Settings and help → Gems" — an admission of discoverability failure. [Source: evidence/gemini.md §18, citing https://support.google.com/gemini/answer/15719111 + /answer/15146780 + /answer/13695044]
- **Gemini's passive knowledge channel** — "automatically uses public information from certain Google services" even when Connected Apps is OFF. There is no UI surfacing "what does Gemini know about me passively?" This violates Nielsen Heuristic #1 (visibility of system status) and creates a Gulf of Evaluation (Norman) — the user cannot form an accurate mental model of the AI's grounding. [Source: evidence/gemini.md §10; academic/don-norman.md §7]
- **Reflect's lack of model disclosure** — "No model card / no AI behaviour disclosure — Reflect does not document which models do what, how prompts are constructed, what context is sent, or what the failure modes are. No documented 'what the AI sees' panel." This makes Reflect's AI a black box from the user's perspective — the user cannot verify grounding even if they wanted to. [Source: evidence/reflect.md §22]
- **Claude Projects' free-tier 5-project cap + opaque RAG expansion** — "When your project knowledge approaches context limits, Claude seamlessly enables RAG mode to expand capacity by up to 10x." The user is not told when RAG mode activates or which documents were retrieved. This is invisible retrieval — a Gulf of Evaluation gap. [Source: evidence/claude.md §10, citing https://support.claude.com/en/articles/what-are-projects]
- **Tana's graph AI marketing without citation UI** — "Not directly accessed: whether Tana shows per-paragraph citations like Heptabase — fetched marketing copy does not explicitly describe citation chips." The graph-grounded AI thesis is strong in marketing but the per-claim citation UX is not documented. The promise may exceed the implementation. [Source: evidence/tana.md §22 — gap noted]
- **Roam's Unlinked References as presentation-only** — "Roam surfaces these in a panel beneath each page (visible in the public UI, not specifically exposed as a separate MCP tool, suggesting it is a presentation-layer feature rather than a data-layer primitive)." This means unlinked references cannot be programmatically queried — they're a UI affordance only. [Source: evidence/roam.md §10]

## 7. Cognitive Load Implications (cite CLT)

- **Extraneous load reduction via grounding**: Per-claim citations (NotebookLM, Heptabase) reduce split-attention (CLT split-attention effect, Chandler & Sweller 1991) — the user verifies the claim against the source in the same perceptual field, rather than holding the claim in working memory while searching for the source. [Source: academic/cognitive-load-theory.md §30; evidence/notebooklm.md §22; evidence/heptabase.md §22]
- **Intrinsic load reduction via single-axis disclosure**: NotebookLM's single-axis model (which sources are selected) is "simpler, more honest" than Perplexity's 4-axis overload. The CLT segmentation principle applies: one decision axis = one element of element-interactivity, vs. four orthogonal axes = 16 combinations to evaluate. [Source: evidence/notebooklm.md §18; evidence/perplexity.md §18; academic/cognitive-load-theory.md §51]
- **Germane load increase via re-representation**: NotebookLM's artifact generators (Audio Overview, Mind Map, Briefing Doc, Flashcards) and Tana Views (table/calendar/card/list) let the user see the same source set different ways. Schema-building through re-representation is the canonical germane-load-maximizing technique. [Source: evidence/notebooklm.md §10; evidence/tana.md §10; academic/cognitive-load-theory.md §40 — worked-example effect]
- **Expertise-reversal risk for typed schemas**: Anytype's typed-relational schema (Types/Properties/Links) is optimized for users who want explicit structure; novices may find the upfront design cost high. Anytype mitigates via Templates ("pre-filled starting points for new Objects"). [Source: evidence/anytype.md §10; academic/cognitive-load-theory.md §44 — expertise-reversal effect]
- **Illusion of knowing risk (arXiv:2607.02723)**: AI-assisted knowledge tools (Claude Projects RAG, Gemini Connected Apps) can create "illusion of knowing" without schema construction — the user trusts the AI's grounding without verifying it. Per-claim citations (NotebookLM) mitigate by forcing verification. [Source: academic/cognitive-load-theory.md §65, citing https://arxiv.org/abs/2607.02723]
- **Information foraging cost (Pirolli & Card)**: Strong information scent reduces the cost of foraging. Citation chips (NotebookLM, Heptabase, Perplexity) are scent affordances. Nielsen (2004): "deceivingly strong information scent costs sales" — products that promise grounding but don't deliver (Tana's marketing vs. undocumented citation UI) create abandonment. [Source: academic/information-scent.md §7 + §56]

## 8. Progressive Disclosure Relationship

- **NotebookLM single-axis disclosure**: "select sources, then ask" is the ONLY meaningful axis before a query. Modes is a SECOND axis but coarse (small number of preset modes), not a 4-axis matrix. Output language is a setting, not a per-query axis. Artifact generators are explicit one-click buttons — no hidden complexity. This is the CLEANER disclosure model in the set. [Source: evidence/notebooklm.md §18]
- **Roam bottom-up by depth**: A page initially shows only its own block tree. "Linked References" panel reveals every page/block that links to it (collapsible). "Unlinked References" panel reveals text matches that could become links (collapsible, separately). Block-level disclosure: every block can be collapsed/expanded. `Cmd/Ctrl+Enter` on a block "zooms in" to show only its subtree. Right sidebar opens additional pages without navigating away. [Source: evidence/roam.md §18]
- **Heptabase spatial nesting**: Sub-whiteboards allow zooming into sub-topics without leaving the main whiteboard context. Card expand/collapse via card info section. Toggles as a block type. Mindmap mode toggles a card's children into a mindmap view. AI Tutor lesson progress disclosed incrementally ("0/4 completed"). [Source: evidence/heptabase.md §18]
- **Anytype content-driven disclosure**: Sidebar Sections — Types/Queries/Collections/Bin only reveal items that have content. "Only Types with at least one Object in them will display in this section." View collapse — toggled headings collapse and expand sections of long Objects. Inline Queries — embedded live-filtered Views, only expanding when the user wants to see them. Sidebar Widgets — pinned Views showing a snapshot. [Source: evidence/anytype.md §18, citing https://doc.anytype.io/anytype/create/objects.md + /create/editor/toggled-headings.md + /features/inline-queries.md + /basics/sidebar/widgets.md]
- **Tana Views as disclosure-by-representation**: Views project the same nodes different ways — progressive disclosure by changing representation rather than hiding/showing. Search nodes surface only matching items — progressive disclosure by filter. [Source: evidence/tana.md §18]
- **Nielsen (2006)** empirical claim: progressive disclosure improves learnability, efficiency, and error rate; the "limiting mental model" concern is groundless. NotebookLM's single-axis disclosure operationalizes this — the user is never asked to commit to depth before knowing what's available. [Source: academic/progressive-disclosure.md §39, citing https://www.nngroup.com/articles/progressive-disclosure/]

## 10. Performance Implications

- **Claude Projects RAG**: "When your project knowledge approaches context limits, Claude seamlessly enables RAG mode to expand capacity by up to 10x while maintaining response quality." RAG adds retrieval latency but is invisible to the user — no performance cliff perception, but also no performance transparency. [Source: evidence/claude.md §10]
- **Perplexity Deep Research**: Citation tokens ($2/1M) + reasoning tokens ($3/1M) imply long-running multi-minute jobs. Pro Search reveals steps (queries run + URLs fetched) — streamed progress for long research. [Source: evidence/perplexity.md §22, citing https://docs.perplexity.ai/getting-started/pricing]
- **Obsidian local-first**: 10k notes benchmark; performance scales with disk I/O, not server round-trips. Bases plugin uses OKLCH colorspace for color properties. [Source: evidence/obsidian.md §20]
- **Anytype local-first**: No Anytype server processes user content — queries execute against the local graph. Performance scales with local device. [Source: evidence/anytype.md §22]
- **Heptabase / Tana large vaults**: No published benchmarks for 1k+ cards/nodes. [Source: evidence/heptabase.md §20 + evidence/tana.md §20 — gaps noted]
