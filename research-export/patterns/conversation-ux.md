## 1. Pattern Definition

**Conversation UX** is the interaction pattern in which a user and an AI exchange messages over a persistent, scrolling transcript — typically with the user typing/pasting/voice-inputting at a bottom-anchored composer and the AI streaming a reply token-by-token into the same surface. The conversation may be the entire product (ChatGPT, Claude, Gemini, GLM, Grok, Le Chat, Meta AI), the primary surface of an agentic product (Cursor, Windsurf, Claude Code, Codex, Aider, Replit, Lovable, Bolt, v0, Manus, Devin, Sweep, Continue, OpenHands, Warp), a contextual side-surface inside a host app (Notion AI, Linear Agent, MS Copilot Chat, JetBrains AI, VS Code Copilot Chat, Apple Siri, Dust), or a whiteboard-anchored panel (Heptabase, Tana). The pattern includes: input affordances (slash commands, @-mentions, attachments, voice), response rendering (streaming text, thinking blocks, tool-call cards, activity cards, action chips), and session lifecycle (resume, fork, compact, archive, multi-turn context). [Source: evidence/chatgpt.md §7, citing https://help.openai.com/en/chatgpt; evidence/claude.md §7, citing https://www.anthropic.com/news/claude-4; evidence/cursor.md §7, citing https://cursor.com/docs/agent; evidence/windsurf.md §7, citing https://docs.codeium.com/windsurf/cascade]

## 2. Why It Matters

Conversation is the dominant **mixed-initiative** interaction model for AI: the user issues natural-language intent, the AI plans/acts/replies, the user corrects/extends. Horvitz (1999) "Principles of Mixed-Initiative User Interfaces" (CHI '99, doi:10.1145/302979.303030) established that mixed-initiative systems must explicitly support *who has the turn*, *when to interrupt*, and *how to recover from misunderstanding* — three concerns that conversation UX directly addresses via streaming, queue/steer/stop controls, and undo/revert affordances [Source: academic/human-ai-interaction.md §2, citing Horvitz 1999].

Amershi et al. (2019) "Guidelines for Human-AI Interaction" (CHI '19, doi:10.1145/3290605.3300233) — Microsoft Research's 18 guidelines derived from 168 HCI guidelines — explicitly requires G7 "Support efficient invocation," G8 "Support efficient dismissal/interruption," and G9 "Support efficient correction" [Source: academic/human-ai-interaction.md §4]. Conversation UX is the surface where these guidelines live or fail: if the user cannot stop a runaway generation, queue a follow-up, or undo a wrong turn, the system violates Amershi G8/G9 directly.

Bansal et al. (2021, CHI '21, doi:10.1145/3411764.3445717) empirically demonstrated that AI explanations can *hurt* team performance when humans over-trust them — complementary team performance requires surfacing *errors*, not just rationales [Source: academic/human-ai-interaction.md §5]. This is why conversation UX must show tool calls, citations, and uncertainty — not just polished prose.

Grouped by conversation approach:

### 3.1 Streaming-first consumer chat
- **ChatGPT**: token-by-token streaming over WebSocket/SSE; "Thinking..." expanding-collapsible panel for GPT-5 thinking model; multimodal inputs (text, image, voice via Whisper, screen share, file attachments); outputs include text, code, generated images, Canvas docs, tool-call results [Source: evidence/chatgpt.md §7, citing https://web.archive.org/web/2025/https://learn.chatgpt.com/docs/changelog].

- **Gemini**: streaming documented for Deep Research and chat replies; two reasoning modes — "Thinking" (all users) and "Pro" (Pro/Ultra plans); inline completion notifications ("next to the chat thread with your completed report"); Gemini Live voice conversation; Gems cannot be used with Gemini Live [Source: evidence/gemini.md §7, citing https://support.google.com/gemini/answer/15719111].

## 5. Premium Exemplars

**v0** — best-evidenced in-flight conversation control: Cmd+Enter interrupts active response, Cmd+Up/Down steps through queued prompts, prompt history with Up/Down in composer (including attachments and skills), typed prompts survive clarifying questions / permission approvals / queued submissions, grouped approvals in a single panel above composer, sound notification on completion while window unfocused. Each feature is dated in changelog [Source: evidence/v0.md §7, citing https://v0.dev/changelog entries Jul 7/21/31 2026, Dec 17 2025, Jan 19 2026]. This is the cleanest implementation of Amershi G7/G8/G9 (efficient invocation, dismissal, correction) observed across the corpus.

**Lovable** — best-evidenced activity-card transparency: expandable cards per agent action (file edits, commands, web searches, browser tests, subagent delegations), question cards with up to four answer options (pick / write own / move between questions / change earlier answers / skip individually / skip all), draft answers persisted in browser, post-response action chips (Undo latest edit without confirmation; Revert to this version with confirmation), per-message Credits-used disclosure [Source: evidence/lovable.md §7, citing https://docs.lovable.dev/features/projects/chat.md].

**Codex CLI** — best-evidenced session-lifecycle surface: `codex resume` picker / `--last` / `codex fork`, `codex archive` / `delete` / `unarchive`, `codex exec --ephemeral`, `/compact`, `/new`, `/mention`, `/undo`, `/diff` — most complete slash-command + session-state vocabulary observed [Source: evidence/codex.md §7, citing https://developers.openai.com/codex/cli/slash-commands].

**Claude** — best-evidenced reasoning-transparency nuance: "thinking summaries" produced by a smaller model "needed about 5% of the time" — i.e., Anthropic explicitly chose *not* to always show full chain-of-thought, replacing it with summary unless Developer Mode is on. This is direct empirical instantiation of Springer & Whittaker 2018's finding that "incremental transparency feedback can be distracting" [Source: evidence/claude.md §7, citing https://www.anthropic.com/news/claude-4; cross-ref academic/progressive-disclosure.md §5 — Springer & Whittaker 2018 arXiv:1811.02164].

**Linear** — best-evidenced contextual conversation integration: AI surfaces are not a side panel but seven distinct first-class teammate-like entry points inside the issue tracker (inline @Linear mention, Linear Asks from Slack, Customer Requests, Triage Intelligence, Coding Sessions, Guided Reviews, Agents Command Menu) [Source: evidence/linear.md §7, citing linear-app-home.html and linear-changelog.html].

## 6. Anti-Patterns

**Bolt** — explicit evidence gap: "Bolt's docs do not document an explicit 'activity card' UI like Lovable's." Version snapshots in chat history are the only action-transparency surface; no inline card for file edits, commands, searches, or subagent delegations [Source: evidence/bolt.md §7, citing explicit "Evidence gap" note in evidence file]. The user cannot see what the agent did without scrolling the chat history and clicking eye/return-arrow icons.

**MS Copilot (Teams)** — "Copilot conversations close when the side panel closes" (state is ephemeral per-session) [Source: evidence/ms-copilot.md §7, citing learn-m365-overview.txt]. This violates Amershi G12 "Remember recent interactions" and G18 "Notify users about changes" — closing the panel destroys the conversation.

**Meta AI** — no documented Think mode or visible reasoning trace; news summarization "without linking directly to original articles... including in Canada, where news links are banned" [Source: evidence/meta-ai.md §7, citing https://en.wikipedia.org/wiki/Meta_AI]. Violates recognition-over-recall (no source citation to recognize) and Bansal et al. 2021's complementary-team-performance requirement to surface errors.

**Helix** — no AI conversation surface at all; the user must run an external agent (Claude Code, Cursor, Aider) and edit in Helix [Source: evidence/helix.md §7]. Not inherently an anti-pattern, but evidence that for keyboard-first power users a chat panel may be optional — and that some products deliberately reject the pattern.

**Arc** — limited AI chat: Arc Max features (Ask on Page, 5-second summaries, ChatGPT via `?` in Command Bar) are scattered, not unified into a chat surface; explicitly "Arc does NOT have a dedicated AI Chat sidebar like Notion AI or VS Code Copilot Chat" [Source: evidence/arc.md §7]. Fragmented AI surfaces may force context-switching (CLT split-attention effect).

**Obsidian** — no first-party AI chat; users must install third-party plugins (Smart Connections, Copilot, Text Generator); the only first-party "AI-shaped" surface is CLI eval [Source: evidence/obsidian.md §7]. Plugin-fragmented AI increases extraneous load (CLT) by scattering AI across multiple plugin UIs with inconsistent affordances.

## 7. Cognitive Load Implications

Cognitive Load Theory (Sweller 1988; Cowan 2001 update: ~4 chunks working memory) [Source: academic/cognitive-load-theory.md §3–4, citing Sweller 1988 *Cognitive Science* 12(2):257–285] predicts the following effects on conversation UX:

- **Long conversation history → high extraneous load (EL)** — every visible prior turn consumes working-memory capacity. ChatGPT's automatic context compaction, Claude's Nov 24 2025 infinite-length summarization, Codex's `/compact`, Claude Code's `--autocompact` are all direct EL-reduction mechanisms. [Source: academic/cognitive-load-theory.md §7 — "AI conversation history UIs: showing full conversation history increases EL; summarization reduces EL."]

- **Multi-agent / multi-card UIs → split-attention effect** — Lovable's expandable activity cards, v0's grouped approval panels, and Heptabase's whiteboard-context chat all reduce EL by *physically integrating* related information (file edit + its diff + its approval into one card) rather than scattering across panes. CLT split-attention effect (Sweller, Chandler & Tierney 1990) directly supports this [Source: academic/cognitive-load-theory.md §5].

- **Expertise-reversal effect** — novices benefit from short summaries (Claude's thinking-summaries "needed about 5% of the time"); experts benefit from raw chain-of-thought (Claude Developer Mode; Grok `Ctrl+E` toggling all thinking blocks). The CLT expertise-reversal effect (Kalyuga, Ayres, Chandler & Sweller 2003) is direct empirical basis for adaptive explanation depth [Source: academic/cognitive-load-theory.md §5].

- **In-flight turn control reduces EL** — VS Code's "Add to Queue / Steer with Message / Stop and Send" and v0's Cmd+Enter interrupt + Cmd+Up/Down queue navigation reduce the EL of holding an "I want to say X" intention while the AI is mid-stream. Without these, the user must hold the pending intent in working memory (~4 chunks) until the AI completes — direct CLT violation.

- **Germane load risk ("illusion of knowing")** — arXiv:2607.02723 (2026) "Doom Researching" warns that AI reduces EL but can create "illusion of knowing" without schema construction. Conversation UX that surfaces reasoning (ChatGPT Think panel, Claude thinking summaries, Grok Think) helps scaffold schema construction; conversation UX that hides reasoning (Bolt's undocumented activity-card UI) risks pure EL reduction without germane load.

## 8. Progressive Disclosure Relationship

Progressive disclosure (Nielsen 2006, nngroup.com/articles/progressive-disclosure/) [Source: academic/progressive-disclosure.md §2–3] interacts with conversation UX in four documented patterns:

1. **Reasoning disclosure** — Claude's "thinking summaries" produced ~5% of the time (summary by default, raw chain-of-thought in Developer Mode); ChatGPT's "Thinking..." expanding-collapsible panel; Gemini's Thinking vs Pro modes; Grok's `Ctrl+E` toggle. These are direct instantiations of Springer & Whittaker 2018 (arXiv:1811.02164): "users benefit from initially simplified feedback that hides potential system errors and assists in building working heuristics" [Source: academic/progressive-disclosure.md §5]. 

2. **Activity-card disclosure** — Lovable's expandable cards (collapsed by default, expand on click for inspection); Dust's "Completed in N sec" affordance opening details panel; Cursor's checkpoint timeline preview-on-click. Each is "initially simplified feedback" with drill-down on demand [Source: academic/progressive-disclosure.md §7].

3. **Slash-command menu disclosure** — v0, Manus, Codex, Continue, Notion `/ai`, JetBrains `/`: typing `/` opens a live-filtering menu, narrowing the command space progressively. This is "discoverability criterion" — "must be obvious how to progress from the primary to the secondary disclosure levels" [Source: academic/progressive-disclosure.md §4 — Nielsen 2006].

4. **Tool-call disclosure** — Claude "tool-call output collapsed by default, expandable" (per academic/progressive-disclosure.md §7); Codex `/diff` to surface Git diff on demand; Cursor's checkpoint preview; Lovable's "More options" menu revealing Credits used. The "opacity theatre" risk (arXiv:2605.10930) requires always-available drill-down — products that hide tool calls without drill-down would violate this [Source: academic/progressive-disclosure.md §7–8].

## 9. Accessibility Considerations

Evidence on accessibility is sparse in the evidence files. Noted:
- **v0 sound notification** — "v0 plays a sound when it finishes responding while the window is not focused, controlled by a Sound Notifications toggle in Settings that is on by default" — useful for low-vision users who cannot see the visual completion indicator [Source: evidence/v0.md §7, citing https://v0.dev/changelog Jul 21 2026].
- **Apple Siri voice customization** — "Pick a voice, then customize expressivity and pace until it clicks for you" — directly serves low-vision / motor-impaired users for whom voice is the primary modality [Source: evidence/apple-intelligence.md §7, citing https://www.apple.com/apple-intelligence/].
- **Ray-Ban Meta multimodal assistive case** — glasses "can describe surroundings; read text aloud using OCR and speech synthesis; and provide turn-by-turn directions" — explicit assistive-tech application [Source: evidence/meta-ai.md §7, citing https://en.wikipedia.org/wiki/Ray-Ban_Meta].
- **Replit Voice Mode with transcribed review** — "Review before sending — Transcribed text lands in the chat box so you can read and edit it before sending — nothing is sent automatically" — deaf/hard-of-hearing accessible voice input; also serves users who want to edit before committing [Source: evidence/replit.md §7, citing https://docs.replit.com/features/agent/voice-mode.md].

**Insufficient evidence — gap noted:** No evidence file documents screen-reader compatibility of streaming text, ARIA-live-region usage for token-stream, or keyboard-only navigation of activity cards. The Zed evidence file notes AccessKit support is "in-progress not shipped" [Source: evidence/zed.md §7 cross-ref §19]. ## 10. Performance Implications

Streaming-first conversation UX creates perceived performance benefits but real engineering costs:
- **First-token latency** dominates perceived responsiveness — every streaming product (ChatGPT, Claude, Gemini, GLM, Lovable, Cursor, v0, Codex CLI) prioritizes first-token render over complete-response render.
- **v0 sound-on-completion** offloads the "is it done?" polling cost when the window is unfocused [Source: evidence/v0.md §7].
- **Windsurf auto-continue on context limit** eliminates the manual "click Continue" round-trip when context fills — reduces wait perception [Source: evidence/windsurf.md §7].
- **Claude Code `--autocompact 100k–1M`** and Codex `/compact` reduce perceived performance degradation by silently summarizing before the user notices context loss [Source: evidence/claude-code.md §7; evidence/codex.md §7].
- **Lovable draft persistence** ("draft answers persist in browser so a refresh doesn't lose them") and v0 "Typed prompts survive clarifying questions, permission approvals, and queued submissions" eliminate the perceived cost of network/state loss [Source: evidence/lovable.md §7; evidence/v0.md §7].

## 11. Long-Session Impact

Multi-hour conversation sessions face three documented failure modes:
1. **Context-loss degradation** — solved by compaction (ChatGPT, Claude, Codex `/compact`, Claude Code `--autocompact`, Windsurf auto-continue). Compaction itself can break (ChatGPT v0.144.0 bug fix: "Resumed ChatGPT threads recover when compaction references a retired model by retrying with the currently selected model") [Source: evidence/chatgpt.md §7].
2. **History-navigation cost** — solved by session lifecycle primitives (Codex `archive`/`delete`/`unarchive`/`fork`; Claude Code `--session-id`/`--teleport`; Aider's three persisted history files; Sweep's "one chat per task" guidance) [Sources as cited in §3.4].
3. **Intent fragmentation** — solved by in-flight queue (VS Code "Add to Queue / Steer with Message / Stop and Send"; v0 Cmd+Up/Down through queued prompts; Cursor "Queue follow-up messages while Agent is working") [Sources as cited in §3.3].

Long sessions also reveal: **per-message cost transparency** (v0 "Credits used" per message; Lovable "Credits used" in More options) becomes essential for users to manage token budgets across hours of work [Source: evidence/v0.md §7; evidence/lovable.md §7].
